# 보트리스 무한모드 후반 압박 구현·검증

검증일: 2026-10-10. 수정 전 HEAD: `87dc16b16710b57f8eb215bd8a0ccbb254a0cc45`.

**새로 시작하는 표준 무한모드에 점수별 조각 곡선을 적용했다. 기존 진행 중 저장은 이전 규칙을 유지한다. 자동 비교에서 생존 제한 도달 비율은 줄었지만, 후반 밸런스가 충분히 해결됐다고 판단하지 않는다.** 이번 작업은 로컬 구현과 검증이며 공개 배포는 수행하지 않았다.

## 원인과 구현

기존 표준은 최대 9색·8병에 도달하면 일반 3칸 확률 5%, 그중 단색 50%로 고정됐다. 고득점이 추가 압박을 만들지 않았고 단색 3칸은 정리를 돕기도 했다.

최종 선택한 첫 후보는 다음과 같다. 점수 사이를 소수 확률로 선형 보간하고 25,000점 이후 마지막 값으로 고정한다.

| 점수 | 적격 생성 중 3칸 | 3칸 중 단색 AAA | 3칸 중 2색 혼합 |
|---|---:|---:|---:|
| 4,500 | 5% | 50% | 50% |
| 10,000 | 8% | 30% | 70% |
| 15,000 | 10% | 20% | 80% |
| 25,000 | 12% | 10% | 90% |

- 실제 8병·활성 9색과 시작 점수 조건을 모두 만족한 뒤 새로 생성하는 조각에 적용한다. 그 전에는 기존 정책을 사용한다.
- 성장의 새 색 소개 조각은 기존 우선 정책을 유지하며 일반 추첨·통계 분모에서 제외한다.
- 혼합 형태는 AAB·ABA·BAA다. ABC는 추가하지 않았다. 일반 1/2칸 스트림·후반 10/90 비율·점수·홀드 규칙을 유지했다.
- 이미 공개된 현재·다음 큐·보관 조각은 바꾸지 않는다. 홀드로 큐를 소비하거나 배치로 보충할 때 현재 실제 점수로 새 조각을 생성한다.
- `pressureVersion: 1`과 전체 `pressureTable`을 규칙·서명에 포함한다. 순수 조회 함수 `pressureAt`·`nextPressure`는 난수와 상태를 소비하지 않는다.
- 기존 3칸 전용 난수 스트림과 generation 단위는 보존했다. 규칙 버전이 없는 과거 조각열과 실제 행동 재생이 수정 전 엔진과 일치했다.
- 정제는 잘못된 행·순서·역방향 확률을 제외하고 확률 범위를 제한한다. 유효한 행이 없는 활성 정책은 기본 표로 정제한다. 손상된 진행 중 정책은 기존 복구 저장 경로에서 보호한다.

기존 기본 설정의 다음 새 판은 새 표준으로 갱신된다. 일일 도전·명시적 커스텀·진행 중 게임은 자동 변경하지 않는다. 이전 표준은 `LEGACY_ENDLESS_RULES`로 정확히 보존했으며 별 지급 대상에도 남겼다. 이전 최고 기록·통계·클라우드 키를 삭제하거나 합치지 않는다. 새 난도 서명의 기록은 별도로 시작한다.

## 화면과 언어

기존 성장 안내 공간에 다음 심화 기준까지 남은 점수를 표시하고 마지막 기준에는 최고 난도 안내를 표시한다. HUD 행과 병 크기를 유지했다. 도움말에는 최대 확장 이후 큰 조각·혼합 조각이 점차 늘어난다는 설명을 추가했다.

기존 9개 언어를 처리했다. 360×640에서 포르투갈어 마지막 안내가 두 줄이 되어 하단 버튼이 밀리는 문제를 실제 측정으로 발견하고 `Nível máximo · recorde`로 줄였다. 실패 원자료는 `out/probe-long-pt-browser.json`에 남겼다.

최종 집중 브라우저 검사에서 9언어·상하 트레이·두 화면/안전 여백·4개 후반 기준의 432개 레이아웃 검사와 실제 터치/마우스·저장·재시작·되돌리기·빠른 입력 등을 포함해 **463/463**을 통과했다. 수정 전후 같은 조건의 병 높이도 일치했다. `outputs/late-pressure/ko-*.png`와 스킨별 화면을 남겼다.

외부 Google Fonts의 일부 서브셋 요청이 지연되어 집중 검사 51번 로드 중 10번에서 3초 대기 상한에 도달했다. 이를 숨기지 않고 `out/browser.json`의 `fontLoads`에 기록했다. 해당 측정은 당시 폴백 글꼴을 포함한다. 별도 기존 전체 폰트·모션·Web Audio 검사 2,741개도 통과했지만 모든 네트워크 환경의 폰트 로딩을 보장하지 않는다.

## 새 시드 밸런스 비교

과거 JSON을 재사용하지 않고 `late-pressure-20261010-0`부터 `-39`까지 새 고정 시드를 사용했다. 기존 1회/2회 붓기 탐색 정책·홀드 판단·평가 가중치를 유지했다. 판당 최대 1,500 성공 배치로 세 조건 240판과 한 번의 조정안 80판, 총 **320판**을 실행했다.

1회 탐색은 네 조건 모두 관측 중앙값 73배치, 10,000점 도달 0/40이었다. 이 자료로 후반 난도를 판단하지 않는다. 2회 탐색은 아래와 같다.

| 조건 / 2회 탐색 | 10,000점 도달 | 15,000점 도달 | 25,000점 도달 | 1,500배치 제한 생존 |
|---|---:|---:|---:|---:|
| 기존 5%·단색 50% | 40/40 | 39/40 | 39/40 | 31/40 (77.5%) |
| 확률만 5→8→10→12%, 단색 50% | 40/40 | 39/40 | 39/40 | 30/40 (75.0%) |
| 전체 후보, 최종 선택 | 40/40 | 40/40 | 40/40 | 24/40 (60.0%) |
| 한 번의 조정안 | 40/40 | 40/40 | 38/40 | 24/40 (60.0%) |

조정안은 4,500/10,000/15,000/25,000점에서 3칸 5/10/12/15%, 단색 50/20/15/10%였다. 제한 생존 수가 전체 후보와 같아 추가 개선이 확인되지 않았다. 확률을 더 올릴 근거가 부족하므로 원래의 **12% 상한** 후보를 유지했다. 선택 근거와 실제 규칙·서명은 `out/selection.json`에 기록했다.

기준선에서 제한까지 살아남고 전체 후보에서는 종료한 시드는 12개, 반대는 5개였다. 전체 후보의 변화가 모든 판을 일관되게 어렵게 만든 것은 아니다. 같은 시드에서도 홀드·점수·generation 진행이 달라지므로 단색 비율 하나의 인과 효과라고 단정하지 않는다.

| 점수 구간 / 2회 탐색 | 기준선 평균 빈칸 / 배치 가능한 병 | 전체 후보 평균 빈칸 / 배치 가능한 병 |
|---|---:|---:|
| 10,000–14,999 | 18.01 / 4.71 | 17.80 / 4.59 |
| 25,000 이상 | 17.86 / 4.67 | 17.84 / 4.58 |

병 전체 용량은 32칸이다. 평균 여유 공간 감소는 작고 전체 후보에서도 과반이 제한까지 살아남았다. **후반 압박 증가의 신호는 있지만 안정된 정렬 전략의 긴 생존과 정체를 해결했다고 볼 수 없다.** 25,000점 이후에는 이번 곡선도 고정된다. 출시 밸런스·사람의 재미·피로·재도전 의욕은 검증되지 않았다.

전체 후보의 25,000점 이상 적격 생성 37,148개 중 3칸 4,384개(11.80%), 그중 단색 460개(10.49%)였다. 소개 조각은 분모에 포함하지 않았다. 모든 조건에서 `unknown` 관측은 0회였고 종료 원자료는 엔진의 합법 공간 없음과 봇 탐색 포기를 구분한다.

제한 도달은 실제 종료 시간이 아니라 관측 중단이다. 2회 탐색의 중앙 관측 배치는 모두 1,500으로, 실제 중앙 생존 길이는 **1,500 이상인 하한**이다. 점수 구간 이후 배치 통계도 원자료의 censor 표시를 함께 읽어야 한다. 점수·배치를 사람의 플레이 시간으로 환산하지 않았다.

`out/baseline.json`은 실제 작업 전 소스·엔진·하네스·봇 해시를 보존한다. 각 비교 파일은 실행 당시 엔진·봇·비교 도구 해시와 전체 규칙을 담는다. 원본 연구 결과는 공용 실행 래퍼로 백업/복원했다. 기존 고정 확률 연구 도구는 새 기본 정책을 실수로 섞지 않도록 명시적으로 이전 표준을 사용한다.

비교 도중 저장 검증을 추가하기 전 중단한 작업의 부분 결과는 `out/probe-before-save-validation.json`이다. 완료된 비교/선택의 근거로 사용하지 않았다. 확정 비교에 사용한 엔진과 최종 엔진의 동일성, 실제 선택한 규칙의 재생 동치를 `verify-evidence.js`에서 확인한다.

## 성능

초기 실행·20회 예열한 고정 시드·9색/8병/25,000점의 강제 구성 조건을 분리해 수정 전후를 측정했다. 각 설정은 붓기 40회·배치 10회·큰 콤보 정리 5회로 55회 실제 상태 전환을 확인했다. 단위는 입력 처리 p90, ms다.

| 조건 | 기본 ×1 | 기본 ×4 CPU | 강화 ×1 | 강화 ×4 CPU |
|---|---:|---:|---:|---:|
| 초기, 전→후 | 1.4→1.4 | 4.6→4.5 | 1.4→1.3 | 6.2→6.1 |
| 예열, 전→후 | 1.2→1.2 | 5.2→4.9 | 1.4→1.4 | 6.6→6.3 |
| 후반 구성, 전→후 | 1.3→1.4 | 5.9→5.2 | 1.7→1.5 | 7.0→7.0 |
| 후반 구성 재측정, 전→후 | 1.5→1.7 | 5.8→5.2 | 1.6→1.4 | 7.9→7.3 |

최초 후반 구성의 강화 ×1에서 배치 항목 p90이 1.7→2.2ms(+29.4%)였다. 같은 고정 시드의 전후 재측정에서는 배치 1.6→1.6ms였다. 전체 처리 p90의 지속적인 20% 초과 악화는 재현되지 않았지만, 배치 10개 표본의 p90은 사실상 최댓값이라 편차를 일반화하지 않는다. 모든 실행의 50ms 초과 long task는 0회, 효과 노드 최대는 기본 23/강화 54였다.

원자료는 `*-perf-perf.json`, 실행 기록은 `*-perf-command.json`, 비교 요약은 `out/perf-summary.json`이다. 후반 조건은 새 정책으로 조각열이 달라질 수 있어 정책 전체의 입력 처리 비교이며 순수 확률 함수의 인과 비용만 분리한 실험은 아니다. 헤드리스 입력 처리 시간은 실제 휴대폰 FPS나 체감 사운드 지연을 입증하지 않는다.

- 실제 로컬 게임: http://127.0.0.1:8154/ — 기존 로컬 서버가 최신 `dist/index.html`을 읽는다.
- 집중 검사는 별도 origin·브라우저 프로필·저장소를 사용했고 실제 플레이 기록을 지우지 않았다.

- 로컬 구현·검증을 완료했으며 원격 반영·Pages 배포는 수행하지 않았다.
