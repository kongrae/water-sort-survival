# UI·UX 개선 구현 및 검증

검증일: 2026-10-09. 대상 명세: `docs/PROMPT_uiux_polish.md`.

## 구현 결과

점수와 성장 안내가 떨어져 있고, 작은 보조 글자와 강조된 일일 도전 버튼 때문에 무한모드의 목표가 덜 명확했다. 점수·최고·콤보와 성장 목표를 상단에 묶고, 아래 병과 조각 트레이는 손이 익힌 위치를 유지하는 방향으로 정리했다.

- IBM Plex Sans KR를 본문·버튼·HUD·결과 숫자에 사용한다. 기존 Jua는 게임명에만 남겼다. 점수 44px(짧은 화면 40px), 성장·상태 13px, 캡션 12px, 일반 버튼 14px를 기준으로 맞췄다. 기존 Google Fonts 요청과 폴백을 재사용하며 폰트나 라이브러리를 추가하지 않았다.
- `4색 · 6병`과 다음 성장까지 남은 점수를 점수 아래에 배치했다. 턴 정산 막대에는 `N턴 뒤 정산`을 유지해 색·병의 점수 성장과 구별했다. 위 줄의 확장 공간과 아래 여섯 병의 고정 위치를 유지했다.
- 현재 조각과 다음 조각의 글자·간격을 정돈하고 병 아래 표시는 `N칸`으로 줄였다. 병의 접근 가능한 이름에는 아래부터의 색과 빈칸 정보를 유지한다. 노란 액체의 기호는 어두운 색으로 표시한다.
- 규칙·설정·뒤집기 버튼과 일반 버튼을 44px 이상으로 맞췄다. 일일 도전은 보조 스타일로 낮췄다. 진행 중 모드 전환은 기존 새 게임과 같은 3초 내 두 번 누르기 확인을 사용하며, 플레이를 이어 하면 확인 상태가 해제된다.
- 설정을 소리와 진동 / 화면과 접근성 / 조작과 안내 / 저장으로 묶었다. 조작 방식과 트레이 위치는 일반 설정에서 바로 바꿀 수 있다. 규칙 실험과 개발 옵션은 접힌 영역에 남겼다.
- 설정·규칙·테마에 고정 제목과 닫기를 적용했다. 모달 안의 Tab 이동, 배경 입력 차단, 닫을 때 포커스 복귀와 설정에서 테마를 연 경우의 포커스 복귀를 처리했다.
- 확장형과 과거 규칙의 설명을 분리했다. 확장형의 색·병 증가는 점수, 빈병 정산은 턴 기준임을 설명하며, 도움말은 현재 조작과 트레이 위치를 따른다.
- 결과에서는 이번 점수를 크게 보여주고 `다시 도전`을 강조한다. 기록 차이·턴·완성 병·최대 콤보·별·테마·공유·기존 부활 경로를 보존했다.
- 360×640에서는 요소 사이 여백을 줄이고 경고 두 줄 공간을 미리 확보했다. 긴 경고와 포기 버튼이 나타나도 병 위치가 유지된다. 효과 영역은 새 목표 HUD와 상태 안내 사이를 사용하도록 좌표 계산을 맞췄다.

93개 UI 검사는 360×740, 390×844, 412×915, 768×1024, 360×640에서 6·7·8병을 검사한다. 아래 여섯 병과 7번째 병의 위치 유지, 화면 잘림과 가로 스크롤, 44px 터치 크기, 밝음·어두움 및 네 병 테마와 기호, 효과 축소, 모달 포커스, 진행 보호, 123,456점·콤보 123, 짧은 화면의 긴 경고와 해금 배너를 포함한다. [측정값과 결과](out/after.json)를 함께 남겼다.

일반 폰트 로드가 완료된 상태에서 IBM Plex Sans KR와 Jua의 로드를 확인했다. 별도로 브라우저 캐시를 비우고 Google Fonts 요청을 차단했으며, `Network.loadingFailed`의 `blockedReason: inspector`와 로드된 폰트 없음으로 실제 폴백 상태를 확인한 뒤 360×640 배치를 검사했다.

기본 실험실 테마의 실제 주요 텍스트 대비는 밝은 화면에서 최소 4.86:1, 어두운 화면에서 최소 7.04:1이었다. 점수·성장·정산·빈칸 캡션·일반 버튼 조합을 측정한 값이며, 모든 장식·그라데이션·애니메이션 프레임에 대한 전체 접근성 인증을 의미하지 않는다.

기존 검사 수정은 다음 이유로 제한했다.

- `existing`의 일일 도전 검사는 즉시 전환을 가정했다. 첫 누름의 진행 보존 검사를 추가한 뒤 두 번째 누름으로 전환한다. 기존 임시 잔·공유·일일 기록 검사를 그대로 유지했고, 수정 후 18/18이 통과했다. 다른 일곱 시나리오의 통과 결과와 합쳐 116개다.
- 효과 검사에서 목표 HUD의 이동에 맞춰 효과 영역 경계를 `점수 아래 ~ 정보 위`에서 `목표 HUD 아래 ~ 상태 안내 위`로 바꿨다. 효과의 최소 높이와 병·상태·버튼·배너의 겹침 검사를 유지한다.
- 효과 전체 검사에서 조작 옵션이 실험 영역 안에 있어야 한다는 옛 전제를 바꿨다. 규칙·통계는 계속 접혀 있고, 조작·트레이는 일반 설정에 있는지 별도 검사한다. 위 트레이의 긴 경고에서 발견한 약 4px 병 이동도 경고 두 줄 공간을 확보해 수정했다. 수정 후 전체 효과 검사는 323/323이 통과했다.
- 전체 효과 조작 검사의 첫 터치 한 항목은 실행 중 간헐적으로 실패했다. 동일 항목 재실행은 105/105로 통과했다. 좌표를 측정하는 조작·효과 검사가 일반 폰트 로드 완료를 기다리도록 보완하고, 해당 항목의 턴·선택·힌트·상태 진단을 추가해 전체를 다시 확인했다. 폰트 장애 검사는 별도로 유지한다.

과거 `engine-test.js`의 알려진 콤보 기대값 실패는 이번 변경의 새 회귀와 구별했다. 그 기대값이나 게임 엔진을 수정해 우회하지 않았다.

## 브라우저 화면과 실제 성장

자동 검사는 격리된 Chrome 프로필에서 정상 Pages 문서를 실행한다. 확장 조작 검사는 브라우저의 터치·마우스·키보드 입력으로 두 조작 방식과 위·아래 트레이, 행 사이 취소, 리사이즈 중 드래그 취소, 연속 입력, 되돌리기와 새로고침을 확인했다.

전후 비교용 6·7·8병 화면은 명시적으로 주입한 검증 상태다. 별도로 시드 기반 전략의 실제 DOM 플레이를 80턴 재생하여 4,800점과 두 번의 병 확장을 얻었고, UI의 병·점수·성장 상태가 순수 엔진의 같은 플레이 결과와 일치했다. 이는 사람의 체험이나 재미 검증을 대신하지 않는다.

인앱 브라우저에서도 390×844와 360×640의 8병 화면, 설정·테마 연결과 포커스 복귀, 모드 첫 누름의 3,200점·7턴 보존을 확인했다. 실제 8137 미리보기를 새로고침해 작업 전의 5턴 진행이 유지되는 것도 확인했다.

## 변경 파일과 한계

- `water-sort-survival.html`: CSS, 마크업, UI 처리.
- `uitest/driver.js`, `uitest/input.js`, `uitest/feel.js`: 확인 절차·폰트 대기·진단·효과 영역의 검사 보완.
- `uitest/uiux.js`, `research/uiux/baseline.js`, `research/uiux/serve.js`: 격리 화면 검사, 기준선 및 선택적 전후 검토 서버.
- `research/uiux/baseline.json`, `research/uiux/out/`, 이 보고서: 증거와 결과.

로컬 실행 화면: [http://127.0.0.1:8137/](http://127.0.0.1:8137/). 직접 빌드할 때는 `node build-pages.js`를 실행해 `dist/index.html`을 제공하면 된다.

실제 휴대폰의 터치감·브라우저 주소창·가상 키보드·OS별 글꼴과 음향은 미검증이다. 클라우드 검사는 기존 모의 백엔드 계약 검사이며 실제 계정 로그인·운영 DB 왕복 검증은 아니다. 광고는 기존 시뮬레이션이다. 공개 배포·커밋·푸시는 수행하지 않았다.

## 후속 수정: 지금·다음 트레이 배치

2026-10-09 사용자 요청에 따라 하단 조각 영역을 다시 정리했다. 이전에는 다음 조각 중 첫 번째에만 캡션이 붙어 두 미리보기의 아래 높이가 어긋났고, 트레이 내용이 왼쪽에 몰려 있었다.

- 지금 조각과 뒤집기를 왼쪽 묶음, 다음 미리보기를 오른쪽 묶음으로 배치하고 얇은 구분선을 둔다. 현재 조각의 너비를 44px에서 52px로 키우고 `지금` 캡션을 강조한다.
- 다음 조각은 30px 너비와 같은 아래 높이를 사용한다. `다음` 캡션은 묶음 전체 아래에 놓고 지금 캡션과 높이를 맞춘다. 두 번째 미리보기의 강조를 낮춰 순서를 구분한다.
- 미리보기가 0개면 다음 묶음을 숨긴다. 기존 미리보기 0~3개와 임시 잔·제안 버튼을 보존한다. 미리보기 3개와 임시 잔이 함께 표시될 때만 간격과 미리보기 크기를 줄여 겹침을 막는다.
- 다음 조각의 접근 가능한 이름에 순서와 아래부터의 색을 제공한다. 조각 큐·뒤집기 횟수·규칙·저장은 그대로이며 순수 엔진 해시도 위 기준선과 동일하다.
