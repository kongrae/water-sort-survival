## 성능

수정 전 9색·8병과 수정 후 10색·9병의 25,000점 강제 구성, 동일 시드 `late-pressure-perf-fixed`·6회 예열·입력 절차로 기본/강화 연출과 1배/4배 CPU 조건을 비교했다. Chrome 헤드리스 390×844, Node v24.19.0 환경에서 다른 검사·비교 작업이 끝난 후 측정했다. 각 조건은 붓기 40회·배치 10회·큰 콤보 정리 5회다. 입력의 두 번째 클릭에서 상태 처리·렌더·효과 시작까지의 동기 JS 시간이며 프레임 속도나 실제 모바일 FPS의 측정이 아니다.

`before-perf-perf.json`의 기존 `--pressure`와 `after-perf-perf.json`의 `--late-expansion`을 비교한다. 기존 기본/압박 측정 절차는 유지하고 후자의 강제 상태만 10색·9병으로 설정했다.

| 연출/CPU | 전후 | 전체 p50 / p90 / 최대 (ms) | 붓기 p90 | 배치 p90 | 큰 콤보 p90 | 표본 | 50ms 이상 작업 | 최대 효과 노드 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 기본 / 1배 | 전 | 1.2 / 4.5 / 9.0 | 1.3 | 4.5 | 9.0 | 55 | 0 | 23 |
| 기본 / 1배 | 후 | 1.2 / 5.9 / 8.7 | 1.4 | 6.4 | 8.7 | 55 | 0 | 23 |
| 기본 / 4배 | 전 | 4.9 / 21.8 / 28.9 | 5.5 | 21.8 | 28.9 | 55 | 0 | 23 |
| 기본 / 4배 | 후 | 4.9 / 18.5 / 28.1 | 5.6 | 18.5 | 28.1 | 55 | 0 | 23 |
| 강화 / 1배 | 전 | 1.4 / 4.5 / 6.5 | 1.5 | 5.4 | 6.5 | 55 | 0 | 54 |
| 강화 / 1배 | 후 | 1.5 / 4.4 / 5.6 | 1.6 | 4.7 | 5.6 | 55 | 0 | 54 |
| 강화 / 4배 | 전 | 6.7 / 17.1 / 22.1 | 7.5 | 22.1 | 21.5 | 55 | 0 | 54 |
| 강화 / 4배 | 후 | 6.8 / 20.2 / 27.3 | 7.4 | 27.3 | 20.3 | 55 | 0 | 54 |

모든 조건 55/55 합법 입력, JS 오류 0, 긴 작업 0이었다. 기본 1배의 배치 p90은 4.5→6.4ms, 강화 4배는 22.1→27.3ms로 증가했다. 한 번의 제한된 측정이므로 수치의 작은 등락을 성능 개선/악화의 확정으로 해석하지 않는다.

목표 탐색은 별도 `planner-perf.js`에서 수정 전/후 엔진을 사용했다. 각각 30회 예열 후 400개의 유효한 25,000점 강제 상태를 같은 생성 절차로 만들고 측정 순서를 번갈아 실행했다. 보드는 고정 정수 난수, 현재/공개/보관 조각은 실제 엔진 생성이다. 판을 직접 플레이해 얻은 상태의 분포와 구분한다.

| 목표 탐색 | p50 / p90 / 최대 (ms) | 표본 | 반환 경로 / 합법 재생 | 최대 탐색 |
|---|---:|---:|---:|---:|
| 전 9색·8병 | 3.554 / 4.472 / 8.087 | 400 | 364/364 | 768 |
| 후 10색·9병 | 3.977 / 4.999 / 7.377 | 400 | 319/319 | 768 |

입력 상태 비변경, 반환 경로의 실제 행동 재생과 지정 색 우선 완성을 검증했다. 오류는 0이며 탐색 768·빔 12·깊이 20 상한은 그대로다. 이 Node 진단에서 p90은 약 0.53ms 증가했다. 반환 목표 수 차이는 색·병 수에 따른 강제 상태 분포도 포함하므로 목표의 실제 실패율이나 접근성을 뜻하지 않는다. 원시 시간 표본과 실행 해시는 `out/planner-perf.json`에 보존했다.

## 재확인과 증거

- 일반 플레이: <http://127.0.0.1:8154/>. 이전 진행 중 게임은 유지되므로 새 표준은 새 판에서 확인한다.
- 12,000/18,000점 체험: <http://127.0.0.1:8160/>. 별도 출처·메모리 기록·Firebase 비활성화 상태다. 처음부터 해당 점수에 도달한 플레이 증거와 구분한다.
- `out/`에는 실행 당시 소스·엔진·봇 해시, 실제 규칙과 서명, 시드·관측·종료 이유를 기록했다. 과거 연구 출력은 실행 래퍼로 보존했다.
- 순수 엔진 비교가 진행되는 동안 UI를 보완했다. 비교의 원래 소스 해시는 유지하고 최종 엔진·봇 해시 및 실제 규칙이 같은지를 검증한다. 브라우저·회귀·성능은 최종 전체 소스 해시와 연결한다.
- 중간 실패·진단은 `probe-*`로 보존하고 최종 통과의 증거에 포함하지 않는다. 기준선 스냅샷은 `outputs/late-expansion/`에 있으며 없으면 기록한 Git 커밋으로 기준선 엔진·화면을 읽는다.
- `out/verification.json`으로 최종 파일·검사·빌드·로컬 응답의 일치를 확인한다. 실제 기기·사람의 재미/재도전·출시 밸런스는 별도 검증이 필요하다.

재검증: `node build-pages.js`, `node research/late-expansion/engine-test.js`, `node research/late-expansion/feature-regressions.js`, `node uitest/late-expansion.js`, `node uitest/late-expansion.js --extras-only`, `node uitest/late-expansion.js --demo-only`, `node uitest/late-expansion.js --growth-only`, `node research/late-expansion/compare.js --n=40 --cap=1500`, `node research/late-expansion/regressions.js`, `node research/late-expansion/planner-perf.js`, `node research/late-expansion/verify-evidence.js`.

성능 재검증은 `node research/bottle-quality/run-check.js before perf --task=late-expansion --pressure`, `node research/bottle-quality/run-check.js after perf --task=late-expansion --late-expansion`이다. 체험은 `node research/late-expansion/serve.js`를 먼저 실행한다. 이미 존재하는 기준선 캡처를 현재 소스로 덮어쓰지 않는다.
