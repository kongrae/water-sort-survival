## 구현 결과

새로 시작하는 표준 무한모드에 점수 성장형 규칙을 적용했다. 시작은 6병·4색이며 일반 빈병 두 개가 위 줄의 고정된 3·4열에 추가된다. 아래 여섯 병은 6·7·8병 상태 모두에서 같은 위치와 너비를 유지한다. 시작부터 위 줄 공간을 확보하며 잠긴 병 슬롯은 표시하지 않는다.

| 점수 | 목표 색 수 | 일반 병 수 |
|---:|---:|---:|
| 0 | 4 | 6 |
| 300 | 5 | 6 |
| 900 | 6 | 7 |
| 1,700 | 7 | 7 |
| 2,800 | 8 | 8 |
| 4,500 | 9 | 8 |

- 병은 넣기 또는 붓기의 점수 정산 직후, 패배 검사 전에 지급한다. 큰 콤보가 두 병 목표를 넘으면 두 병을 모두 지급한다.
- 활성 색은 배치당 하나씩 증가한다. 현재 조각·미리보기는 확정된 상태로 보존하고 이후 생성부터 반영한다. 새 색 소개 조각은 아직 공개되지 않은 항목에만 들어간다.
- 20턴 정산과 별 보상은 유지했다. 정산은 새 병 지급 전의 빈병 수를 사용한다. 턴 경계의 강제 색상 추가는 확장형에 적용하지 않는다.
- 9색까지 활성화된 뒤 일반 2칸 조각의 생성 확률을 90%로 높였다. 새 색 소개 조각은 기존 소개 크기를 따른다. 초반 1~2칸 분포는 유지한다.
- 임시 잔 제안은 확장형에서 껐다. 기존 규칙·기존 저장의 임시 잔은 유지한다.
- 두 줄의 실제 행을 판정해 행 사이 공간에 놓은 조각/붓기가 다른 행에 들어가지 않게 했다. 화면 크기가 바뀌면 진행 중인 확장형 드래그를 취소한다.
- 최근 콤보·버스트·액체 이동 효과의 기본값과 조작 방식은 유지했다. 새 병 등장 연출은 입력을 잠그지 않는다.

## 저장·설정 호환 정책

기존 `v:1` 상태는 그대로 이어 한다. 확장형은 규칙의 `expansion:1`과 저장된 `growth` 상태로 명시적으로 구분한다. 병 해금으로 규칙 객체를 변경하지 않아 최고점/페이스 키는 판 안에서 고정된다. 새 서명에 성장표, 큐 정책, 미리보기 수, 후반 2칸 비율을 포함한다.

기존 최고점·페이스·별·테마·설정은 삭제하지 않는다. Firebase/아티팩트 계정 저장의 기존 기록 목록 구조를 그대로 사용한다. 새 표준 규칙도 별 획득 자격에 포함했다. 실제 계정 로그인과 원격 쓰기는 이번에 검증하지 않았다.

기존 저장을 이어 하는 동안에는 새 규칙으로 전환하지 않는다. 새 판의 규칙 선택은 다음과 같다.

- 규칙 저장 없음 또는 과거 표준 기본값: 확장형으로 새 판 시작.
- 과거 비표준 커스텀 값: 기존 고정 병 규칙 유지.
- 이번 설정 화면에서 명시적으로 적용한 규칙: `wsurv.rules.custom` 표시를 저장해 선택 유지.
- 설정의 기본 규칙 버튼: 확장형으로 복귀. 병/용량/색/조각 크기를 바꾸면 고정 병 커스텀 규칙으로 적용하며 설정 화면에도 이를 안내한다. 정산 주기·미리보기·뒤집기 등 나머지 설정은 성장형을 유지하되 기록 서명이 달라질 수 있다.
- 일일 도전: 기존 기본 규칙과 날짜·조각 번호별 같은 순서 유지.

## 비교 실험

재실행:

```powershell
node research/expansion/compare.js --n=60 --cap=500 --workers=3
node research/expansion/compare.js --tails --n=60 --cap=500 --workers=3
node research/expansion/tail-check.js
```

공통 시드는 `expansion-0`~`expansion-59`. 구조와 점수 전이를 모두 실제 엔진에서 실행하는 어댑터를 사용했다. 기존 `harness.js`와 `bot2.js`의 평가 가중치·뒤집기 예산·1수/2수 붓기 탐색을 재사용한 정책이다. 과거의 가벼운 보드 복사와 달리 확장·점수·큐·패배 상태를 함께 복사하고 실제 전이를 적용한다. 기준과 후보 모두 동일한 어댑터를 사용했다. 상한은 500배치이고 임시 잔·부활을 모두 사용하지 않았다.

같은 시드는 같은 입력 실험 조건이다. 점수 성장과 생성 스트림이 달라져 규칙 간 조각 내용이 동일하다는 뜻은 아니다. 아래 분위수는 종료와 상한 생존이 섞인 관측값이다. 상한 생존 비율이 절반을 넘으면 중앙값은 `≥500`이다.

첫 비교의 색상 임계값:

- early-8: 300 / 700 / 1,300 / 2,200점, 최대 8색.
- steady-9: 300 / 900 / 1,700 / 2,800 / 4,500점.
- late-9: 500 / 1,300 / 2,500 / 4,000 / 6,500점.
- 7병은 6색 목표, 8병은 8색 목표와 함께 지급. 세 후보의 후반 2칸 비율은 첫 비교에서 모두 50%.

| 후보 | 1수 배치 p50 / p90 | 1수 7병 / 8병 도달 | 2수 배치 p50 / p90 | 2수 500 생존 |
|---|---|---|---|---:|
| 기존 기준 | 50 / 67 | 해당 없음 | 117 / 181 | 0/60 |
| early-8 | 53 / 98 | 49/60 / 21/60 | ≥500 / ≥500 | 60/60 |
| steady-9 | 59 / 97 | 46/60 / 18/60 | ≥500 / ≥500 | 50/60 |
| late-9 | 55 / 104 | 46/60 / 6/60 | ≥500 / ≥500 | 50/60 |

early-8은 숙련 정책에서 너무 안정적이었고, late-9는 1수 정책의 두 번째 확장 도달률이 낮았다. steady-9를 유지하고 후반 조각 길이 한 변수만 비교했다.

| steady-9 후반 2칸 확률 | 1수 배치 p50 / p90 | 2수 500 생존 | 2수 배치당 붓기 |
|---:|---|---:|---:|
| 50% | 59 / 97 | 50/60 | 1.45 |
| 80% | 59 / 96 | 47/60 | 1.70 |
| **90% (선택)** | **59 / 96** | **42/60** | **1.77** |
| 100% | 59 / 96 | 37/60 | 1.84 |

90%는 1칸 조각의 변화를 남기면서 후반 붓기 부담과 종료 빈도를 높이는 첫 체험용 선택이다. 100%는 긴 생존 문제를 해결하지 못하면서 모든 일반 조각을 2칸으로 고정한다. 따라서 90%를 출시 밸런스로 확정한 것은 아니다.

선택안에서 7병/8병 도달은 1수 46/60·18/60, 2수 모두 60/60이다. 도달한 판만의 중앙 도달 배치는 1수 28·65, 2수 23·58이다. 첫 정리 중앙값은 1수 8배치, 2수 6배치이고 최대 콤보 중앙값은 각각 ×2·×5다.

2수 정책의 배치별 평균 여유 칸은 7병·7색에서 15.96칸, 8병·8색에서 18.94칸, 8병·9색에서 16.52칸이었다. 같은 단계의 즉시 가능한 배치 대상 평균은 4.90·5.65·4.38곳이다. **확장 이후 공간이 넉넉해지고 숙련 판이 길어지는 위험이 남는다.** 단계별 평균은 도달한 판·배치의 분포이며 병 해금의 독립적인 인과 효과 추정이 아니다.

90% 후보에서 500배치까지 생존한 첫 6시드를 1,500배치까지 연장했다. 종료는 884·848·1,251·984배치였고 2판은 1,500 상한까지 생존했다. 이는 생존 조건으로 고른 표본으로 전체 생존율 추정에 사용할 수 없다. 8병·9색에서는 모든 색에 전용 병을 하나씩 배정하는 전략이 불가능하지만 장기 생존은 여전히 나타났다. ‘무한 전략이 없다’거나 실제 사람도 이만큼 생존한다고 입증한 결과는 아니다.

원자료는 `out/comparison-60-500.json`, `out/tail-comparison-60-500.json`, `out/tail-check.json`에 저장했다. 첫 두 비교 실행 시간은 각각 약 201초·175초였다. 점수 분위수, 종료 시 병·색 수, 여유 칸·배치 대상 수, 해금 행동 전후 상태도 원자료에 포함한다.

- 과거 기능 브라우저 회귀: 115/115. 계정 동기화는 인메모리 모의 서버·SDK 검증이며 실제 원격 계정 증거가 아니다.
- 기존 조작: 효과 축소 965/965, 전체 효과 961/961. 새 행 판정 도입 때 기존 병 위 착지 영역 회귀를 발견해 단일 행의 기존 판정을 유지했다.
- 기존 효과 배치: 하단 트레이 기본 규칙의 네 화면 크기에서 48/48.
- 확장 브라우저: **100/100 통과**, 결과는 `out/browser.json`. 네 화면 크기의 6/7/8병 배치, 44px 이상 터치 영역, 병 위치 유지, 두 조작 방식·두 트레이·마우스/터치, 행 사이 취소, resize 취소, 빠른 입력·멀티터치·키보드, 되돌리기·복원·기록·별 보상을 확인했다.
- 확장 화면을 강제로 만든 배치/입력 검사와, 빈 판의 고정 시드에서 점수를 실제로 얻으며 80배치 진행한 검사를 구분했다. 후자는 기능 단계 공개를 끈 설정에서 DOM 버튼 입력으로 두 해금을 거쳐 실제 엔진과 점수 4,800 및 보드·큐·성장 이력이 일치했다. 사람의 플레이 테스트는 아니다.
- 실제 휴대폰 터치 체험, 재미·피로도, 재방문·출시 성과는 미검증이다. 과거 `engine-test.js`의 콤보 리셋 기대값 한 건은 수정 전부터 실패했으며 해당 검사를 약화시키거나 기대값을 변경하지 않았다. `engine-test-v1.js`는 수정 전 통과했고 기준 엔진 동치 검증으로 호환성을 추가 확인했다.

## 직접 실행과 다음 판단

```powershell
node build-pages.js
node research/expansion/serve.js
```

브라우저에서 `http://127.0.0.1:8137/`을 연다. 과거 저장을 이어 하면 이전 규칙이므로 새 게임 또는 설정의 기본 규칙 적용으로 확장형을 시작한다. 로컬 미리보기 서버이며 공개 게시본은 바뀌지 않았다.

사람의 체험에서는 세 질문을 확인한다: 새 병을 얻고 계속하고 싶었는가, 두 줄에서도 빠르게 조작했는가, 확장 이후에도 정리 선택이 흥미로웠는가. 현재 결과로는 기능 검증이 끝난 실험용 무한모드이며 후반 생존 시간과 조작 피로도는 출시 전 판단이 남아 있다.
