# 병 재질·액체 이동·정리 연출 개선

작업일: 2026-10-09~10. 명세: `docs/PROMPT_bottle_quality_motion_fx.md`.

## 구현

`water-sort-survival.html`의 CSS와 UI 효과 경로를 수정했다. 새 라이브러리는 추가하지 않았다.

- 유리 입구의 안쪽 음영, 양쪽 반사, 바닥 두께와 접지 그림자를 추가했다. 선택·배치 가능·드래그 대상·거절 표시는 재질 그림자와 함께 유지한다.
- 같은 색의 실제 액체 칸을 시각적으로 연결했다. 실제 칸 수·기호·눈금은 유지하며, 미리보기와 드래그 유령은 실제 물과 연결하지 않는다. 작은 현재/다음/HOLD 병은 반사를 약하게 적용한다.
- 붓는 물 덩어리와 물줄기가 출발 병 입구, 곡선, 도착 병 입구, 도착 수면을 같은 경로로 지난다. 실제 병 버튼 좌표는 바꾸지 않고 기존 복제본을 이용한다.
- 착지 시 최상단 수면만 짧게 압축·반동하고 감쇠한다. 아래의 색층과 기호를 함께 늘이거나 줄이지 않는다.
- 성능 재측정 후 물줄기 본체와 반사선을 부모 SVG의 한 애니메이션으로 합치고 경로 표본을 16개에서 11개로 줄였다. 같은 색 연결 여부는 원본 배열에서 판단해 반복 DOM 조회를 없앴다. 수면 가상 요소도 실제 최상단에만 생성한다.
- 정리는 완성한 색의 응축 → 국소 반짝임 → 방향성 있는 물방울과 얇은 바닥 파동 → 점수 회수로 연결했다. 소수의 긴 물방울과 작은 둥근 방울로 형태를 만들며 입자 상한을 늘리지 않았다.
- 같은 병을 곧바로 재사용하면 오래된 완성 액체 스냅샷을 제거한다. 점수와 빈 병 사용 가능 시점은 효과 종료를 기다리지 않는다.
- 동시 정리의 주요 타격음·화음·진동·화면 반응을 한 그룹에 한 번으로 합쳤다. 타격음은 응축 종료 시점에 맞추고, 콤보에 따라 음량을 계속 키우지 않는다.

새 정리 스냅샷은 기존 노드·타이머 관리 경로와 함께 추적한다. 되돌리기, 새 게임, 모드/스킨/언어 변경, 설정, 화면 크기 변경, 탭 숨김, 동작 줄이기 전환 시 제거한다.

## 검증 방법과 증거

새 테스트 `uitest/bottle-quality.js`는 격리된 Chrome 프로필·고정 시드·테스트용 저장소를 사용한다. 실제 CDP 마우스 입력과 시간별 스크린샷으로 붓기, 착지, 단일 정리, 고콤보를 확인한다. 빠른 재사용은 20/50/80/260/390ms 간격으로 검사하고, 효과 켬/줄이기의 최종 상태와 점수를 비교한다. 일부 시나리오의 시작 상태·동시 정리는 테스트 훅으로 구성한다.

대표 이미지는 `outputs/bottle-quality/before-*`, `after-*`에 있으며, 장면별 0/20/120/230/350/470/650/950/1500ms 목표 시점과 실제 관측 시간은 JSON에 함께 남긴다. 스크린샷 촬영 비용 때문에 목표 시점과 실제 시점이 완전히 같지는 않다. 정지 화면만으로 모션을 통과시키지 않고 비행·수면·물방울 노드의 실제 재생도 검사한다.

`run-check.js`는 기존 검사 결과 파일을 보존하고 이번 결과를 `out/` 및 `outputs/bottle-quality/after/`로 복사한다. `uitest/make.js`, `uitest/run.js`, `research/feel/perf.js`에 추가한 선택적 `--source=...`는 작업 소스를 되돌리지 않고 기준선과 같은 검사를 실행하기 위한 테스트 전용 옵션이다.

### 검사 중 구분한 문제

- 새 비교 검사와 기존 HUD 검사의 고정 디버깅 포트가 다른 작업의 Edge 프로세스와 겹쳤다. 두 검사를 Chrome 전용 프로필의 자동 할당 포트(`DevToolsActivePort`)로 변경하고 재실행했다. 새 비교 검사는 CDP 응답 시간 제한과 고유 탐색 URL도 사용한다.
- 최초 새 테스트의 OS 동작 줄이기 설정이 일반 모션을 가렸다. 설정을 명시하고 실제 적용된 테마·스킨·모션, 비행·물방울 발생을 검사하도록 고쳤다. 최초 결과는 `probe-reduced-fixture.json`으로 보존했다.
- 기존 FX 검사는 탐색 직후 이전 문서의 훅을 읽어 360px 화면 높이가 0.53px 다르게 측정됐다. 고유 탐색 URL, 글꼴 준비, 두 프레임 대기로 수정했다. 허용 오차는 넓히지 않았다. 최초 실패는 `probe-navigation.json`에 보존했다.
- 예전 `feel` 전체 모션 검사에는 현재 커스텀 모드의 배너/콤보 배치와 맞지 않는 12개 실패가 있다. 저장한 수정 전 소스에서도 같은 이름과 결과로 재현됐다. 위쪽 트레이의 작은 점수바에서 콤보 문구가 생략되는 경우, 직접 표시한 큰 배너의 겹침 등이 포함된다. 이번 작업으로 모두 해결됐다고 보고하지 않는다.
- 수정 전 소스에 새 액체 스냅샷·물방울 형태 검사를 적용하면 추가 6개가 실패한다. 이는 의도한 표현 변경의 차이이며 배너 관련 기존 12개와 구분했다. 테스트를 삭제하거나 허용 범위를 늘려 통과시키지 않았다.

## 성능

같은 PC의 headless Chrome, 390×844 화면에서 기본(base)/강화(juicy) 효과와 CPU 1배/4배를 비교했다. 한 설정당 붓기 40수, 배치 10수, 정리 5수의 입력 처리 시간을 측정한다. 모든 설정에서 55수가 실행됐고 50ms 초과 long task는 0개였다. 이 값은 실제 휴대폰 FPS가 아니다.

먼저 기존 도구의 6수 예열·실행별 난수 시드를 그대로 사용했다. 아래 전 값은 `probe-paired-before-perf-perf.json`, 후 값은 최종 소스의 `after-perf-perf.json`이다. 다른 측정과 실패·튜닝 과정도 `before-*`, `probe-*`에 보존했다.

| 설정 | 전 p50 / p90 / max (ms) | 후 p50 / p90 / max (ms) |
|---|---|---|
| base / 1배 | 0.9 / 1.4 / 3.8 | 1.0 / 1.8 / 4.0 |
| base / 4배 | 3.7 / 5.1 / 12.3 | 4.0 / 7.7 / 14.8 |
| juicy / 1배 | 1.1 / 1.3 / 1.8 | 1.2 / 1.4 / 2.0 |
| juicy / 4배 | 4.8 / 5.7 / 5.9 | 5.4 / 6.5 / 7.0 |

최종 소스의 직전 반복 측정(`probe-surface-perf-perf.json`)에서 p90은 순서대로 1.7 / 4.8 / 1.4 / 6.2ms였다. 즉 기본 효과의 짧은 샘플에는 20%를 넘는 악화와 편차가 남는다. 이를 전체 성능 통과로 취급하지 않는다. 기본 효과의 경우 상대적으로 느린 정리 5수가 전체 55수의 상위 5개를 차지하여, 전체 p90이 나머지 행동의 거의 최대값에 좌우된다. 원시 행동별 시간도 남겼다.

강화 효과의 4배 감속 p90이 튜닝 전 6.9~8.0ms까지 늘어나, 이중 물줄기 애니메이션·DOM 조회·모든 층의 수면 가상 요소를 줄였다. 최종 반복값은 6.2~6.5ms다. 보통 시나리오의 최대 효과 노드는 전 76개에서 후 54개로 감소했고, 7병 동시 정리의 별도 최악 조건은 159개/입자 96개, 정리 후 잔존 노드·타이머·스냅샷은 0개였다.

초기 단기 샘플의 편차와 지속되는 비용을 구분하기 위해 추가로 `--steady` 조건을 전후 동일하게 실행했다. 이 조건은 시드 `bottle-quality-perf-fixed`, 예열 20수, 측정 55수이며 기존 측정과 섞지 않는다. 초기 측정값을 삭제하거나 허용 범위를 바꾸지 않았다.

| 설정 | 전 p50 / p90 / max (ms) | 후 반복 p50 / p90 / max (ms) | 후 2회 p90 범위 |
|---|---|---|---|
| base / 1배 | 0.9 / 1.3 / 4.5 | 1.0 / 1.5 / 4.6 | 1.3~1.5ms |
| base / 4배 | 3.7 / 5.7 / 12.7 | 4.0 / 4.7 / 13.7 | 4.5~4.7ms |
| juicy / 1배 | 1.1 / 1.3 / 1.7 | 1.2 / 1.5 / 2.3 | 1.5~1.6ms |
| juicy / 4배 | 4.9 / 6.3 / 7.2 | 5.6 / 7.0 / 8.1 | 6.4~7.0ms |

원본은 `probe-steady-before-perf-perf.json`, 후 첫 측정은 `probe-steady-after-perf-perf.json`, 후 반복은 `probe-steady-repeat-perf-perf.json`이다. 마지막 반복의 p90 변화는 +15.4% / -17.5% / +15.4% / +11.1%다. 강화 1배의 첫 측정은 +23.1%(+0.3ms)였으나 반복에서는 +15.4%(+0.2ms)였다. 예열된 고정 시드 조건에서 지속적인 20% 초과 악화는 재현되지 않았다. 초기 단기 조건의 증가까지 해소됐다는 의미는 아니며, 실제 휴대폰의 첫 입력과 긴 플레이 성능은 여전히 확인이 필요하다.
