# 보트리스 고득점 색상 도전 구현·검증

검증일: 2026-10-10. 이전 후반 압박 작업을 포함한 작업 중 소스를 기준으로 구현했다. 기존 변경을 유지했으며 커밋·푸시·공개 배포는 수행하지 않았다.

## 원인과 최종 규칙

4,500점 이후에는 새 조작이 열리지 않고 조각 확률만 바뀌었다. 고득점에서 완성 순서를 선택할 이유를 추가하기 위해 **지정 색 먼저 완성하기** 보너스 목표를 구현했다.

| 항목 | 동작 |
|---|---|
| 시작 | 새 표준 무한모드에서 실제 확장을 마친 뒤 10,000점부터 |
| 간격 | 5,000점 구간마다 한 목표. 여러 구간을 한 번에 넘겨도 목표가 쌓이지 않음 |
| 목표 | 다른 색 병보다 지정 색 병 1~2개를 먼저 완성 |
| 제한 | 성공한 조각 배치 12회. 붓기·보관·뒤집기·거절된 입력은 차감하지 않음 |
| 마지막 배치 | 12번째 배치 자체의 완성까지 인정한 뒤 종료 |
| 보상 | 목표 전체를 달성하면 병당 150점, 최대 300점. 부분 달성에는 보너스 없음 |
| 미달성 | 다른 색을 먼저 완성하거나 배치 제한을 소진하면 보너스 목표만 종료. 정상 완성 점수·콤보·생존 규칙은 유지 |
| 공정성 | 현재 보드·현재 조각·공개된 다음 조각·사용 가능한 보관 조각만 사용한 합법 달성 경로가 있는 목표만 제시 |

목표 탐색은 난수·생성 번호·조각 큐를 바꾸지 않는다. 최대 768개 전이, 12개 후보 보드, 20단계로 제한한다. 목표 색을 먼저 완성하는 경로를 확인하고, 준비가 필요한 목표를 우선한다. 탐색으로 증명하지 못한 판에서는 다음 성공 배치 이후 다시 확인한다. 숨겨진 미래 조각을 읽거나 목표용 조각을 지급하지 않는다. 제한 탐색이므로 가능한 목표를 놓칠 수는 있다.

상단의 기존 성장 안내 공간에 목표 색·완성 수·남은 배치를 표시하고 목표 색이 있는 병에 작은 표식을 붙였다. 시작·완료·종료 안내와 기존 음향·물결 연출을 연결했다. 완료 횟수와 다음 목표까지 남은 점수를 표시하며 결과 화면에도 달성 횟수·보너스를 남긴다. HUD 행과 병 높이는 유지했다. 한국어·영어·일본어·중국어 간체/번체·스페인어·브라질 포르투갈어·힌디어·인도네시아어를 처리했다.

## 저장과 호환성

- `colorChallengeVersion: 1`과 시작점·구간 간격·배치 제한·보너스·목표 수·완성 순서 조건을 기록 서명에 포함했다.
- 이전 압박 규칙은 `PRESSURE_ENDLESS_RULES`로 보존했다. 진행 중 저장·명시적 커스텀·오늘의 도전은 자동 변경하지 않는다. 기존 표준 설정의 다음 새 판부터 새 규칙을 사용한다.
- 목표 진행·종료 결과·지급 합계는 게임 상태에 포함되며 저장·새로고침·되돌리기로 함께 복원된다. 보너스 중복 지급을 방지하고 기존 최고 기록 키를 삭제하지 않는다.
- 손상된 새 상태는 기존 복구 저장 경로로 보호한다. 봇 후보 상태도 목표 객체를 따로 복사하여 탐색이 실제 상태를 오염시키지 않도록 했다.

## 비교에서 조정한 내용

처음에는 지정 색 병을 완성하면 보너스를 주는 단순 목표를 시험했다. 기존 생존 봇이 목표를 고려하지 않아도 종료된 목표 **121/121**을 달성했다. 제한을 12회에서 6회로 줄여도 결과가 같았다. 따라서 제한 횟수는 12회로 유지하고, 완성 순서를 조건에 포함했다.

최종 소스로 `color-challenge-20261010-0`부터 `-15`까지 동일한 16개 시드, 기존 2회 붓기 탐색·보관·뒤집기 정책, 판당 500 성공 배치 한도로 세 조건 **48판**을 새로 실행했다. 봇 평가는 목표를 고려하도록 바꾸지 않았다.

| 조건 | 10,000점 도달 | 500배치 제한 생존 | 종료 목표 / 달성 | 달성률 | 보너스의 총점 비중 |
|---|---:|---:|---:|---:|---:|
| 기존 압박 규칙 | 16/16 | 14/16 | 없음 | — | 0% |
| 단순 지정 색 완성 | 16/16 | 14/16 | 121 / 121 | 100% | 2.48% |
| 지정 색 먼저 완성, 최종 | 16/16 | 14/16 | 120 / 86 | 71.67% | 1.78% |

최종 목표 중 34개는 다른 색을 먼저 완성하여 놓쳤으며 배치 제한으로 놓친 목표는 없었다. 이 표본에서 제시된 목표는 모두 1병이었다. 2병 목표는 공개된 동일 색 물량이 충분한 경우에만 열리며 별도 엔진·실제 입력·체험 화면으로 검증했다.

평소 정렬만으로 모든 목표를 달성하는 문제는 줄었으나, **사람의 재미·재도전·유지율은 검증하지 않았다.** 완성 순서 조건과 목표 선정 방식이 함께 달라졌으므로 달성률 변화를 조건 하나의 인과 효과로 해석하지 않는다. 제한 생존은 실제 종료 시간이 아닌 관측 중단이며 이 16개 시드만으로 출시 밸런스를 확정하지 않는다. 기존 후반의 긴 생존 문제를 해결했다는 결과도 아니다.

## 검증

| 검사 | 결과 |
|---|---:|
| 새 목표 엔진: 경계·순서·마지막 배치·지급·복원·커스텀 계약 | 14그룹 통과 |
| 무작위 보드 목표 탐색 | 400개 보드, 363개 증명 경로 |
| 증명 경로 재생 | 미공개 조각열을 바꾼 1,089번 모두 통과 |
| 기존 v2 | 1,070/1,070 |
| 기존 보관/3칸·확장 | 16그룹 / 17그룹 |
| 기존 후반 압박 | 9그룹, 적격 조각 480,000개 |
| 새 모바일·9언어·실제 터치/마우스·저장·되돌리기 | 1,244/1,244 |
| 체험 화면 실제 입력·기록 미저장 | 6/6 |
| 기존 상단 HUD / 이펙트 | 164/164 / 122/122 |
| 기존 폰트·모션·사운드 | 2,741/2,741 |

새 화면 검사는 360×640 및 390×724, 두 트레이 위치, 9개 목표 색, 열리기 전·목표 준비 상태를 포함했다. 안전 여백은 CSS로 주입한 조건이다. 검사 중 외부 글꼴 대기 62회 가운데 2회는 2.5초 제한에 도달하여 당시 폴백 글꼴로 측정했다. 실제 휴대폰 검증은 수행하지 않았다.

이전 소스와 최종 소스를 같은 25,000점·9색·8병 강제 상태에서 비교했다. 기본/강화 연출과 1배/4배 CPU 조건 모두 정상 행동 55/55, 실행 오류 0회였다. 최종 소스의 50ms 초과 긴 작업은 네 조건 모두 0회였다. 이전 기본 연출 4배 조건에는 2회가 관측됐다.

강화 연출 1배에서 전체 행동 p90은 1.6→4.5ms, 배치 p90은 1.7→7.5ms였다. 4배에서는 전체 p90 7.9→18.9ms, 최종 최대 22.3ms였다. 목표 탐색 비용의 증가를 확인했다. 배치 표본은 각 10회이며 프레임 속도나 실제 휴대폰 성능의 증거로 사용하지 않는다. 각 강제 상태에서 목표를 초기화하여 턴을 거꾸로 설정하는 테스트가 잘못된 저장으로 판단되지 않도록 했다.

## 로컬 확인과 증거

- 일반 플레이: <http://127.0.0.1:8154/>
- 10,000점 목표 체험: <http://127.0.0.1:8159/>. 독립 출처와 메모리 저장소를 사용하며 게임 기록은 저장하지 않는다.
- `out/engine-test.json`, `comparison.json`, `browser.json`, `demo-browser.json`, `pressure-engine-test.json`에 최종 소스/엔진 해시와 원자료를 남겼다.
- `out/trial-simple*.json`은 초기 단순 목표 실험이며 최종 규칙의 증거와 구분한다.
- 이전 소스와 브라우저 이미지는 `outputs/color-challenge/`에 있다. 이 폴더는 기존 저장소 관례대로 Git 제외 대상이다. 엔진의 이전 동작 비교와 화면 높이 비교를 재실행하려면 이 작업에서 캡처한 이전 스냅샷이 필요하다.
- 로컬 일반 플레이 응답은 HTTP 200이며 최종 `dist/index.html` 바이트와 일치한다. `out/verification.json`에서 최종 소스·검사·빌드의 연결을 확인한다. 공개 GitHub Pages 배포는 하지 않았다.

재검증: `node build-pages.js`, `node research/color-challenge/engine-test.js`, `node uitest/color-challenge.js`, `node research/color-challenge/compare.js --n=16 --cap=500`, `node research/color-challenge/verify-evidence.js`.
