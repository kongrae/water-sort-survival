HOLD는 병에서 물을 받거나 일부 조각을 나누는 기능이 아니다. 버튼으로 보관·교환한 뒤 현재 조각의 기존 탭/드래그 넣기를 사용한다. `canHold / holdCandidate / applyHold`를 엔진·UI·봇에서 재사용한다. 불가능한 HOLD는 상태를 바꾸지 않는다. 미리보기 0~3 모두 결정적인 다음 조각을 한 번만 소비한다.

보관에는 조각 순서, 소개 색 메타데이터, 뒤집힌 상태가 함께 이동한다. 배열은 복사한다. HOLD 자체는 턴·점수·콤보·붓기 예산·성장을 지급하지 않으며, 붓기·뒤집기·실패한 입력으로 사용권이 복구되지 않는다.

### 뒤집기와 패배 판정

뒤집은 보관 조각은 뒤집기 1회를 예약한다. 실제 배치에서만 소비하고, 이미 소비한 횟수와 현재·보관 예약 합계가 제한을 넘지 못한다. 무제한 설정 및 이미 뒤집힌 현재 조각을 원래 순서로 되돌리는 계약은 유지했다. UI 잔여 횟수와 보관 조각의 ⇅ 표시도 예약을 반영한다.

현재 조각의 배치/붓기 경로와 합법적인 단일 HOLD 대안을 검사한다. 같은 길이의 후보는 보드 탐색을 재사용한다. `true / false / 'unknown'` 계약을 유지하며, 모든 합법적 분기가 확정 불가능할 때만 종료한다. HOLD만으로 살 수 있는 경우에는 홀드 안내를 표시한다. 0개 미리보기에서 대안을 확인하는 가상 생성은 실제 큐·생성 번호를 소비하지 않는다.

3칸은 한 병에 연속 빈칸 3개가 있어야 들어간다. 분산된 빈칸 합계는 허용하지 않는다. 들어갈 곳이 없다고 조각을 줄이거나 공급을 조절하지 않는다. 생성·형태 전용 결정적 난수 분기를 분리해 기능을 끈 과거 규칙의 조각 순서도 보존했다.

## 저장·기록·기존 사용자

- 진행 중 저장은 저장된 규칙 그대로 복원한다. 옛 판에 새 HOLD나 3칸을 끼워 넣지 않는다.
- 이전 기본 설정 사용자의 다음 새 판만 새 표준으로 전환한다. 명시적 커스텀 및 임의 확장 규칙은 보존한다. 고정 보드 커스텀으로 바꾸면 기능 플래그도 제거한다.
- 일일 도전은 이전 날짜 시드·규칙·순서를 유지한다.
- 저장 버전 `v:1`과 기존 최고점·페이스·별·테마·클라우드 키 구조를 유지한다. 새 서명에 HOLD/3칸 버전·해금·확률·형태 정책을 포함한다. 기존 기능 없는 서명 문자열은 그대로다.
- 서명은 시작 규칙으로 고정한다. 플레이 중 병 증가나 보관 내용으로 변하지 않는다. 실험 후보의 기록은 섞이지 않는다. 별 획득 자격은 이전 표준과 새 표준에만 부여한다.
- 최근 페이스 인덱스는 10개를 유지하면서, 새 정책 추가 때문에 옛 `pace/last/runs` 키를 삭제하지 않도록 했다.
- 성공한 HOLD 직전에 기존 히스토리 스냅샷을 남긴다. 되돌리기는 현재·보관·큐·생성 번호·소개 정보·뒤집기 예약·사용권을 복원하고 기존 비용/한도를 따른다.
- 신규 기능 저장은 조각 길이·색·형태·소개·플래그·예약 예산·큐 등 필수 상태를 검사한다. 손상 상태는 `wsurv.recovery.<mode>`에 원본과 시간을 보존하고 복구 안내와 새 판을 표시한다. 원본 백업이 용량 제한 등으로 실패하면 그 세션의 해당 모드 진행 저장을 중단해 손상 원본을 덮어쓰지 않는다. 이 예외는 화면에 안내한다.
- 모의 클라우드/Firebase 검증만 수행했다. 실제 계정 로그인이나 원격 데이터 쓰기는 수행하지 않았다.

## UI·이펙트·다국어

기존 지금/다음 트레이에 가로로 HOLD를 추가했다. 6병부터 60×66 CSS px 버튼 공간을 확보해 해금 시 세로 배치가 밀리지 않는다. 보관/교환·잠금·배치 후 재사용 표시와 ARIA 설명을 제공한다. 긴 보조 문구는 짧은 표시와 전체 접근성 문구로 나눴다.

3칸 현재·다음·홀드·드래그 표시는 기존 2칸 프레임 안에 세 물칸을 그린다. 병 높이에 영향을 주는 최대 조각 길이 값을 일괄 변경하지 않았다. 네 가지 스킨의 물 색상 기호와 순서를 유지했다.

HOLD는 엔진 상태를 즉시 교환한 뒤 220ms 이동/강조 효과를 재생한다. 이전 드래그·선택·착지 힌트를 정리하고, 진행 중 정리/점수 연출과 빠른 입력을 유지한다. HOLD 자체로 점수/콤보/화면 흔들림을 만들지 않는다. 3칸 비행 물방울, 넣기·정리·상단 병 드래그를 확인했다. 효과 전체/축소에서 동일 행동의 최종 상태가 같고 애니메이션이 정리된다.

한국어·영어·일본어·중국어 간체/번체·스페인어·브라질 포르투갈어·힌디어·인도네시아어에 신규 17개 메시지를 추가했다. 전체 362개 메시지, 9개 언어를 내장한다. 기본 블랙, OS 밝음일 때 어두운 기본값, 페이지 스크롤 방지, 설정 내부 스크롤은 보존했다.

## 제한된 밸런스 비교

명령:

```powershell
node research/hold-triple/compare.js --n=60 --cap=500 --workers=3
node research/hold-triple/compare.js --tails --workers=3
```

각 조건에 `expansion-0`~`expansion-59`, 1수/2수 붓기 탐색 정책, 최대 500배치를 적용했다. 6조건 × 2정책 × 60 = **720판**. 부활/임시 잔 없이 실제 HOLD 전이를 사용했다. 각 후보의 탐색 깊이·그리디 반복 한도 60/40, 부족 공간 경로 깊이 10·노드 30,000 한도를 유지했다. HOLD 후보도 평가하므로 기능 조건의 실제 후보 수와 연산 시간은 더 크다. 이는 사람의 초보/숙련 구분이 아니다. HOLD로 큐 소비·성장 시점이 달라져 같은 시드의 공급 조각이 완전히 같지는 않다.

### 선택과 남은 판단

**5%를 보수적인 첫 실험값으로 유지한다.** 10%는 1수 정책에서 3칸이 현재인 종료를 늘렸고, HOLD 결합의 2수 500배치 생존은 5%와 같은 57/60이었다. 연장 6개 표본으로 10%의 우월성을 주장할 수 없다.

HOLD는 기능적으로 공간 선택을 제공하지만, 기존에도 긴 2수 정책의 판을 더 길게 만들었다. 3칸 단독은 압박을 더했지만 결합 시 HOLD의 생존 증가를 충분히 줄이지 못했다. 현재 결과로 재미·리텐션·출시 적합성을 입증할 수 없다. 이번 범위를 벗어나는 성장표/점수/시간 제한을 함께 바꾸지 않았다. 사람의 플레이 후 후반 난도 조정 여부를 별도 판단해야 한다.

사람 테스트 질문은 세 가지다.

1. HOLD가 선택을 늘렸는가, 입력을 늦췄는가.
2. 3칸 조각을 준비해서 받아낼 수 있었는가.
3. 8병 이후에도 다시 최고 기록에 도전하고 싶었는가.
