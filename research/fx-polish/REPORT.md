# 병 높이 복원과 이펙트 강화 구현·검증

작성: 2026-10-09. 기준 HEAD: a1588911532d918a91829e3daf8d49dfde20018a.

## 결과

두 줄 배치를 유지하면서 여유 있는 화면의 병 높이를 원래 크기로 복원했다. 짧은 화면은 실제 사용 가능한 높이를 측정해 축소한다. 물줄기·착지 파동, 완성 색의 물방울과 두 겹 충격파, 콤보 무대, 새 병의 유리 윤곽과 반사를 개선했다. 연출은 입력을 잠그지 않는다.

원인은 확장형의 --lh 축소와 고정 행 높이에 따른 .glass의 추가 flex 축소였다. 행이 유리·입구·레이블 전체를 담게 수정하고, 위 줄 예약 공간은 비어 있어도 유지했다. 폰트 로드, 언어, 트레이, 스킨, 뷰포트 변경에서만 크기를 다시 계산한다. 매 입력에서 뷰포트 높이와 미디어 쿼리를 읽던 초기 구현의 비용을 제거했다.

## 실제 병 크기

같은 Pages 문서 골격, 같은 8병 검증 상태, 한국어·어두운 기본 스킨으로 측정했다. 단위는 CSS px이며 유리 높이는 getBoundingClientRect 값이다.

| 뷰포트 | 수정 전 유리 | 수정 후 유리 | 수정 후 병 너비 | 스크롤 |
|---|---:|---:|---:|---|
| 360×640 | 75.48 | 78.47 | 48 | 없음 |
| 360×740 | 87.41 | 99.27 | 48 | 없음 |
| 390×844 | 103.31 | 136.00 | 53 | 없음 |
| 412×915 | 103.31 | 136.00 | 56.66 | 없음 |
| 768×1024 | 103.31 | 136.00 | 58 | 없음 |

390×844에서 약 32% 높아졌다. 360×640에 원래 높이 136px를 고정하는 것은 화면 안에 들어가지 않으므로 제한된 높이를 유지한다. 작은 화면의 글자·버튼·조각을 축소해서 억지로 원래 높이를 넣지 않았다.

6/7/8병에서 아래 6개와 현재 조각의 좌표가 동일하고, 7번째 병도 다음 확장 때 이동하지 않는다. 기본 플레이 화면의 병과 주요 버튼은 44px 이상의 조작 영역을 유지한다.

## 연출 변화

- 붓기: 색이 이어지는 짧은 곡선 물줄기, 길쭉해지는 액체, 출발 병의 시각 복제본 기울기를 추가했다. 실제 병 버튼은 기울이지 않는다. 착지에는 얇은 수면 파동과 짧은 반동을 준다.
- 완성: 실제 축소된 액체 칸 높이에 맞는 색 기둥을 사용한다. 색이 모이는 짧은 강조 뒤 크기·속도가 다른 물방울, 파동, 점수 비행이 이어진다. 높은 콤보에는 두 번째 얇은 파동이 추가된다.
- 콤보: 강도는 기존 streak를 사용하고 시각 강도는 상한을 둔다. 확장형에서는 위 줄 왼쪽 두 칸의 빈 공간에 콜아웃을 표시해 점수·병을 가리지 않는다. 긴 번역은 12px 이상으로 줄바꿈한다.
- 성장: 위 줄 오른쪽 두 칸의 빈 공간에 짧은 안내를 표시한다. 경고·점수·병과 겹치지 않는다. 새 병의 윤곽·반사와 수면 파동은 별도 효과이며 실제 버튼은 즉시 사용할 수 있다.
- 한 행동에 여러 성장 이벤트가 생겨도 안내·사운드는 한 번으로 모은다. 두 병을 동시에 받으면 빈병 +2와 최종 병 수를 정확히 표시한다.
- 평상시: 기존 스킨의 색과 마감을 보존하면서 얇은 유리 반사와 액체의 정적인 광택을 추가했다. 상시 입자 배경은 추가하지 않았다.
- 사운드: 착지의 가벼운 유리 음과 물방울 음, 완성의 짧은 저음·화음을 조정했다. 다중 완성의 타격음을 중복하지 않고 기존 컴프레서·음소거·진동 설정을 유지했다.
- 신기록: 기존 판당 한 번의 안내와 결과 화면 보상을 유지한다. 별도 보상이나 기록 조건은 추가하지 않았다.

## 입력, 정리, 접근성

20/50/80ms 간격으로 완성 직후 다음 붓기를 실행해 두 수가 즉시 처리되고 이전 효과도 정상적으로 끝나는 것을 검증했다. 기본·강화·줄이기 설정에서 최종 게임 상태를 전체 비교했다.

이 비교에서 기존 lastBigTurn 안내 메타데이터가 기본 연출에서만 갱신되던 차이를 발견했다. 강화 연출에서도 동일하게 갱신해 설정에 따른 저장 상태 차이를 제거했다. 순수 엔진 블록은 변경하지 않았다.

되돌리기, 새 판, 설정 열기, 언어 변경, 리사이즈, 탭 숨김에서 효과와 타이머·점수 카운터·배너를 정리한다. 별도 Chrome 탭을 실제 활성화해 원래 탭의 document.hidden이 true인 것을 확인하고 복귀 후 정리도 검증했다. 20회 연출을 중단하고 초기화해도 유령 액체, 효과 노드와 늦은 점수 변경이 남지 않는다.

OS 동작 줄이기와 게임 설정을 함께 존중한다. 저장된 효과 설정이 켜져 있어도 OS가 줄이기를 요구하면 비행·입자·흔들림을 생략한다. OS 선호 변경 후 판을 초기화하지 않고 효과를 복원한다. 필수 선택·완성·점수 피드백은 즉시 표시한다.

효과 계층은 pointer-events: none과 기존 aria-hidden을 유지한다. 새 성장 안내 두 종류는 한국어와 8개 번역을 추가해 345개 메시지를 임베드한다. 기존 저장 키·언어 전환·색상 기호·미리보기 계약은 보존한다.

## 성능

동일한 research/feel/perf.js로 수정 전과 수정 후 각각 기본/강화, 일반/4배 CPU 감속을 측정했다. 각 조건은 붓기 40수·배치 10수·고콤보 완성 5수로 55수 모두 처리됐다. 아래는 강화 연출이다.

| 항목 | 전 | 후 |
|---|---:|---:|
| 일반 입력 처리 p50 / p90 / max | 1.1 / 1.4 / 1.8ms | 1.2 / 1.5 / 1.6ms |
| 4배 CPU 감속 p50 / p90 / max | 4.0 / 5.1 / 7.4ms | 4.9 / 6.3 / 8.8ms |
| 일반 / 감속 long task | 0 / 0 | 0 / 0 |
| 해당 시퀀스의 최대 효과 노드 | 119 | 76 |

일반 속도의 p90 변화는 +0.1ms다. 4배 감속에서 p90이 +1.2ms 늘었지만 입력을 지연시키는 대기나 50ms 이상의 작업은 없었다. 기본 연출에서는 초기화/워밍업의 약 55~56ms 작업이 전후 각각 한 번 있었으며, 강화 연출에서 새 long task는 관측되지 않았다.

전역 효과 노드 예산은 180개, 물방울 예산은 96개다. 예산 초과 시 장식부터 제거하며 상태 변경·착지·점수 처리는 유지한다. 다중 완성 스트레스 검사에서도 전역 상한 안에서 모두 정리됐다. 이 비용 측정은 headless Chrome의 입력 처리 시간이며 실제 휴대폰 FPS 측정이 아니다.
