성장 계약은 유지한다.

1. 병은 점수를 얻은 합법 행동 정산 중 막힘 판정 전에 지급한다. 붓기·배치·색상 목표 보너스와 점수 도약을 포함한다.
2. 색은 성공 배치에서 최대 1종씩 활성화한다. 한 번에 여러 기준을 넘어도 색을 건너뛰거나 중복 소개하지 않는다. 병 지급을 모든 새 색이 활성화될 때까지 임의로 지연하지 않는다.
3. 현재·공개 큐·보관 조각은 유지하고 새 색 소개는 기존 `pendingIntro` 정책을 사용한다. 소개가 추가 완성 물량이나 자동 정렬 보상이 되지 않게 한다.
4. 실패·종료 입력, 렌더, 확률 조회, 탐색은 성장·점수·generation을 진행시키지 않는다.
5. 되돌리기·저장·재로드는 병·색·소개 대기·큐·보관·성장 로그·목표를 함께 복원한다. 경계 재통과가 중복 지급으로 이어지지 않는다.
6. 마지막 성장 후에는 다음 병이나 색이 계속 열린다고 안내하지 않는다. 이후 기록 도전과 색상 목표는 계속된다.

## 3 병 배치와 화면 연출

**기존 병 높이·물 층 높이·터치 영역을 유지한다.** 3행, 문서 세로/가로 스크롤, 병 축소, HUD 행 추가로 12병을 수용하지 않는다. 기존 2행과 화면 높이 예산 안에서 해결한다.

아래 줄은 엔진 인덱스 0~5를 1~6열에 유지한다. 윗줄의 최초 슬롯 후보는 다음과 같다. 열 번호는 1부터 시작한다.

| 엔진 병 인덱스 | 윗줄 열 |
|---|---:|
| 6 | 3 |
| 7 | 4 |
| 8 | 5 |
| 9 | 6 |
| 10 | 2 |

이 순서는 현재 7~9번째 병 위치를 유지하면서 빈 칸을 채운다. DOM 배열과 엔진 인덱스의 대응을 유지하고, 실제 입력은 화면 위치의 순서가 아닌 병 인덱스로 전달한다. 병 해금 때 기존 병들이 이동하지 않는지 측정한다.

현재 `i - 3` 열 계산은 11·12번째 병을 7·8열로 보내므로 명시적인 슬롯 매핑이 필요하다. 병 개수 변화 때 연출 좌표 캐시가 갱신되는 기존 수정도 보존한다.

**11병부터 현재 콤보·배너용 왼쪽 2열이 좁아지고, 12병에서는 윗줄의 빈 칸이 사라진다.** 병 배치와 연출 배치를 함께 수정한다.

- 10병 이하와 11/12병의 연출 공간을 실제 좌표로 구분한다. 병이 놓인 영역을 빈 연출 칸으로 취급하지 않는다.
- 기존 HUD/트레이의 고정 높이 안에서 정보와 연출의 내부 배치를 조정할 수 있다. 점수·현재/다음 조각·HOLD·활성 목표·조작 버튼을 불투명 배너가 덮지 않게 한다.
- 콤보 숫자와 상태 안내는 유지한다. 큰 버스트가 들어가지 않으면 간결한 숫자·빛·병 주변 효과로 표현하되 정보를 통째로 숨겨 해결하지 않는다.
- 새 색/병 해금·붓기·착지·클리어·목표·위험 연출의 좌표, 수명, 연속 입력, 되돌리기/새 게임 정리를 확인한다. 입자와 소리가 새 색 인덱스에 연결되어야 한다.
- 기본·강화 연출, 모션 줄이기, 음소거, 상하 트레이와 두 조작 방식에서 확인한다. 필수 클릭 대기나 입력을 막는 전체 화면 연출을 추가하지 않는다.

## 4 색 표현과 다국어

기존 10색의 인덱스·색 이름·기호·팔레트는 보존하고 새 3색을 끝에 추가한다. `--liq10`~`--liq12`, 색 이름, 고유 기호, ARIA, 목표 스와치, 미리보기, HOLD, 착지·붓기·클리어 입자까지 연결한다.

4개 스킨의 다크/명시적 라이트에서 기존 색·유리·빈칸과 구분되는 후보를 선택한다. 고유 기호는 작은 물 층에서도 구분되고 기존 기호와 중복되지 않아야 한다. 네모 글리프·빈 기호·`undefined`·잘못된 CSS 색 변수를 검사한다. 색·기호 설정은 기존 사용자의 선택을 유지한다. 화면 캡처와 자동 검사는 사람의 색 구분이나 색각 접근성의 입증으로 보고하지 않는다.

한국어·영어·일본어·중국어 간체/번체·스페인어·브라질 포르투갈어·힌디어·인도네시아어 9개 언어를 처리한다. `messages.tsv`와 삽입 절차를 사용하고 생성된 런타임을 손으로 편집하지 않는다. 활성 목표를 기존 `colorInfo`에서 우선 표시하고, 목표가 없으면 다음 색/병까지 남은 점수를 표시한다. 최대 색에 도달해도 병 성장이 남아 있음을 안내한다. 도움말은 **선택한 최종 성장표**를 설명해야 한다.

## 5 정책 버전과 기존 기능 호환성

현재 표준 10색·9병 규칙을 정확히 보존하는 상수를 만들고 새 정책을 명시적으로 버전 관리한다. 예를 들어 기존 `lateGrowthVersion: 1`을 보존하고 새 정책을 `lateGrowthVersion: 2`로 구분할 수 있다. 기존 `expansion === 1` 계약은 유지한다.

- 버전 없는 기존 확장: 9색·8병 상한과 기존 정제·서명·동작 유지.
- 후반 확장 버전 1: 10색·9병 상한과 기존 성장표·서명·조각열·목표 동작 유지.
- 새 버전: 최대 13색·12병을 해당 정책에만 허용. 구체적인 성장표·압박표와 결과에 영향을 주는 필드를 난도 서명에 반영.

진행 중 게임은 저장된 규칙으로 계속한다. 이전 표준 설정만 다음 새 판부터 새 기본값으로 갱신하며 명시적 커스텀·일일 도전은 보존한다. 과거 최고 기록·별·통계·클라우드 키를 삭제하거나 새 난도에 소급 적용하지 않는다. 이전 표준의 별 지급 자격도 보존한다. 설정을 열고 적용할 때 최대 색과 정책이 잘못된 기본 옵션으로 바뀌지 않아야 한다.

규칙 정제와 저장 검증에서 버전별 색 인덱스·병 수·성장표 단조성·중복 점수·범위·손상 버전을 검사한다. 최초 후보는 성장표 14행이므로 기존 16행 제한 안에 들어간다. 잘못된 새 저장은 기존 복구 보호 경로를 따른다.

새 정책에서도 다음 계약을 보존한다.

- 실제 9색부터 일반 1/2칸 비율 10%/90%. 새 최대 색 13을 이 비율의 시작 조건으로 사용하지 않는다.
- 실제 9색·8병 기본 확장 후 10,000점부터 색상 목표. 미래 성장 때문에 시작·탐색·표시를 막지 않는다.
- 목표는 지정 색 우선, 성공 배치 12회, 5,000점 간격, 병당 150점·최대 300점. 활성 목표는 성장 때 초기화하거나 제한을 연장하지 않는다.
- 목표 증명은 현재 실제 병과 공개된 물만 사용한다. 아직 받지 않은 10~12번째 병과 미공개 조각은 사용하지 않는다.
- HOLD 7병, 3칸 조각 8병, 뒤집기·일반 점수·콤보·소개 물량·미리보기·병 용량은 유지한다. 4칸 조각을 새로 만들지 않는다.
- 일반/3칸 난수 스트림과 generation 단위를 유지한다. 새 정책 메타데이터를 제외하고 **30,000점 이전 동일 시드·동일 행동 결과는 현재 10색·9병 기준선과 같아야 한다.**

기존 검사에서 버전 2를 미지원 손상으로 사용한 경우에는 새 지원 버전과 구분하여 미지원 값으로 검사한다. 기존 버전 1 검사는 보존한 이전 표준을 명시하여 계속 실행한다. 행동 계약을 삭제하거나 과거 증거의 해시를 새 결과로 바꾸지 않는다.

## 6 허용할 난이도 조정

색·병 수와 최종 공간은 구현 목표다. 난이도 조정은 **새 성장의 점수 간격과 기존 3칸 생성 정책의 후반 확률표** 안에서 수행한다. 플레이 중 보드 상태를 보고 몰래 확률이나 병 지급을 바꾸는 자동 난도 조정은 추가하지 않는다. 선택한 후보는 한 판 내내 고정된 규칙이다.

0~18,000점 성장, 30,000점 첫 새 색, 25,000점까지 기존 압박표는 유지한다. 목표 보상·콤보·병 용량·HOLD·뒤집기·소개 물량을 함께 조정하지 않는다. 새 성장 점수를 조정한다면 40,000점 이후 행을 최초 값의 ±20% 안에서 움직이고, 점수·색·병 단조성과 색 먼저/병 나중 순서를 유지한다.

후반 압박의 최초 비교 후보는 다음과 같다. 모든 후보에서 기존 4,500/10,000/15,000/25,000점 행을 유지한다. 새 구간의 3칸 단색 비율은 10%로 유지하여 한 번에 여러 확률 축을 바꾸지 않는다.

| 점수 | A 성장만 | B 완만한 압박 추가 | C 더 강한 압박 | D 더 약한 압박 |
|---|---:|---:|---:|---:|
| 30,000 | 12% | 12% | 12% | 12% |
| 40,000 | 12% | 14% | 16% | 13% |
| 70,000 | 12% | 17% | 22% | 15% |
| 100,000 | 12% | 20% | 28% | 18% |

표의 값은 일반 생성 중 3칸 조각 확률이고 소개 조각은 기존처럼 별도로 처리한다. 28%는 이번 탐색의 상한이다. A는 기존 12% 상한 그대로이며 별도 행이 없어도 의미가 같다.

**현재 `pressureAt()`은 행 사이를 선형 보간한다.** 25,000점 다음에 높은 확률의 행을 바로 추가하면 새 색 이전부터 확률이 변한다. 30,000점에 기존 값 12%/10%인 고정점을 두어 30,000점 이전 압박·조각열을 유지하고, 이후만 보간한다. 이 계약을 실제 생성열로 검증한다.

## 7 제한된 비교와 결과에 따른 수정 절차

`research/full-board/`에 기존 봇·측정 구조를 재사용한 별도 도구를 만든다. 첫 비교 전에 아래 표본·시드·선택 기준을 설정 파일에 고정한다. 기존 깊이 2의 붓기 탐색·생존 평가·홀드/뒤집기 정책을 조건마다 동일하게 유지한다. 후보에 유리하도록 봇이나 탐색 예산을 변경하지 않는다.

### 탐색 비교

시드 `full-board-tune-20261011-0`~`19`, 조건당 20개 새 판, 성공 배치 1,500회 한도로 다음 4조건을 새로 실행한다.

1. 기준선: 현재 작업 전 10색·9병 규칙.
2. 색 추가만: 30,000/55,000/85,000점에 색은 늘지만 병은 9개로 유지. 압박은 기존 상한.
3. 전체 성장 A: 최초 성장표, 압박은 기존 상한.
4. 전체 성장 B: 최초 성장표, 완만한 압박 추가.

색 추가만과 A를 비교하여 병 지급의 효과를 분리하고, A와 B를 비교하여 후반 압박의 효과를 확인한다. 11색·9병 → 11색·10병, 12색·10병 → 12색·11병, 13색·11병 → 13색·12병을 각각 보고한다.

그 결과로 다음 작업을 실제로 수행한다.

- A가 충분한 긴장을 유지하면 A를 선택한다. 병 지급 뒤 여유와 관측 중단이 크게 늘어나면 B를 우선 평가한다.
- B도 지나치게 쉬우면 C를, B가 급격한 붕괴를 만들면 D를 추가 비교할 수 있다.
- 문제가 확률보다 성장 간격에 있다고 판단되면 C/D 대신 성장 점수 한 축을 조정한 후보를 추가할 수 있다. 근거를 해당 구간 지표로 설명한다.
- **추가 후보는 최대 1개**이며 같은 20시드로 실행한다. 탐색은 최대 5조건·100판이다. 성장 점수와 확률을 동시에 바꾸어 원인을 설명할 수 없는 추가 후보를 만들지 않는다.
- 마지막에는 선택한 성장표·압박표를 실제 새 표준으로 반영한다. 비교 파일의 규칙과 제품 기본 규칙이 일치해야 한다. 후보가 명백히 쉬운데 경고 문구만 쓰고 A를 그대로 확정하지 않는다.

### 최종 비교와 독립 시드 확인

후보를 선택한 뒤 코드를 고정하고 **기준선과 최종 후보를 각각 40판** 재검증한다. 시드는 `full-board-final-20261011-0`~`39`, 성공 배치 한도는 1,500회다. 이어서 선택에 사용하지 않은 `full-board-holdout-20261011-0`~`19`로 기준선/최종 후보 각 20판을 확인한다. 최종·독립 시드 비교는 총 120판이다.

독립 시드 결과를 보고 유리한 시드만 남기거나 계속 재조정하지 않는다. 결과가 반대로 나오면 불안정성과 남은 위험을 보고한다. 탐색 100판과 최종 확인 120판을 넘겨 후보 탐색을 계속 늘리지 않는다. 엔진·UI 결함 수정은 이 제한과 별도로 반드시 처리한다.

### 관측과 판단 기준

다음 수치는 **이번 자동 비교에서 후보를 선별하기 위한 가설**이다. 사람의 재미·출시 적정성을 보장하는 통과선으로 표현하지 않는다.

- 최종 후보의 1,500배치 관측 중단 비율은 우선 10~40%를 목표로 본다. 50% 이상이거나 기준선 이상이면 후반 정체가 남았다는 경고다.
- 새 판에서 12병 실제 해금이 20% 미만이면 성장 접근성이 부족할 가능성을, 80% 이상이면서 대부분 오래 생존하면 보상이 과도할 가능성을 표시한다.
- 새 색 해금 후 50배치 이내의 실제 종료 비율이 30% 이상이면 급격한 난도 상승을 점검한다. 해당 해금에 도달한 판을 분모로 사용한다.
- 12병 해금 뒤 생존 배치 중앙값은 우선 100~500회를 참고하되 관측 중단이 많으면 실제 중앙값을 알 수 없다고 보고한다. 작은 표본으로 값을 확정하지 않는다.
- 병 지급 직후의 빈칸 증가가 실제 여유 회복으로 이어지는지, 그 뒤 압박이 회복되는지 확인한다. 색 수/병 수의 비율 하나로 난도를 판정하지 않는다.

후보 선택은 이 지표들을 함께 사용한다. 수치가 모두 맞지 않더라도 결과를 감추거나 검사를 느슨하게 하지 말고, 회귀가 안전한 후보 중 선택한 이유와 충족하지 못한 기준을 남긴다. 모든 후보가 명백히 부적절하면 가장 유망한 구현을 실험 후보로 보존하고 **출시 밸런스가 성립하지 않았음**을 명확히 보고한다. 이 경우에도 구현·비교·허용 범위 조정·기능 검증까지 완료하고, 결과가 좋지 않다는 이유로 초기에 작업을 멈추지 않는다.

다음 원자료와 분모를 보존한다.

- 10,000/12,000/18,000/30,000점과 각 새 성장 기준의 도달 판 수, 실제 색/병 해금 턴·점수.
- 각 해금 뒤 관측 배치 수, 50배치 이내 종료, 관측 한도까지 생존 여부.
- 점수 구간과 실제 색·병 단계별 평균 빈칸, 현재 조각을 즉시 배치할 수 있는 병 수, 순수 병/색 분산, HOLD 사용·구제, 목표 성공/종료와 보너스.
- 성공 배치뿐 아니라 색/병 해금 행동 직전·직후, 이후 10/50/100배치의 변화를 가능한 판에서 기록.
- 실제 엔진 종료, 봇 탐색 포기, `unknown`, 관측 중단을 구분. 도달하지 못한 판을 후반 평균에 0으로 넣지 않음.
- 구간의 표본 판 수·배치 수와 판별 평균도 제시. 배치 가중 평균만으로 오래 생존한 판이 전체 경험을 대표한다고 설명하지 않음.

어떤 후보에서 마지막 성장 도달 판이 20개 미만이면 조건부 보조 비교를 할 수 있다. 작업 전 기준선에서 **30,000점 경계 직전 마지막 유효 상태**를 얻은 고정 시드의 모든 체크포인트를 보존하고, 같은 상태에 비교 정책을 설치하여 실제 합법 행동으로 후반을 진행한다. 시작 보드·점수·공개 큐·HOLD를 임의로 채우거나 고득점으로 바꾸지 않는다. 정책 설치 전후 유효성·물량·큐 보존을 확인한다.

보조 비교는 후보 선택 후 기준선/최종 후보만, 가능한 체크포인트 최대 40개씩, 추가 성공 배치 1,000회 한도로 한 번 실행한다. 새 판 도달률과 조건부 생존을 섞지 않는다. 이 비교에서도 마지막 성장 표본이 적으면 부족한 그대로 보고한다. 강제 13색·12병 UI/성능 상태는 기능 검사 자료이며 밸런스 플레이 자료가 아니다.

## 8 엔진과 실제 브라우저 검증

의미 있는 행동 계약을 검사한다. 구현식을 그대로 반복하는 검사나 테스트 허용 오차 확대를 피한다.

1. 최종 각 성장 기준의 직전/정확히/직후, 배치·붓기·목표 보너스·점수 도약·실패·종료 입력. 새 병이 같은 행동의 패배를 방지하는 경계 포함.
2. 새 색 소개 한 번 예약, 공개 큐·HOLD 유지, generation 단위와 비활성 색 생성 금지. 새 3색의 생성 범위·물량 분포도 확인.
3. 모든 이전 표준의 정제·서명·실행 동치. 새 표준은 30,000점 이전 실제 동일 행동·보드·큐·목표·점수·일반/3칸 생성열 동치.
4. 활성 목표가 모든 성장 경계를 넘어 유지. 색 인덱스 10/11/12의 공개 물량 증명을 실제 행동으로 재생. 미래 병 없이 가능한 증명만 반환.
5. 병 인덱스 9/10/11의 배치·붓기·뒤집기·HOLD·완성·콤보·막힘 판정. 탐색 부족을 실제 패배로 잘못 확정하지 않음.
6. 경계 전후 저장·재로드·되돌리기·다음 행동 동치, 손상 복구, 이전 이어하기/커스텀/일일 도전/별 자격/기록 보존과 다음 새 판 갱신.
7. 모바일 360×640·390×724와 데스크톱 1280×900에서 6~12병을 측정. 같은 화면·트레이 조건의 작업 전후 유리 높이·물 층·터치 너비·기존 병 위치를 직접 비교. 터치 너비 44px 이상, 페이지 스크롤·클리핑·병/배너/콤보/조작 겹침 없음.
8. 9언어, 상하 트레이, 두 조작 방식, 4스킨과 다크/라이트, 기본/강화/모션 줄이기의 대표 성장·목표·붓기·클리어. 실제 CDP 터치/마우스로 마지막 세 병을 사용하고 저장·재시작·연속 입력 확인.
9. 새 전체 보드에서 긴 번역·큰 점수·목표 시작/실패/완료·게임 종료·위험 상태와 안전 여백·글꼴 로드/폴백을 확인. 실제 레이아웃과 색 기호를 캡처하여 눈으로 검사.

기존 v2·확장·HOLD/3칸·압박·색상 목표·컴팩트 HUD·모바일·다국어·실제 입력·프레젠테이션 검사를 필요한 범위로 실행한다. 과거 출력은 별도 출력 또는 기존 백업/복원 래퍼로 보존한다.

기존 전체 모션 검사에는 작업 전후 동일했던 12개 실패가 있다. 새 기준선으로 다시 확인하고 **새 실패와 기존 실패를 이름·원인으로 구분**한다. 이번에 수정하는 공통 연출 배치와 직접 관련된 문제라면 함께 해결하고 재검증한다. 검사나 증거를 삭제하여 전부 통과했다고 만들지 않는다.

## 9 성능과 최종 증거

같은 환경·시드·입력 절차에서 작업 전 10색·9병과 최종 11색·10병/12색·11병/13색·12병을 비교한다. 기존 6회 예열, 붓기 40·배치 10·큰 콤보 5 입력 절차를 재사용하고 기본/강화 및 1배/4배 CPU 조건에서 p50/p90/최대·유효 입력 수·50ms 이상 긴 작업·JS 오류·최대 효과 노드를 기록한다. 성능 측정 중 다른 봇 비교나 UI 검사를 병렬 실행하지 않는다.

목표 탐색은 작업 전/후 각각 30회 예열·400개 유효 강제 상태로 별도 측정한다. 기존 768개 탐색·빔 12·깊이 20 상한을 유지하며 반환 경로는 실제 행동으로 재생한다. 12병에서 비용이나 목표 제안 누락이 늘면 탐색·렌더의 중복 작업을 먼저 줄인다. 목표를 더 자주 찾기 위해 매 프레임 탐색하거나 상한을 크게 늘리지 않는다. 후보 선택에 영향을 주는 탐색 알고리즘을 바꿨다면 서명·동치·최종 비교도 다시 확인한다.

구현/검증/튜닝/최종 선택은 `research/full-board/REPORT.md`, 원자료는 `research/full-board/out/`, 화면·입력·스냅샷은 `outputs/full-board/`에 보존한다. 최종 보고서는 다음 내용을 포함한다.

- 최종 성장표·색/병 상한·압박표, 최초 후보에서 바꾼 값과 관측 근거.
- 탐색·최종·독립 시드·조건부 비교를 구분한 표, 표본·관측 중단·종료 이유·남은 난도 문제.
- 정책 버전·새 판 적용·이전 이어하기·기록/별 보존, 최종 12병 화면·색·연출과 실제 입력 결과.
- 통과·새 실패·기존 실패, 성능 수치와 실제 기기/사람 검증의 경계.
- 실제 실행한 소스·엔진·봇·검사·설정 해시, 규칙·서명·시드·원시 관측·명령/종료 코드. 최종 제품 규칙과 검증 규칙의 일치.

최종 소스로 빌드한 후 브라우저 제공 파일의 실제 바이트와 빌드가 일치하는지 확인한다. 엔진이나 선택 규칙을 수정했으면 영향을 받는 비교·검증을 다시 실행한다. 중간 후보 자료를 최종 후보의 통과 증거로 사용하지 않는다.

일반 플레이와 주요 성장/12병 체험의 로컬 주소를 제공한다. 강제 상태 체험은 별도 저장 출처 또는 메모리 기록으로 만들어 실제 플레이 기록을 오염시키지 않는다. 배포 여부를 명시한다.

**기능 구현 완료, 자동 난도 선별 결과, 사람의 재미·재도전 검증은 서로 다른 결론이다.** 병이 12개가 됐거나 봇 종료율이 높아졌다는 이유만으로 더 재미있고 출시 밸런스가 적정하다고 보고하지 마라.
