## 4. 병과 물의 재질

### 4.1 유리

- 병 입구는 안쪽 구멍과 가장자리의 두께가 느껴지도록 빛과 음영을 분리한다. 좌우 모서리, 둥근 바닥, 바닥의 두께를 같은 광원 방향으로 표현한다.
- 얇은 주 반사광과 보조 반사, 안쪽 음영, 작은 접지 그림자를 조합해 평면적인 윤곽을 개선한다. 어두운 화면에서도 빈 병의 형태와 바닥이 읽혀야 한다.
- 전체 병의 강한 흰색 발광은 피하고, 액체 색이 가장 눈에 들어오도록 밝기를 조절한다. 반사와 그림자는 실제 버튼의 크기·좌표·레이아웃을 바꾸지 않아야 한다.
- CSS 그라디언트·가상 요소·기존 변수로 구현하는 것을 우선한다. 가상 요소가 기포·눈금에 이미 쓰이고 있으므로 기존 역할과 겹치는지 확인한다.
- 선택, 배치 가능, 드래그 대상, 거절, 위험, 유령 층이 새 반사·그림자 위에서도 구별되어야 한다. 새로운 `box-shadow`가 기존 상태 표시를 덮어쓰지 않도록 조합한다.

### 4.2 액체

- 액체에 측면의 깊이, 윗면의 얕은 곡면과 반사를 더한다. 실제 최상단 수면과 내부 색 경계를 구별해 모든 칸이 각각 떠 있는 젤리 조각처럼 보이지 않도록 한다.
- 같은 색이 연속된 영역은 하나의 액체처럼 이어지게 표현하면서, 눈금·경계·기호를 통해 점유 칸 수를 읽을 수 있게 한다.
- 반사와 그라디언트는 기존 색상 간의 차이를 줄이지 않아야 한다. 특히 노란색·밝은 색의 기호 대비와 어두운 테마의 진한 색 구분을 확인한다.
- 빈 병·부분 채움·네 칸 완성, 단색·서로 다른 색, 미리보기·떠나는 층을 각각 확인한다. 장식 액체가 실제 점유 칸으로 오인되지 않게 한다.
- 현재/다음 조각, HOLD와 작은 미리보기에도 같은 재질 언어를 적용한다. 작은 병은 반사를 간소화하고 크기와 내용의 판독성을 유지한다.
- 평상시에는 정적인 재질을 중심으로 한다. 계속 흔들리는 수면이나 모든 병의 상시 입자 효과를 추가하지 않는다.

## 5. 붓기와 착지

- 붓기는 출발 액체의 이동 → 짧게 이어지는 색상 물줄기 → 도착 수면의 퍼짐 → 잔물결의 감쇠로 연결한다. 출발과 도착 지점이 실제 병 입구·수면과 맞아야 한다.
- 이동 색과 양은 실제 행동과 맞춘다. 두 칸·세 칸 조각, 서로 다른 색의 조각도 순서와 구분을 보존한다.
- 기존 복제본과 효과 레이어를 활용해 출발 병의 작은 기울기와 착지 반응을 만든다. 실제 병 버튼과 드래그 판정 좌표는 고정한다.
- 조각 배치는 붓기와 구별되는 짧은 착지 압축과 반동을 주고, 도착 수면이 작게 흔들린 뒤 가라앉게 한다. 과한 탄성으로 여러 번 튀지 않게 한다.
- 수면 반응은 주로 최상단에서 일어나고 아래 색층과 기호가 함께 일그러지지 않게 한다.
- 같은 병에 다음 행동이 들어오면 최신 상태에 맞춰 직전 효과를 마무리하거나 이어 간다. 이전 효과가 나중에 살아 있는 병의 액체를 덮어쓰지 않아야 한다.

## 6. 병 정리의 대표 연출

**액체의 색이 잠깐 모임 → 수면과 병 윤곽의 짧은 반짝임 → 색상 물보라와 얇은 파동 → 점수 회수와 빈 병 복귀**를 일관된 한 장면으로 만든다. 재사용되는 병은 형태를 유지한다.

- 응축은 완성한 액체의 스냅샷에 적용한다. 실제 점수 처리와 빈 병 사용 가능 시점을 연출 때문에 늦추지 않는다.
- 물보라는 방향성 있는 큰 방울 소수, 작은 방울, 짧은 액체 꼬리로 구성한다. 형태·궤적·속도·소멸을 다듬고 기존 입자 수를 무작정 늘리지 않는다.
- 흰색 섬광은 짧고 국소적으로 사용한다. 완성한 색이 장면의 중심이어야 한다. 화면 전체의 반복 섬광은 사용하지 않는다.
- 파동은 병 위치와 접지면을 기준으로 얇고 선명하게 퍼지게 한다. 주변 병의 액체·현재 조각·HUD를 긴 시간 가리지 않게 한다.
- 빈 병은 다음 입력을 즉시 받을 수 있어야 한다. 완료 스냅샷은 장식임이 분명하게 사라지고, 빠른 재사용 시 새 액체를 가리지 않게 조정한다.
- 동시에 여러 병이 정리되면 각각의 색과 위치에서 반응하고, 콤보 문구와 주요 사운드는 하나의 보상 흐름으로 합친다.
- 점수 비행과 카운트업은 실제 최종 점수에 도달해야 한다. 큰 숫자 맞춤, 빠른 추가 점수, 되돌리기 후 값도 유지한다.

### 강도와 시간의 초기 튜닝 기준

아래 시간은 시각 효과를 다듬는 출발점이다. 상태 처리·입력에 대기 시간을 넣지 않는다. 현재 장면과 비교해 더 자연스러운 값으로 조정하고 실제 사용한 값을 보고한다.

| 사건 | 강조 | 초기 시간 범위 |
|---|---|---|
| 선택·누름 | 작은 밝기/반사 변화와 즉각적인 선택 표시 | 60~100ms |
| 붓기·조각 착지 | 이동과 착지 연결, 감쇠하는 수면 | 주요 동작 160~280ms, 잔물결 약 400ms 이내 |

기존 콤보 문구의 단계와 번역을 재사용한다. 위 구간은 시각 강도 구분이며 엔진 콤보 규칙을 바꾸라는 의미가 아니다. 고콤보와 성장이 겹치면 문구·빛·소리가 경쟁하지 않게 기존 우선순위를 다듬는다. 매우 큰 콤보에도 비용과 흔들림이 계속 증가하지 않게 한다.

## 7. 사운드·효과 줄이기·정리 정책

- 붓기에는 짧은 유체음, 착지에는 가벼운 물방울음, 정리에는 응축에서 해방되는 음색을 연결한다. 시각적 착지·타격과 소리의 시작 시점을 맞춘다.
- 기존 SND·chime·Web Audio 생성/정리 경로와 컴프레서를 재사용한다. 콤보 상승은 음색·음높이로 표현하고 출력 음량을 계속 키우지 않는다.
- 동시 정리와 빠른 연속 입력에서 소리가 과도하게 쌓이지 않게 한다. 음소거·탭 숨김·새 게임·설정 변경 시 예약된 소리의 취소와 복귀를 확인한다. 첫 실제 사용자 입력 후 오디오 활성화 정책을 유지한다.
- 모든 장식 요소는 `pointer-events: none`과 적절한 접근성 숨김을 적용한다. 새 타이머·애니메이션·노드는 기존 관리 흐름에 등록한다.
- 되돌리기·재시작·모드 변경·시트 열기·언어/스킨 변경·리사이즈·탭 숨김/복귀에서 유령 액체·오래된 좌표·입자·소리가 남지 않아야 한다.
- 빠른 다음 수에 의한 일반 렌더링과 사용자의 초기화는 구별한다. 정상적인 직전 성공의 잔향을 무조건 없애거나 폐기한 수의 효과를 계속 남기지 않는다.
- 게임의 효과 줄이기와 OS `prefers-reduced-motion`을 각각 확인한다. 줄이기에서는 비행·물보라·흔들림을 생략하고 선택·착지·정리·점수는 짧고 선명하게 표시한다. 정적인 유리 재질은 유지할 수 있다.

## 8. 성능 예산

- 작성 시 `FX_NODE_LIMIT=180`, `FX_PARTICLE_LIMIT=96`이다. 이번 작업은 이 상한 안에서 품질을 높인다. 새 하위 요소도 노드 비용에 포함한다.
- `transform`·`opacity` 중심으로 움직인다. 큰 영역의 blur/filter 애니메이션과 반복적인 레이아웃 읽기/쓰기 교차를 피한다. 작은 요소에도 상시 `will-change`를 남기지 않는다.
- 일반/CPU 4배 감속에서 동일한 시나리오로 입력 처리 p50/p90/max, long task, 최대 효과 노드와 정리 후 잔존 노드를 비교한다. 반복 측정으로 확인한 p90의 지속적인 20% 초과 악화는 원인을 수정하고 재검증한다. 절대 밀리초 값과 측정 편차도 함께 남긴다.
- 8병·높은 콤보·동시 정리·빠른 다음 입력을 최악 조건으로 포함한다. 여러 차례 초기화 후 노드·타이머가 누적되지 않는지 확인한다.
- 기존 headless 측정의 입력 처리 시간은 실제 휴대폰 FPS와 다른 증거다. 기기에서 측정하지 않았다면 60fps·실기기 음질·진동 검증 완료로 보고하지 않는다.

## 9. 검증과 완료 기준

1. **기준선:** 현재 Git 상태, 엔진 해시, 빌드, 병 크기/좌표, 대표 연출과 성능을 남긴다.
2. **기본 장면:** lab의 정지 재질 → 붓기/착지 → 단일 정리를 순서대로 완성하고 실제 재생을 확인해 조정한다.
3. **통합:** 콤보/동시 정리/점수/사운드와 연결하고 네 스킨·두 테마·조작 방식·트레이 방향을 확인한다.
4. **회귀:** 빠른 입력, 정리 정책, 효과 줄이기, 다국어, 병 높이, 성능과 엔진 동일성을 검증한다.
5. **보고:** 수정한 소스와 재현 가능한 증거를 남기고, 로컬 미리보기를 제공한다.

기존 검증 도구를 재사용한다. 아래 명령은 현재 존재하는 대표 검사이며 실제 테스트 코드를 읽고 관련 검증을 실행한다. 포트/Chrome 프로필을 공유하는 브라우저 검사는 순차 실행한다.

```powershell
node build-pages.js

```

고정 출력 경로를 쓰는 기존 검사는 변경 전 결과를 보존하고, 이번 결과를 별도 폴더에 복사한다. 기존 추적 결과를 새 측정으로 덮어쓴 상태로 남기지 않는다. 테스트 실패는 기준선 결함과 새 회귀를 구별한다. 테스트 삭제나 의미 없는 허용 범위 확대로 통과시키지 않는다. 새 검사는 빠른 재사용·취소·레이어 식별 등 이번 변화의 실질적인 위험에 한정한다.

추가 플레이 확인은 다음을 포함한다.

- 360×640, 360×600/위아래 안전 여백 24px, 390×724/위 47px·아래 34px, 390×844, 412×915, 태블릿에서 6/7/8병. 병 크기는 변경 전과 같고 가로·세로 스크롤, 잘림, 버튼 겹침이 없어야 한다.
- 두 트레이 방향, 기본 무한 모드·오늘의 도전·대표 커스텀 용량, HOLD 저장/교환과 3칸 배치. 테마와 긴 번역도 확인한다.
- 효과가 끝나기 전에 다음 수를 입력하고, 같은 병을 즉시 다시 사용한다. 빠른 입력 간격 20/50/80ms에서는 상태·점수·잔존 효과를 확인하고 실제 Chrome 입력 재생도 별도로 수행한다.
- 동일한 행동 시퀀스의 최종 엔진 상태가 효과 켬/줄이기에서 같아야 한다. 리플레이 시드·행동과 결과를 남긴다.
- 단일 정리, 연속 정리, 동시 정리, 3/5 이상 콤보, 성장과 정리 동시 발생. 실제 색과 위치, 문구·사운드의 중복을 확인한다.
- 연출 중 되돌리기·새 게임·모드 전환·시트 열기·언어/스킨 변경·리사이즈·탭 숨김/복귀. 이전 액체·소리·점수가 새 상태를 덮어쓰지 않아야 한다.
- 외부 폰트 실패와 색상 기호 사용, 효과 줄이기/OS 동작 줄이기. 실제 액체와 장식의 식별성을 확인한다.

최종 정지 스크린샷만으로 애니메이션을 검증하지 않는다. 브라우저에서 출발·착지·응축·타격·잔향을 시간 순서로 확인하고, 대표 장면의 연속 프레임이나 짧은 재생 자료를 남긴다. 가능하면 같은 상태·화면 크기의 전후 장면을 비교한다.
