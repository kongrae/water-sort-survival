## 4. 반드시 막아야 할 기존 기능의 회귀

현재 코드에는 단순히 성장표와 상한을 올리면 다른 기능까지 바뀌는 연결이 있다. 아래 항목을 실제 함수에서 확인하고 수정한다.

### A. 9색 구간의 일반 조각 비율

현재 `generatePiece()`의 후반 1·2칸 비율 조건은 `g.activeColors >= r.maxColors`다. 새 규칙의 최대 색을 10으로 바꾸면 9색 구간이 기존 1칸 10%·2칸 90%에서 다른 비율로 돌아갈 수 있다.

새 규칙에서도 **기존 9색 해금부터 적용되던 일반 생성 정책을 그대로 유지**한다. 실제 9색 활성 조건을 사용하고 새 색상 상한과 이 정책의 시작 조건을 분리한다. 과거 규칙의 조건·조각열은 바꾸지 않는다. 이미 공개된 큐도 유지한다.

### B. 색상 도전이 18,000점까지 미뤄지는 문제

현재 `colorChallengePlan()`과 `updateColorChallenge()`는 `nextGrowth(S)`가 있으면 목표를 시작하지 않는다. 성장표만 연장하면 10,000점 색상 도전이 마지막 확장까지 막힌다. HUD도 목표 안내를 `!nextGrowth` 아래에서 표시한다.

새 규칙은 **기존 기본 확장인 실제 9색·8병을 마친 뒤 10,000점부터** 색상 도전을 계속 제공해야 한다. 미래의 12,000/18,000점 확장이 남아 있다는 이유로 목표를 막거나 숨기지 않는다. 기본 확장 준비 여부와 후반 성장 대기를 구분한다. 과거 규칙의 동작은 유지한다.

- 지정 색 먼저 완성, 성공 배치 12회, 5,000점 간격, 병당 150점·최대 300점, 미달성 시 보너스 목표만 종료하는 규칙을 유지한다.
- 진행 중 목표는 새 색·병이 열려도 초기화하거나 제한을 연장하지 않는다. 성장 자체를 목표 달성으로 처리하지 않는다.
- 목표 증명은 실제로 공개된 보드·조각·미리보기·홀드만 사용한다. 아직 받지 않은 9번째 병이나 미공개 미래 물량이 있어야 가능한 경로를 달성 증거로 삼지 않는다.
- 10번째 색도 보드·공개 물량이 충분하면 정상적인 목표 후보가 될 수 있다. 기존 제한 탐색 예산을 무작정 늘리지 않는다.

### C. 9번째 병과 연출 좌표

현재 확장 보드는 아래 6병, 위 가운데 2병이다. 추가 병의 열을 정하는 코드가 8병까지만 구분하여 9번째 병이 기존 병과 같은 칸에 겹칠 수 있다. 윗줄 좌우 여백에는 콤보·배너 연출이 있다.

9병의 슬롯을 명시적으로 정하고 병·배너·콤보·클리어·붓기 좌표가 겹치지 않게 한다. DOM 인덱스와 실제 엔진 병 인덱스의 대응은 유지한다. 화면 밖에서 붓거나 엉뚱한 병에 착지하는 연출도 확인한다.

- 정제·저장 검증에서 색 인덱스 0~9, 병 개수, 성장표의 점수·색·병 단조성, 범위·중복·손상된 버전을 확인한다. 잘못된 저장은 기존 복구 보호 경로를 따른다.

- 이미 진행 중인 게임은 저장된 규칙으로 이어간다. 최고 기록·별·통계·클라우드 키를 삭제하거나 기존 기록을 새 난도에 소급 적용하지 않는다. 이전 표준의 별 지급 자격도 유지한다.
- 일반·3칸 난수 스트림과 generation 단위를 유지한다. 새 정책 메타데이터를 제외하면 12,000점 이전의 동일 시드·동일 행동 결과가 기준선과 같아야 한다. 이후 변경은 실제 새 색/병 해금으로 설명할 수 있어야 한다.

2. 새 색 소개 예약의 단일 지급, 현재/공개 큐/홀드 유지, generation 단일 증가, 비활성 색 생성 금지.
3. 기준선의 기존 규칙·서명·동일 행동 동치. 새 표준도 12,000점 전의 실제 9색 구간까지 조각 비율·큐·점수·보드·목표 동치를 확인한다.
4. 마지막 확장이 남은 10,000점에서도 기존 색상 목표가 시작·표시되는지, 활성 목표가 성장 경계를 넘어 유지되는지, 10번째 색의 증명 경로가 실제 행동으로 재생되는지 확인한다.
5. 병 추가가 같은 행동의 패배를 방지하는 경계, 9번째 병의 배치·붓기·뒤집기·홀드·완성·콤보·막힘 판정.
6. 경계 전후 저장/재로드·되돌리기·다음 행동 재생, 규칙 정제/직렬화, 손상된 신규 상태 복구, 새 판 갱신/이전 이어하기/명시적 커스텀·일일 도전 보존.
7. 모바일 360×640·390×724 및 데스크톱에서 6/7/8/9병을 측정한다. 같은 화면 조건의 수정 전후 병 높이와 터치 영역을 직접 비교하고 문서 스크롤·클리핑·겹침을 검사한다.
8. 9개 언어·상하 트레이·두 조작 방식·4스킨·모션 줄이기/기본/강화 연출에서 대표 성장·목표·붓기·착지·클리어를 재생한다. 실제 터치/마우스로 9번째 병을 사용하고 연속 입력·저장/재시작도 확인한다.

기존 대표 검증은 `node build-pages.js`, `node test-v2.js`, `node research/expansion/engine-test.js`, `node research/hold-triple/engine-test.js`와 관련 후반 압박·색상 목표·UI 테스트다. 실제 경로와 인자를 먼저 읽고 필요한 회귀를 실행한다. 이번 엔진 변경은 과거 작업의 고정 소스 해시 검증과 구분하며 옛 증거 검증을 삭제하거나 성공하도록 바꾸지 않는다.

현재 테스트가 새 기본 상한을 전제로 잘못된 고정 상태를 구성한다면 기존 규칙을 명시하거나 새 상태를 올바르게 구성한다. 행동 계약을 삭제해 통과시키지 않는다. 과거 출력 파일을 새 결과로 덮어쓰지 않도록 별도 출력·백업 복원 절차를 사용한다.

## 8. 제한된 밸런스 비교와 성능

`research/late-expansion/`에 기존 봇·비교 구조를 재사용한 별도 도구와 보고서를 만든다.

| 비교 조건 | 12,000점 | 18,000점 |
|---|---|---|
| 기준선 | 기존 9색·8병 유지 | 기존 유지 |
| 색 추가만 | 10색·8병 | 병 추가 없음 |
| 전체 후보 | 10색·8병 | 10색·9병 |

- 세 조건의 압박 곡선·홀드·색상 목표·점수·일반 생성 비율·봇 판단 정책은 동일하게 유지한다. 조건별 마지막 성장점 차이 때문에 목표가 늦게 시작하거나 목표 탐색이 숨겨지지 않게 한다.
- 새 고정 시드 접두사 `late-expansion-20261011-`로 조건당 40개, 기존 2회 붓기 탐색 정책, 판당 성공 배치 1,500회 한도로 **120판**을 비교한다. 과거 JSON은 현재 비교 결과로 재사용하지 않는다.
- 10,000/12,000/18,000/25,000점 도달, 실제 해금 턴, 각 해금 이후 생존 배치, 12,000~17,999/18,000~24,999/25,000 이상 구간의 빈칸·배치 가능한 병·홀드 사용·목표 달성률을 보고한다.
- 색 추가만과 전체 후보를 분리해 병 추가 이후 쉬워지는 정도를 확인한다. 색·병 비율만으로 난도를 확정하지 않는다. 구간에 도달하지 못한 판을 0으로 넣어 후반 평균을 만들지 않는다.
- 제한까지 생존한 판은 관측 중단으로 표시한다. 봇 탐색 포기와 실제 합법 공간 없음도 구분한다. 같은 시드라도 행동·점수·generation이 달라지면 조각열이 달라지므로 순수 인과 효과로 단정하지 않는다.
- 18,000점 도달 표본이 조건당 20개 미만이면, 사전에 정한 기준선 시드에서 얻은 실제 유효 체크포인트를 모두 사용한 보조 비교를 할 수 있다. 임의로 유리한 상태를 골라내지 않고 조건부 비교라는 점을 표시한다.
- 결과가 너무 쉬워지거나 대부분 관측 제한까지 버티면 밸런스가 개선됐다고 결론 내리지 않는다. 추가 매개변수 탐색으로 작업을 계속 늘리지 말고 최종 후보와 한계·다음 조정 근거를 보고한다. 이번 작업에서 압박 확률·보상·병 용량까지 함께 바꾸지 않는다.
- 같은 환경·절차에서 기준선 9색·8병과 신규 10색·9병의 대표 입력·목표 탐색·강화 연출 비용을 비교한다. p50/p90/최대, 표본 수, 긴 작업, 오류·효과 노드 수를 남긴다. 탐색 상한을 늘리거나 매 프레임 탐색해서 목표 실패를 숨기지 않는다.
- 브라우저 에뮬레이션·강제 상태·자동 봇 자료와 실제 휴대폰·사람의 재미/재도전 검증을 분리해 보고한다. 실제 기기를 확인하지 않고 모바일 FPS·사운드 체감을 보장하지 않는다.

## 9. 산출물과 완료 기준

- 실제 엔진·규칙·병 배치·연출 좌표·10번째 색·HUD·9개 언어 변경과 집중 테스트.
- `research/late-expansion/REPORT.md`: 최종 성장표, 기존 연결 문제의 해결, 저장/기록 호환성, 세 조건 비교, 성능과 증거의 한계.
- `research/late-expansion/out/`: 새 검증·밸런스 원자료와 실행 당시 소스/엔진/봇/검사 해시, 규칙·서명·시드·표본·종료 이유.
- `outputs/late-expansion/`: 비교 화면, 실제 입력·연출 증거, 필요한 작업 전 스냅샷. 기존 Git 제외 관례를 따른다.
- 최종 빌드·브라우저 제공 파일·검증에 사용한 소스가 일치하는지 확인한다. 수정 전·중간 실험 결과를 최종 파일의 통과 증거로 사용하지 않는다.

최종 응답에는 실제 성장 기준, 새 판 적용/기존 이어하기와 기록 처리, 통과·실패·기존 실패 구분, 색 추가와 병 추가의 비교 결과, 병 높이·겹침·색 표현·실제 입력 확인, 로컬 접속 주소와 배포 여부를 포함한다.

‘병이 늘었으니 더 재미있다’, ‘빌드가 됐으니 밸런스가 적정하다’, ‘자동 검증으로 출시 준비가 끝났다’고 보고하지 않는다. **10색·9병 구현과 회귀 검증의 완료**, **밸런스 비교에서 관측한 사실**, **사람 검증이 남은 부분**을 각각 명확히 밝힌다.
