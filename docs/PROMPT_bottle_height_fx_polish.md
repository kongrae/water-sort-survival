# 보트리스 병 높이 복원 및 이펙트 강화 구현 프롬프트

작성: 2026-10-09. 대상: C:/workspace/water-sort-survival.

이 문서를 읽고 실제 구현, 빌드, 회귀 검증, 브라우저 시각 확인까지 진행해라. 제안이나 계획만 작성하고 끝내지 마라.

이번 목표는 **두 줄 배치에서도 물병을 시원하게 크게 보이게 하고, 빠른 물 정렬과 연속 완성이 눈·귀·손에 확실히 느껴지게 만드는 것**이다. 단순한 화면에 장식을 계속 붙이는 방식보다, 플레이어의 행동에 반응하는 액체 움직임과 성공 연출에 집중해라. 특히 병 완성, 고콤보, 새 병 등장에 충분한 연출 공수를 써라.

## 3. 병 배치와 높이: 두 줄 유지, 여유가 있으면 원래 크기

### 확인된 원인

현재 확장형 .rack.expanding은 기본 액체 칸 높이를 30px에서 24px로 줄이고, 짧은 화면에서는 20px·17px로 더 줄인다. 또한 고정 행 높이와 .glass의 flex 축소가 실제 유리 영역을 추가로 압축한다. 따라서 --lh만 30px로 바꾸는 수정으로는 충분하지 않다.

문서 작성 전 동일한 8병 화면으로 측정한 참고값은 다음과 같다. 실제 실행 시 재측정해라.

| CSS 뷰포트 | 현재 유리 높이 | 두 줄에서 원래 높이 복원 | 한 줄 8병의 너비 |
|---|---:|---|---:|
| 390×844 | 약 103px | 136px, 화면 안에 들어감 | 약 38px |
| 360×740 | 약 87px | 136px 고정 시 하단 넘침 | 약 34px |
| 360×640 | 약 75px | 136px 고정 시 하단 넘침 | 약 34px |

이는 임시 브라우저 비교 결과이며 실제 휴대폰 검증은 아니다. outputs/rack-size/comparison.png와 geometry.json이 남아 있으면 참고할 수 있지만, 해당 폴더는 Git에서 제외되므로 없어도 작업을 계속한다.

### 구현 요구사항

1. **두 줄 배치를 유지한다.** 한 줄에 8개를 몰아넣거나 가로 스크롤을 도입하지 않는다.
2. 표준 4칸 병은 공간이 충분할 때 기존 --lh: 30px 수준을 복원한다. 유리의 실제 getBoundingClientRect 높이 약 136px를 기준으로 삼는다. 숫자만 바꾸고 실제 병이 계속 압축된 상태를 완료로 보고하지 마라.
3. 390×844의 기본 무한모드 8병 화면은 원래 높이 복원을 목표로 한다. 360×740·360×640에서는 현재 사용 가능한 높이에 맞춰 필요한 만큼만 줄인다. 작은 화면에서 136px를 무조건 고정하지 않는다.
4. 병보다 먼저 불필요한 세로 여백과 반복 안내의 공간을 줄인다. 글자·버튼·현재 조각을 알아보기 어려울 정도로 압축해서 병 크기를 확보하지 않는다.
5. 행 높이, 병 테두리·입구, 빈칸 레이블과 내부 액체 간격을 함께 맞춰라. custom 규칙의 병 용량도 기존 의미를 유지하며 화면에 맞게 처리한다.
6. 위 줄이 비어 있는 6병 상태에서도 확장 공간을 유지한다. 같은 뷰포트에서 6 → 7 → 8병이 될 때 기존 6개 병과 조각 트레이가 이동하지 않고, 7번째 병도 8번째 등장으로 밀리지 않아야 한다.
7. 임시 비교의 grid-template-rows: auto를 그대로 복사하면 빈 위 줄이 접힐 수 있다. 실제 코드에서는 예약된 행 공간과 안정적인 좌표를 보장한다.
8. 병 조작 영역과 주요 버튼은 최소 44×44 CSS px를 유지한다. 기본 플레이 화면은 360×640에서도 가로·세로 스크롤 없이 상태와 하단 조작을 확인할 수 있어야 한다.
9. 배너·콤보·경고·폰트 로드·언어 변경으로 병 위치가 흔들리지 않게 한다. 높이를 수정한 뒤 드래그 판정, 유령 미리보기, 효과 좌표와 무대 위치도 함께 검증한다.
10. 화면 회전·리사이즈·브라우저 주소창에 따른 사용 가능 높이 변화에 대응한다. 현재 입력 취소·좌표 갱신 흐름을 활용하고 render마다 강제 레이아웃을 반복하지 않는다.

## 4. 연출 방향: 물과 유리의 일관된 손맛

이미 붓기 비행, 조각 착지, 병 완성, 콤보 콜아웃, 점수 비행, 위기 피드백, 성장 효과가 구현되어 있다. 먼저 실제 재생을 확인한 뒤 기존 fxq, #fxLayer, fxAdd/fxDrop, fxLater, fxAnim, clearFx, comboBurst, growthFx 등을 개선해라. 같은 사건을 처리하는 별도의 효과 시스템을 만들지 않는다.

**작은 행동은 즉각적이고 짧게, 완성은 충분히 시원하게, 연속 완성은 단계적으로 더 강하게** 표현한다. 물방울·수면 파동·유리 반사·점수의 흐름이 하나의 시각 언어로 이어져야 한다. 모든 행동에 동일한 폭발과 화면 흔들림을 붙이지 않는다.

다음 시간은 초기 튜닝 범위이며 게임 처리 시간을 지연시키라는 의미가 아니다. 현재 구현과 실제 재생을 비교하면서 조정한다.

| 사건 | 시각적으로 느껴져야 하는 것 | 초기 연출 범위 |
|---|---|---|
| 선택·누름 | 손에 붙는 즉각적 응답, 선택 대상의 선명함 | 60~100ms |
| 조각 넣기·물 붓기 | 출발·이동·착지의 연결과 수면 반응 | 140~280ms |
| 병 완성 | 짧은 응축 뒤 물이 터지는 해방감 | 주요 타격 350~650ms |
| 고콤보 | 완성보다 한 단계 큰 보상과 점수 상승 | 문구 700~1100ms |
| 새 병·새 색 등장 | 판이 넓어지고 다음 도전이 열린다는 느낌 | 강조 400~800ms |

### 4.1 붓기와 조각 착지

- 현재 덩어리 비행을 실제 물이 옮겨지는 느낌으로 다듬는다. 출발 병의 가벼운 기울기, 색이 이어지는 짧은 물줄기나 물방울 꼬리, 도착 병의 수면 파동을 조합한다.
- 물리 시뮬레이션을 새로 만들 필요는 없다. 기존 액체 층과 복제한 효과 요소의 transform·opacity 중심으로 자연스러운 속도 변화와 착지를 만든다.
- 이동량과 액체 색이 원래 행동과 맞아야 한다. 남은 액체가 사라지거나 유령 액체가 실제 층처럼 보이지 않게 한다.
- 조각 넣기는 붓기와 구별되는 짧은 착지 압축·반동을 준다. 현재·다음 조각의 내용 변화도 매끄럽게 연결한다.
- 컵과 병의 실제 버튼 위치·히트 영역은 고정한다. 효과가 재생 중이어도 다음 컵 선택·붓기·드래그를 즉시 처리한다.

### 4.2 병 완성: 이번 작업의 핵심

- 완성 직전의 짧은 빛 모임 → 병 안의 색이 통일되는 강조 → 물방울과 얇은 파동 → 점수 회수로 이어지는 한 장면을 만든다.
- 완성한 액체의 색이 연출의 중심이어야 한다. 무조건 흰색 번쩍임이나 색과 무관한 꽃가루로만 표현하지 않는다.
- 작은 물방울의 크기·속도·궤적을 다양하게 하고, 큰 파동은 1~2개 정도로 명확히 보이게 한다. 입자 개수보다 형태·타이밍·소멸의 품질을 높인다.
- 병 자체에는 짧은 반동이나 유리 반짝임을 줄 수 있다. 주변 병의 버튼과 판정 좌표를 움직이지 않는다.
- 동시에 여러 병을 완성하면 각 병의 위치에서 반응하고, 전체 보상은 하나의 더 강한 장면으로 묶는다. 콜아웃과 사운드를 병마다 중복 폭발시키지 않는다.
- 다음 수가 들어와 render가 일어나도 직전 완성의 잔향이 정상적으로 끝나야 한다. 현재 해결된 효과 소실 문제가 다시 생기지 않게 한다.

### 4.3 콤보와 점수: 계속 플레이하고 싶은 이유

- 낮은 콤보는 간결하게, 중간 콤보는 더 큰 파동과 선명한 콜아웃, 높은 콤보는 특별한 광채·물방울 패턴·사운드로 확실히 구분한다.
- 기존 콤보 단계와 실제 streak를 기준으로 강도를 조절한다. 시각 강도의 상한을 두어 매우 큰 콤보에서도 화면과 비용이 무한히 커지지 않게 한다.
- 숫자를 키우는 것 외에도 등장 속도, 반동, 주변 빛과 소리의 높낮이로 강도를 구분한다. 콤보 종료는 짧고 읽기 쉽게 처리한다.
- 점수 비행은 완성 위치와 점수 HUD를 연결한다. 합산값·최종 표시값이 실제 S.score와 맞고, 중복 가산·뒤늦은 롤백처럼 보이지 않아야 한다.
- 콤보 문구는 기존 무대의 사용 가능한 공간을 활용한다. 8병·짧은 화면·위쪽 트레이에서도 물 색, 현재 조각, 점수와 주요 버튼을 가리지 않는다.
- 긴 번역과 데바나가리 문자도 잘림 없이 표시한다. 충분한 공간이 없으면 문구를 줄이고 핵심 배율을 유지한다.

### 4.4 새 병·새 색·기록 갱신

- 새 병이 생기면 위 줄의 해당 위치에서 얇은 수면 파동이나 유리 윤곽이 모이고 병이 짧게 자리 잡는 느낌을 준다. 판 전체를 재배치하지 않는다.
- 새 병은 연출 시작과 동시에 사용할 수 있어야 한다. 출현 애니메이션이 히트 영역을 늦게 켜거나 실제 버튼을 이동시키지 않는다.
- 새 색은 실제 색과 이름을 짧게 보여주고 이후 조각에 도착한다는 기존 의미를 유지한다. 등장과 동시에 현재 조각을 바꾸지 않는다.
- 한 행동에 완성·콤보·성장이 겹치면 우선순위를 정해 하나의 보상 흐름으로 표현한다. 안내 문구가 서로 겹치거나 긴 대기열로 밀려 나오지 않게 한다.
- 신기록 연출은 기존 기록·결과 표시와 연결하고 한 판에서 같은 이벤트를 반복하지 않는다. 결과 화면에도 짧은 보상을 남기되 다시 도전 버튼을 즉시 사용할 수 있게 한다.

### 4.5 배경·위기·사운드

- 평상시에는 절제된 배경을 유지하되, 기존 유리 반사·기포·무대의 깊이를 다듬어 멈춘 화면도 빈 느낌이 덜하게 한다. 지속적인 고비용 입자 배경은 만들지 않는다.
- 고콤보의 열기는 물 색을 바꾸지 않는 주변 빛과 짧은 강조로 표현한다. 모든 병에 상시 발광을 붙이지 않는다.
- 위기는 가장자리와 기존 상태 표시를 중심으로 표현한다. 성공 효과와 위기 경고의 색·소리·리듬을 구별하고, 빠른 전체 화면 섬광을 반복하지 않는다.
- 기존 Web Audio 사운드에 착지·붓기·완성·성장의 차이를 더한다. 고콤보는 단계적으로 높아지되 음량은 무작정 키우지 않는다.
- 동시 효과의 중복 소리를 줄이고 기존 컴프레서·음소거·첫 사용자 입력 후 오디오 활성화 정책을 유지한다.
- 진동은 설정을 존중하고 지원 환경에서만 짧게 쓴다. 브라우저에서 호출 성공을 확인했다고 실제 휴대폰 촉각을 검증했다고 쓰지 않는다.

## 5. 빠른 입력, 정리와 성능

- 상태 변경과 입력 처리는 즉시 완료한다. 연출을 기다리는 입력 잠금, 딜레이, 별도 입력 버퍼를 도입하지 않는다.
- 빠른 연속 행동에서는 이전 비행을 현재 상태에 맞게 마무리하고 새 효과를 시작한다. 오래된 좌표와 점수 타이머가 새 상태를 덮어쓰지 않게 한다.
- 효과 요소는 pointer-events: none과 적절한 접근성 숨김을 적용한다. 실제 버튼의 transform과 시각 복제본을 구분해 판정이 어긋나지 않게 한다.
- 되돌리기·새 게임·모드 변경·사용자가 여는 시트·언어 변경·리사이즈의 정리 정책을 확인한다. 폐기된 수의 입자·유령 층·타이머·점수 비행이 남지 않게 한다. 기존 결과 화면의 마지막 완성/신기록 연출은 의도에 맞게 유지한다.
- 새 타이머와 애니메이션은 기존 관리 흐름에 등록한다. animationend에만 의존하지 말고 숨겨진 탭·프레임 중단 후에도 정상 복구한다.
- OS 동작 줄이기와 게임의 효과 줄이기를 각각 검증한다. 설정을 바꾸거나 OS 선호가 변경되는 상황도 확인하고, 줄이기 모드에서는 날아가기·입자·흔들림을 끄면서 선택·완성·점수 변화는 즉시 읽을 수 있게 한다.
- 동시에 살아 있는 입자와 효과 노드의 전역 상한을 둔다. 작성 전 측정한 현재 기준선과 강화 후 비용을 비교해 예산을 정하고 보고서에 숫자로 남긴다. 예산을 초과하면 장식 입자를 먼저 줄이고 필수 성공 피드백을 유지한다.
- transform·opacity를 중심으로 구현하고, 반복적인 레이아웃 읽기/쓰기 교차와 큰 영역의 blur·filter 애니메이션을 피한다. 추가 SVG가 필요하면 기존 코드 안에서 최소한으로 사용한다.
- 일반·4배 CPU 감속에서 기존 perf.js의 입력 처리 p50/p90/max, long task와 최대 효과 노드를 비교한다. 유의미한 악화가 있으면 원인을 수정하고 다시 확인한다.
- 효과 수를 늘린 것과 완성도를 높인 것을 구별한다. 성능이 같거나 나아도 실제 재생이 밋밋하면 완료로 보지 않는다.

## 6. 다국어와 기존 기능

- 새 사용자 문구는 기존 tr 경로와 locales/messages.tsv에 9개 언어로 반영한다. 한국어 콜아웃을 하드코딩하지 않는다.
- 번역 표는 현재 파이프 구분 형식과 자리표시자·의도된 공백을 유지한다. embed-i18n.js와 빌드로 실제 포함 여부를 확인한다.
- 언어 변경으로 판, 선택, 기록, 되돌리기 이력이 초기화되지 않게 한다.
- 액체의 기존 색 구분, 색상 기호 옵션, 유령 미리보기와 막힌 병 안내를 보존한다. 입자와 광채가 실제 액체 층처럼 보이지 않아야 한다.
- 밝은·어두운 테마와 외부 폰트 로드 실패에서도 병·레이블·효과의 대비와 위치를 확인한다.

## 7. 구현과 검증 순서

1. 현재 상태·화면·엔진 해시·성능 기준선을 기록한다.
2. 두 줄 병 높이를 수정하고 6/7/8병의 좌표·스크롤·조작 영역을 확인한다.
3. 붓기·착지 → 완성 → 콤보·점수 → 성장·신기록 순서로 기존 효과를 개선한다. 각 단계에서 실제 연속 입력으로 확인한다.
4. 줄이기 모드, 정리 정책, 다국어와 성능을 검증하고 필요하면 효과를 조정한다.
5. 회귀 검증과 브라우저 시각 확인을 완료하고 결과를 보고한다.

기존 도구를 활용하며 다음 검증을 수행한다. 실행 전 기준선 실패와 새 회귀를 분리하고, 테스트를 삭제하거나 단순히 허용 범위를 늘려 통과시키지 않는다.

```powershell
node research/uiux/baseline.js
node research/expansion/engine-test.js
node uitest/uiux.js
node uitest/expansion.js
node uitest/i18n.js
node uitest/run.js feel --motion=both
node uitest/real.js
node uitest/run.js fresh existing v1saves v1daily themes legacy cloud firebase --motion=reduce
node research/feel/perf.js
node build-pages.js
```

위 검사는 서로 다른 증거다. 기존 feel의 합성 이벤트 검증과 real.js의 실제 Chrome 입력 검증을 구분한다. 필요하면 기존 테스트에 이번 변화의 위험을 확인하는 항목만 추가한다.

### 추가로 확인할 플레이 시나리오

- 360×640, 360×740, 390×844, 412×915, 태블릿에서 6/7/8병을 확인한다. 기본 화면에서 스크롤·잘림·버튼 겹침이 없어야 한다.
- 6 → 7 → 8 확장 전후 기존 병과 조각 트레이의 좌표가 유지되는지 측정한다. 처음 위 줄에 등장한 병의 즉시 조작도 확인한다.
- 붓기 → 완성 → 다음 수를 효과 종료 전에 이어간다. 20/50/80ms 간격의 빠른 입력에서도 정상 상태와 점수, 살아 있는 효과를 확인한다.
- 연출 켬·기본·줄이기에서 같은 입력 시퀀스의 최종 엔진 상태가 같아야 한다.
- 단일 완성, 동시 다중 완성, 낮은 콤보, 높은 콤보, 콤보 종료, 성장 동시 발생을 확인한다.
- 효과 도중 되돌리기, 새 게임, 설정 열기, 언어 변경, 리사이즈, 탭 숨김/복귀 후 잘못된 액체·점수·좌표가 남지 않아야 한다.
- 반복 플레이와 초기화 후 효과 노드·타이머가 계속 쌓이지 않는지 확인한다.
- 9개 언어의 짧은 화면에서 핵심 배율·성장 안내·점수·버튼이 읽혀야 한다.
- 최종 스크린샷만으로 이펙트를 검증하지 않는다. 실제 브라우저에서 출발·타격·잔향의 시간 흐름을 확인하고 대표 장면을 여러 시점으로 남긴다.

## 8. 산출물과 완료 기준

- 실제 수정한 소스와 필요한 번역·검증 코드.
- research/fx-polish/REPORT.md에 변경 이유, 병 실제 크기, 좌표 안정성, 각 효과의 전후 차이, 검증 명령/결과, 성능 비교를 기록한다.
- outputs/fx-polish/ 아래에 개선 전후 화면과 붓기·완성·고콤보·새 병 출현의 시점별 캡처를 남긴다. 가능하면 짧은 영상도 남기되 새 의존성을 추가하지 않는다.
- 결과 보고에는 **병 크기가 얼마나 복원되었는지**, **완성/고콤보가 어떻게 더 좋아졌는지**, **다음 수가 즉시 처리되는지**를 먼저 설명한다.
- 자동 검사, 실제 브라우저 재생, CPU 감속 측정, 실제 휴대폰 확인, 공개 배포를 구분한다. headless 측정만으로 휴대폰 60fps를 보장했다고 쓰지 않는다.
- 기존 GitHub Pages 배포 도구는 유지한다. 이번 문서의 기본 완료 범위는 로컬 구현·검증이며, 실행 요청에 배포가 포함되어 있으면 기존 deploy-pages.ps1과 scripts/verify-pages.js로 공개 소스/버전을 확인한다.
- 화면만 화려해지고 병 색이나 다음 행동을 읽기 어려워지면 미완료다. 병은 크고 안정적이며, 빠르게 조작할수록 완성과 콤보의 보상이 확실히 느껴져야 한다.
