# 모바일 물정렬 게임 UI UX 개선 구현 프롬프트

작성: 2026-10-08. 대상: `C:/workspace/water-sort-survival`.
권장 모델: **GPT-6.1 Sol / Extra High (xhigh)**.

현재 구현된 점수 성장형 무한모드를 기준으로 화면 UI, UX, 폰트, 정보 배치, 안내 문구를 개선해라. 실제 코드를 수정하고 빌드, 자동 검증, 브라우저 시각 확인까지 끝내라. 분석이나 디자인 제안만 작성하고 멈추지 마라. 이번 요청은 화면과 사용성 개선이며 게임 규칙이나 밸런스 개편이 아니다.

## 1. 완성할 경험

빠르게 물을 넣고 부으며 콤보와 최고 기록에 도전하는 모바일 퍼즐이다. 플레이어가 가장 먼저 병과 현재 조각을 읽고, 그다음 점수와 다음 확장 목표를 이해할 수 있게 만들어라. 차분하고 선명한 화면 안에서 액체 색과 성공 피드백이 살아나는 방향으로 정리한다.

화려한 배경이나 많은 장식보다 읽기 쉬운 글자, 확실한 선택 상태, 안정된 병 위치, 빠른 조작을 우선한다. 무한모드가 중심이며 일일 도전은 보조 기능으로 유지한다. 기존 사용자가 새 조작을 다시 배울 필요가 없어야 한다.

## 3. 현재 확인된 문제와 수정 방향

### 3.1 정보 배치와 여백

현재 기본 화면은 점수, 성장 안내, 병 사이에 큰 간격이 있어 정보를 읽는 흐름이 끊긴다. 하단 조작을 엄지 가까이에 두는 여백과, 7번째·8번째 병을 위해 확보한 위 줄 공간은 의도된 배치다. 이 둘을 무작정 없애지 말고 불필요하게 흩어진 HUD를 묶어라.

- 상단은 작은 게임명과 모드 표시, 규칙·설정 버튼으로 정돈한다.
- 현재 점수를 중심으로 최고 기록과 콤보를 연결해 보여준다. 턴 수는 보조 정보로 낮춘다.
- 성장 정보는 짧은 한 묶음으로 보여준다. 예: `4색 · 6병`, `다음 색까지 300점`.
- 다음 병이 열리는 시점에는 병 해금 목표가 분명하게 보이게 한다. 목표 점수와 남은 점수의 의미를 혼동하지 않게 한다.
- 턴 정산 진행 막대가 점수 성장 진행 막대로 보이지 않게 한다. 정산은 보조 정보로 표시하고 막대에는 실제 의미를 붙인다. 성장 막대를 새로 쓰면 실제 점수 성장 조건만 표현한다.
- 보드와 현재 조각을 하나의 플레이 영역으로 읽히게 한다. 현재 조각과 다음 조각의 중요도를 크기와 위치로 구분하되 현재 미리보기 개수와 공개 정책은 유지한다.
- 긴 화면의 잉여 공간은 유연하게 처리하고, 짧은 화면에서는 여백과 반복 설명부터 줄인다. HUD를 재배치할 때 병·효과·상태 메시지를 겹치게 하지 않는다.
- 빈 위 줄을 여러 잠금 카드나 광고 공간으로 채우지 않는다. 짧은 확장 안내나 기존 콤보 연출이 자연스럽게 머물 공간으로 활용할 수 있다.

### 3.2 폰트와 가독성

현재 `Jua`와 `IBM Plex Sans KR`를 함께 쓰고 있으며, 성장 안내와 병 아래 빈칸 수 등 여러 보조 텍스트가 11~12px다. 폰트 이름을 바꾸는 것만으로 작업을 끝내지 말고 크기, 굵기, 행간, 대비, 숫자 정렬을 함께 정리해라.

- 한글 본문·버튼·HUD는 일관된 산세리프 계열로 통일한다. 기존 IBM Plex Sans KR를 우선 검토한다. 디자인 판단에 따라 Pretendard 같은 다른 한글 UI 폰트 한 종류로 교체할 수 있다.
- `Jua`를 유지한다면 게임명 등 제한된 위치에 사용한다. 점수, 최고점, 콤보, 결과 숫자는 읽기 쉽고 자릿수 변화가 안정적인 굵은 숫자로 정리한다.
- 크기 초안: 현재 점수 40~48px, 주요 정보와 버튼 14~16px, 보조 안내 12~13px. 성장 목표·상태 메시지는 13px 이상을 목표로 한다. 실제 화면에서 비교한 뒤 조정한다.
- 작은 글자를 낮은 대비와 얇은 굵기로 동시에 표현하지 않는다. 긴 한글 설명에 불필요한 자간을 넣지 않는다.
- 숫자는 가능한 한 tabular 숫자를 쓰고, 점수 자릿수와 콤보가 늘어도 주변 요소가 흔들리거나 잘리지 않게 한다.
- 외부 폰트 로드 전후, 로드 실패, 오프라인 폴백에서 병과 버튼 위치 및 효과 좌표가 깨지지 않게 한다.
- 폰트를 새로 가져오면 공식 배포처와 라이선스를 확인하고 필요한 굵기만 사용한다. 로컬 배포 시 `build-pages.js`가 실제 파일을 포함하게 한다. 폰트 변경을 이유로 여러 새 의존성을 추가하지 않는다.

### 3.3 버튼 중요도와 진행 보호

현재 하단에서 `오늘의 도전`이 유일한 강조 버튼이다. 무한모드 플레이 화면에서 다른 모드로 이동하는 버튼이 가장 중요한 행동처럼 보이는 문제를 고쳐라.

- 플레이 중 되돌리기는 가까운 위치에 유지하고 남은 횟수·비활성 상태를 명확하게 한다.
- 새 게임과 모드 전환은 보조 행동으로 정리한다. 플레이 중 반드시 강조 버튼이 하나 있어야 한다는 이유로 새 게임을 강하게 강조하지 않는다.
- 일일 도전은 기존 버튼을 보조 스타일로 바꾸거나 상단 모드 영역으로 옮길 수 있다. 기능을 없애거나 매번 홈 화면을 거치게 하지 않는다.
- 새 게임·모드 전환으로 진행 중인 판이 즉시 사라지는 경로를 확인한다. 필요한 경우 기존 새 게임의 두 번 확인 패턴을 재사용해 UI 수준에서 진행을 보호한다. 일반 넣기·붓기에는 확인 절차를 추가하지 않는다.
- 규칙·설정 버튼도 터치 영역은 최소 44×44 CSS px를 확보한다. 보이는 아이콘이 작아도 주변 터치 영역이 다른 버튼과 겹치면 안 된다.
- 아이콘만으로 바꿀 때는 접근 가능한 이름과 이해 가능한 표시를 제공한다. 새 아이콘 패키지보다 기존 코드 또는 간단한 SVG를 사용한다.

### 3.4 병과 조각의 상태 구분

- 빈병의 윤곽과 용량, 액체 층 경계, 선택한 병, 받을 수 있는 병을 밝은·어두운 화면 모두에서 구분할 수 있게 한다.
- 선택, 드롭 대상, 완성 예상, 거절 피드백은 서로 다른 역할로 읽혀야 한다. 동시에 겹칠 때 어느 표시가 우선인지 정리한다.
- 액체 색상과 기호의 의미는 유지한다. 색 구분을 약화시키는 광택·블러·그라데이션·그림자를 줄인다.
- `빈 2` 같은 표시는 `2칸` 등 더 짧고 명확한 표현으로 검토한다. 시각적 표시를 줄여도 병의 접근 가능한 이름에는 색과 빈칸 정보를 보존한다.
- 아래 여섯 병은 6·7·8병 상태에서 같은 위치와 크기를 유지한다. 7번째 병도 8번째 병이 추가될 때 이동하지 않는다.
- 병의 터치 폭을 줄여 글자와 버튼을 맞추지 않는다. 새 폰트와 장식 때문에 두 줄 사이 빈 공간이 드롭 대상으로 바뀌면 안 된다.

### 3.5 설정과 규칙 안내

- 설정을 `소리와 진동`, `화면과 접근성`, `조작`, `저장`처럼 사용자가 이해하는 소수의 묶음으로 정돈한다. 기존 옵션과 저장 값은 보존한다.
- 자주 쓰는 조작 방식·트레이 위치 설정은 필요하면 일반 설정으로 옮긴다. 규칙 실험, 강제 테마 체험, 개발용 통계는 기존처럼 접힌 실험 영역에 둔다.
- 매 옵션에 긴 설명을 반복하지 않는다. 중요한 차이를 짧게 설명하고 상세 정보는 필요할 때 읽을 수 있게 한다.
- 긴 설정 화면에서도 제목과 닫기를 쉽게 찾게 한다. 닫기 버튼이 내부 스크롤 끝에만 있어야 하는 배치를 피한다.
- 규칙 화면은 현재 조작 방식에 맞는 넣기, 붓기, 완성, 성장, 종료를 먼저 설명한다. 과거 버전 안내보다 현재 플레이에 필요한 정보가 먼저 나오게 한다.
- 실제 동작과 어긋나는 설명을 찾아 고친다. 특히 `optZones` 주변의 `20턴마다 새 색이 들어와요`는 점수 성장형에서는 맞지 않는다. 확장형의 턴 정산과 점수 색상 증가를 구분하고, 과거 규칙을 이어 하는 경우에는 그 규칙에 맞는 설명을 사용한다.
- 현재 트레이 위치에 맞게 `위에 나온 조각` 등의 표현을 확인한다. 콤보 유지 조건도 실제 엔진과 맞게 설명한다.
- 처음부터 여러 안내 모달을 연달아 띄우지 않는다. 기존 단계별 안내와 사용자 설정을 존중한다.

### 3.6 결과 화면과 다시 도전

- 이번 점수와 최고 기록 차이를 가장 먼저 읽게 한다. 턴, 완성 병, 최대 콤보, 별·테마는 보조 정보로 정돈한다.
- 다시 도전하는 행동을 쉽게 찾게 한다. 판 보기, 결과 복사, 테마 확인은 보조 행동으로 유지한다.
- 기존 부활·별·테마·공유 기능은 유지하고 실제 동작과 다른 안내를 만들지 않는다. 광고 자리 표시를 실제 광고 연동 완료처럼 표현하지 않는다.
- 숫자 애니메이션이나 결과 연출이 다음 행동을 기다리게 하거나 점수를 잘못 보여주면 안 된다.

## 4. 변경하지 않을 계약

- 시작 6병·4색, 900점 7병, 2,800점 8병, 최대 9색을 포함한 현재 성장표와 후반 조각 비율을 바꾸지 않는다.
- 점수, 콤보, 정산, 패배, 병 지급, 색 활성화, 확정 미리보기 큐, 시드 생성, 뒤집기 횟수 등 엔진 동작을 바꾸지 않는다.
- 작업 전후 `<script id="engine">` 내용의 해시를 비교해 엔진이 동일함을 확인한다. UI 버그를 고치는 데 필요해 보여도 규칙 변경으로 우회하지 마라.
- 기존 저장, 최고 기록 서명, 페이스, 별, 테마, 사용자 설정, 과거 규칙 복원, 일일 도전, 클라우드 저장 계약을 유지한다.
- classic과 tapPlace, 위·아래 트레이, 컵 드래그, 병 드래그, 길게 누르기, 취소, 되돌리기, 키보드, 빠른 연속 입력을 보존한다.
- 현재 소리·진동·효과 기본값과 효과 줄이기 설정을 유지한다. 연출 위치와 가독성은 조정할 수 있지만 조작을 잠그거나 재입력을 기다리게 하지 않는다.
- DOM 위치를 바꾸면 현재 `paintStage()`, 효과 좌표 계산, 폰트 완료 처리, 리사이즈 처리와 함께 확인한다. 보이는 병과 드롭 판정 좌표가 일치해야 한다.
- 스테이지 모드, 타이머, 자동 낙하, 재화, 스킬, 신규 스킨, 로그인 요구 화면, 광고 SDK를 추가하지 않는다. 공개 배포·커밋·푸시는 별도 요청 없이 진행하지 않는다.

## 5. 구현과 검증 순서

1. 현재 화면의 문제를 근거와 함께 짧게 정리하고, 실제 구현할 디자인 방향 하나를 정한다. 여러 시안만 만들고 선택을 기다리지 마라.
2. 폰트·색·간격·버튼의 최소한의 CSS 기준을 정한 다음 메인 화면부터 수정한다. 새 추상화나 디자인 시스템 프로젝트를 만들지 않는다.
3. 설정·규칙·결과·테마 화면의 공통 스타일과 안내를 맞춘다. 테마 해금 및 자산은 보존한다.
4. 정상 Pages 문서를 빌드해 브라우저에서 확인하고 발견한 잘림, 겹침, 입력 회귀를 고친다.
5. 필요한 검증만 기존 도구에 추가하고 완료 기준을 확인한다. 디자인이 바뀌었다는 이유로 입력·점수·저장 검사를 삭제하거나 약화시키지 않는다. 위치 검사 수정이 필요하면 바뀐 배치와 유지할 계약을 설명한다.

## 6. 화면별 완료 기준

- 화면 크기: `360×740`, `390×844`, `412×915`, `768×1024`. 추가로 `360×640`에서 짧은 화면 대응을 확인한다.
- 기본 6병, 7병, 8병을 모두 확인한다. 강제 상태 주입으로 확인한 화면과 실제 점수 획득으로 확장된 화면을 구분한다.
- 기본 밝은·어두운 테마와 기존 병 테마 모두에서 액체, 빈병, 선택 상태, 기호를 읽을 수 있어야 한다. 효과 축소·전체 효과를 확인한다.
- 모바일 기본 세로 화면에서 주요 플레이 영역과 하단 조작이 잘리거나 가로 스크롤이 생기면 안 된다. 설정·도움말 등 긴 시트의 내부 스크롤은 허용하되 닫기를 찾을 수 있어야 한다.
- 일반 버튼은 44×44px 이상, 병 터치 폭은 44px 이상을 목표로 확인한다. 드롭할 수 없는 행 사이 공간과 주변 장식은 입력을 가로채지 않는다.
- 다섯 자리 이상 점수, 큰 콤보, 긴 상태 메시지, 병 해금 배너에서 잘림과 겹침이 없어야 한다.
- 폰트 로드 완료·실패, 브라우저 크기 변경 후 화면과 효과 좌표가 맞아야 한다.
- 모달의 키보드 포커스, 닫기, 포커스 복귀, 비활성 상태, 접근 가능한 이름을 확인한다. 일반 텍스트 4.5:1, 큰 텍스트 3:1 대비를 목표로 실제 주요 조합을 확인한다.
- 아래 여섯 병의 위치 유지, 선택·드롭 판정, 되돌리기·새로고침 복원, 기존 진행 보존을 자동 검사와 실제 브라우저 입력으로 확인한다.
- 에뮬레이션에서 통과한 것을 실제 휴대폰 체험, 재미, 출시 품질 검증으로 보고하지 않는다.
