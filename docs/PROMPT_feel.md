# 물정렬 생존 UI/UX·손맛 개선 지시 (빨리 두고, 크게 터지는 플레이)

너는 이 HTML 프로토타입의 화면과 손맛을 개선하는 개발자다. 조작 방식은 앞선 작업(`docs/PROMPT_controls.md`, `docs/PROMPT_controls2.md`)에서 정했다. 기본값은 조작 '조각 누르고 병 누르기'(classic)와 배치 '조각 칸 아래'(bottom)다.

이번 목표는 테트리스나 블록 퍼즐처럼 **망설임 없이 빨리 두고, 병을 완성할 때 크게 터지는 손맛**이다. 할 일은 다섯 가지다.
1. 연출 기반의 결함을 고친다(5장). 모든 설정에 적용한다.
   - 빨리 두면 완성 연출이 잘린다.
   - '효과 줄이기'가 연출 일부만 끈다.
   - 누르는 순간에는 화면이 반응하지 않는다.
2. 새 손맛 F1~F9(6장)를 만든다. 설정 '연출'에서 '손맛 강화'를 고를 때만 켠다. 지금 연출은 '기본'으로 남겨, 휴대폰에서 둘을 비교한다.
3. 화면 개선 U1~U5(7장)를 한다. 버튼 구성이나 규칙에 닿는 큰 변경은 질문만 한다(7.6).
4. 플레이 테스트 기록에 템포 지표를 더한다(8장).
5. 체크포인트 D에서 사용자가 휴대폰으로 비교해 고르면, 그 안을 확정한다.

배경(5d6b55c 기준, 390x844, 헤드리스 Chrome 실측):
- 한 수의 처리는 즉시 끝나고 입력을 막는 연출도 없다. 빠른 플레이의 바탕은 이미 있다.
  - 붓기 1회(commit + render) 처리 시간은 p50 1.2ms다.
  - 4배 CPU 감속에서도 p50 5.8ms, p90 6.8ms다.
- 하지만 연출이 병 버튼 안에 붙어 있어서 다음 render가 지운다.
  - 완성 직후 80ms 안에 다음 수를 두면, 터지는 층(`.burst`)과 점수 글자(`.float`)가 1개에서 0개가 된다.
  - 빨리 둘수록 보상이 사라지는 구조다.
- 붓기와 넣기에는 이동이 없다. 받는 병의 새 층이 0.22초 동안 늘어나는 `pop`만 있고, 원천 병과 컵에서는 그냥 사라진다.
- 완성 연출은 병 안에 갇혀 있다.
  - 층이 0.55초 동안 위로 사라지고, '+N ×k' 글자가 병 테두리와 이웃 병 위에 겹친다.
  - 큰 반응은 콤보 ×4부터다.
- 콤보 배지는 17px로, 42px 점수 옆 메타 줄에 있다.
- '조각 칸 아래' 배치에서는 점수판과 구역 정보 사이가 비어 있다. 중앙 배너는 화면 가운데에 떠서 상태 줄이나 병 윗부분을 가린다.

  | 크기 | 빈 공간 | 중앙 배너가 가리는 것 |
  |---|---|---|
  | 360x740 | 91px | 병 윗부분 |
  | 390x844 | 195px | 상태 줄 |
  | 412x915 | 266px | 상태 줄 |
  | 768x1024 | 375px | 없음 |

### 2.3 렌더링과 입력
- 수는 즉시 확정된다(`applyPour`·`applyPlace` → `commit()` → `render()`).
  - 연출은 `fxq`에 쌓였다가 `render()` 끝의 `applyFx()`가 붙인다.
- `render()`는 매번 병 버튼, 컵, 미리보기, 임시 잔을 지우고 다시 만든다.
  - 그래서 병 버튼 안의 연출(`burst`, `float`, `flash`, `pop`, `shake`)은 다음 render에서 사라진다.
  - 실측: 완성 직후 `.burst` 1개와 `.float` 1개가 있었다. 80ms 뒤 다음 붓기를 하자 둘 다 0개가 됐다.
- 탭은 `pointerup`에서 처리한다. 끌기와 구분하고, 대상 밖에서 떼면 취소하기 위해서다(controls 원칙 4).
  - 누르는 순간의 시각 반응은 tapPlace의 길게 누르기 링(`.charging`)뿐이다.
- 엔진 훅은 넷이다: `move(t, m)`, `clear(i, c, gain, streak)`, `comboBreak(streak, pts)`, `zone(z, empties, bonus, newColor)`.
  - 붓기의 원천 번호는 `pourTo`의 `from`으로 UI가 안다.
  - 넣기의 출발점(컵이나 끌던 고스트)도 `tryPlace`를 부르는 쪽에서 UI가 안다.
  - 옮겨 갈 층의 색과 수는 처리 전에 `previewPour`·`previewPlace`로 구할 수 있다.
- `prefs.reduceFx`의 기본값은 OS의 `prefers-reduced-motion`을 따른다.
  - JS 연출(펀치, 입자, 꽃가루, 사망 연출, 되돌려 보내기, 붓기 안내의 움직임)은 이 값을 본다.
  - CSS 애니메이션은 OS 감속 미디어 쿼리에서만 꺼진다.
  - 실측: OS 감속 없이 `reduceFx`를 켜도 `burst` 0.55s, `floatUp` 0.95s, `flash` 0.6s, `shake` 0.3s가 그대로 돈다. 설정 설명('멈춤, 흔들림, 입자, 꽃가루 효과를 끄고…')과 다르다.
- 소리와 진동
  - 소리는 Web Audio 합성(`tone`, `noise`)이고, 첫 `pointerdown`에서 AudioContext를 깨운다.
  - 마스터 볼륨이나 압축이 없어서, 소리가 겹치면 클리핑될 수 있다(코드 추정).
  - 진동은 `navigator.vibrate`다. iOS Safari에는 진동 API가 없으므로 아이폰의 손맛은 화면과 소리로만 전해진다.
- 헤드리스 Chrome의 `requestAnimationFrame` 간격은 이 PC에서 약 31ms로 고정된다. 그래서 헤드리스에서는 프레임 시간을 잴 수 없다(9장).

## 3. 반드시 지킬 원칙

1. 다음은 바꾸지 않는다: 규칙, `rulesSig`, 판 저장 형식(`wsurv.game.*`), 공유 텍스트, 데일리 결정성, 점수 계산, 되돌리기 규칙.
   - 엔진 블록의 diff는 0이어야 한다.
   - 시간에 따라 점수나 게임 오버가 달라지는 기능은 만들지 않는다. 러시 모드와 속도 점수는 질문만 한다(7.6).
2. **연출은 플레이어의 시간을 빼앗지 않는다.**
   - 수는 지금처럼 입력 즉시 확정한다.
   - 연출을 기다리게 하는 입력 잠금이나 지연 처리를 만들지 않는다. 잠그지 않으므로 입력 버퍼도 만들지 않는다.
     - ROADMAP MVP-0 #5의 '입력 버퍼 2개'는 연출 중 입력을 잠그는 구현을 전제로 한다. 이 차이를 보고에 적는다.
   - 연출 중에 다음 입력이 오면 바로 처리한다.
   - 진행 중인 연출은 끝까지 재생한다. 단, 같은 병이나 컵에 새 연출이 오면 앞의 것은 60ms 안에 끝맺는다.
   - 히트스톱은 연출의 시간축만 멈춘다. 입력, 판 상태, 소리 예약은 멈추지 않는다.
   - 연출 레이어는 `pointer-events: none`이다. 비행 중에도 실제 병과 컵은 입력을 받는다.
3. **연출은 render와 분리한다.**
   - 새 연출과 옮겨 오는 기존 연출(`burst`, `float`, `flash`)은 render가 다시 만들지 않는 고정 레이어(`#fxLayer` 또는 새 레이어)에 그린다.
   - 위치는 수를 처리하기 전후에 잰 병·컵 박스로 정한다.
   - 클라우드 병합 render가 와도 연출과 보상 무대(U1)가 지워지지 않는다.
4. **줄이기 스위치는 하나다.**
   - `prefs.reduceFx` 하나로 새 연출과 기존 CSS 연출을 함께 줄인다. 기본값은 지금처럼 OS 설정을 따른다.
   - 줄이기 모드에서는 흔들림, 히트스톱, 입자, 비행, 콜아웃 확대가 없다. 색과 글자는 OS 감속 때처럼 움직임 없이 바로 바뀐다.
   - 진행 표시(`.charging` 링)는 지금처럼 예외로 둔다.
5. **안전한 연출**
   - 초당 3회 넘게 번쩍이지 않는다(WCAG 2.3.1).
   - 흰빛 플래시는 병 하나 크기를 넘지 않는다.
   - 화면 흔들림은 최대 6px, 250ms 이내다.
   - 진동은 1회 최대 60ms이고, 한 패턴의 합은 200ms 이하다.
6. `prefs`의 `sound`, `vibrate`, `reduceFx`, `ghost`, `symbols`를 존중한다.
   - `prefs`에 더하는 키는 둘뿐이다.
     - `fx`: 사용자가 설정에서 고를 때만 저장한다. `prefs` 기본값 객체에 넣지 않고 `fxMode()` 같은 함수로 해석한다(controls 원칙 8).
     - `seenCoach`(U5): 손 안내를 보인 뒤 저장한다. 기존 `seenFlipHint`와 같은 방식이다.
   - 두 키 모두 클라우드 동기화(`localSave`·`mergeCloud`)에 넣지 않는다.
   - 새 저장 키는 만들지 않는다. 템포 지표는 기존 `wsurv.playtest` 안에 더한다(8장).
7. 단일 HTML을 유지한다.
   - 외부 라이브러리, 에셋, 새 파일을 페이지에 넣지 않는다. 소리는 Web Audio로 합성한다.
   - `<canvas>` 요소 하나를 마크업에 더하는 것은 된다.
   - 테스트용 전역 훅을 페이지에 넣지 않는다.
8. 화면 원칙(ROADMAP 1장 원칙 1)
   - 가장자리는 위험 신호(F7)에만 쓴다. 보상은 중앙과 점수 주변에만 둔다.
   - 배너는 지금처럼 큐 하나로 띄운다. 배너의 글자와 우선순위, 순서는 바꾸지 않는다(기존 검사가 본다). 위치는 U1에서 옮긴다.
   - 상시 버튼이나 패널을 새로 추가하려면 체크포인트 D에서 확인을 받는다. 설정 항목 추가는 괜찮다.
   - 열기 막대(F6)는 열기가 0이면 숨겨서 상시 요소로 만들지 않는다.
9. 병 줄은 움직이지 않는다.
   - 흔들림으로 잠깐 움직이는 것을 빼면, 연출과 보상 무대 때문에 `#rack`의 top이 1px 넘게 바뀌지 않는다.
   - 기본 규칙 4개 크기에서 가로·세로 스크롤이 생기지 않는다.
   - 설정 최대값 360x740에서 `scrollHeight`가 '기본' 연출보다 크지 않다.
10. 접근성
    - 연출 문구를 상태 줄(`aria-live`)에 더 쏟지 않는다. 콜아웃은 `aria-hidden` 레이어에 그린다.
    - 키보드로 한 넣기·붓기에도 같은 연출이 나온다.
    - 드래그 없이 되는 조작(controls 원칙 4)은 그대로다.
11. 기존 검사의 기대값을 고쳐서 통과시키지 않는다. 의도한 변경 때문에 고친 검사는 이름과 이유를 보고한다.
12. **성능 예산** (4배 CPU 감속, 390x844, '손맛 강화')
    - 한 수의 처리와 연출 시작에 드는 JS 시간이 p90 12ms 이하다.
    - 50ms를 넘는 long task가 0건이다. ×5 완성과 열기 최대 상태를 포함한다.
    - 동시에 살아 있는 연출 DOM 노드는 200개 이하다. 입자를 canvas에 그리면 canvas는 1개로 센다.
    - 헤드리스 프레임 시간은 쓰지 않는다(2.3). 실제 프레임은 휴대폰 체험(10장)으로 확인한다.

## 5. 연출 기반 (모든 설정에 적용)

### 5.1 연출 레이어 (P1)
- render와 독립된 연출 함수를 만든다. 이름과 형태는 주변 코드 관례를 따른다. 필요한 동작은 다음과 같다.
  - 박스 A에서 B로 층을 날리기
  - 병 박스에서 터뜨리기
  - 글자 띄우기
  - 흔들기
- 위치
  - 수를 처리하기 직전에 관련 병과 컵의 박스를 잰다(`pourTo`, `tryPlace`).
  - 처리하고 render한 뒤에 다시 잰다.
  - 연출은 고정 위치 레이어에 그린다.
- 기존 `burst`, `float`, `flash`를 이 레이어로 옮겨, 다음 render가 지우지 않게 한다.
  - '기본' 연출에서는 모양과 시간을 지금과 같게 유지한다. 바뀌는 것은 사라지지 않는다는 점뿐이다.
  - 새 층의 `pop`과 거절 `shake`는 병 버튼에 둬도 된다. 다음 render에서 끊겨도 어색하지 않다.
- 상한
  - 동시에 진행하는 비행은 4개까지다. 입자 노드는 160개까지이고, 넘으면 오래된 것부터 지운다.
- 정리: 다음 경우 진행 중인 연출을 즉시 모두 지운다. 지운 수의 연출이 남아 있으면 거짓 정보가 되기 때문이다.
  - 되돌리기
  - 새 판 시작(`startGame`)
  - 모드 전환
  - 시트가 열릴 때. 결과 시트는 사망 연출 뒤에 열린다.
- **수용 기준**
  - 완성 직후 80ms 안에 다음 수를 두어도, 완성 연출 노드가 원래 시간(기본 0.55s·0.95s)이 끝날 때까지 남는다.
  - 완성 연출이 진행 중일 때 `window.__cloud.push()`로 render를 일으켜도 연출이 남는다.
  - 되돌리기를 누르면 연출 레이어가 비고, 진행 중이던 연출 노드가 0개가 된다.
  - '기본' 연출에서 기존 8개 시나리오와 controls, geom이 그대로 통과한다.

### 5.2 줄이기 스위치 통합 (P2)
- `prefs.reduceFx`를 문서 루트의 클래스(예: `fx-reduce`)와 맞춘다.
- 이 클래스에 OS 감속 미디어 쿼리와 같은 효과를 준다. 기존 CSS 끝의 `@media (prefers-reduced-motion: reduce)` 두 규칙이 그 범위다.
  - 모든 애니메이션의 시간을 0.01ms로 줄이고, 전환을 없앤다.
  - 예외: `.charging` 링은 지금처럼 시간을 유지한다.
- 설정 설명 문구를 실제 동작에 맞춘다.
- **수용 기준**
  - 일반 모드(OS 감속 아님)에서 `reduceFx`를 켜고 완성과 거절을 일으킨다.
  - 그 뒤 해당 요소의 computed `animation-duration`이 0.01ms 이하이거나 애니메이션이 없다.
  - 새 연출(비행, 입자, 흔들림, 콜아웃 확대)의 노드나 transform이 생기지 않는다.

### 5.3 누르는 순간 반응 (P3)
- 병, 컵, 임시 잔에 `pointerdown` 즉시 눌림 표시를 붙인다. 예: 0.97배 축소와 밝기 변화, 전환 60ms 이하.
- 떼거나 취소하면 원래대로 돌린다. 끌기로 바뀌면(8px) 눌림 표시를 풀고 지금의 끌기 표시로 넘어간다.
- 판 상태(`S`)와 선택(`sel`)은 바꾸지 않는다. 처리는 지금처럼 `pointerup`에서 한다.
- render가 와도 누르는 중이면 눌림 표시를 다시 붙인다(`reapplyGesture`).
- **수용 기준**
  - 누른 직후 다음 프레임 전에 대상에 눌림 클래스가 있고, `S`와 `sel`은 그대로다.
  - 뗀 뒤에는 눌림 클래스가 없다. 누르는 중 `__cloud.push()`가 와도 눌림 클래스가 남는다.
  - real.js의 터치·마우스 모두에서 확인한다.

## 6. 새 손맛 ('손맛 강화'에서만)

### 6.0 설정과 공통 시간표
- 설정 '화면 (바로 적용)' 섹션에 '연출' 선택을 둔다. 선택지는 '기본'(`base`)과 '손맛 강화'(`juicy`)다.
  - `prefs.fx`는 고를 때만 저장하고 `fxMode()`로 읽는다.
  - 기본 해석값은 체크포인트 D 전까지 `base`다.
- `reduceFx`가 켜져 있으면 '손맛 강화'도 5.2의 줄이기 모드로 동작한다.
- 아래 시간은 시작값이다. 바꾸면 `AUDIT.md`에 이유와 함께 적는다. ROADMAP 수치(pour-feel 축소판 등)와 달라지면 고칠 문장을 보고에서 제안한다.
  - 기호: k = 그 완성 뒤의 콤보 단계(`streak`), p = min(k, 5)

| 장면 | 연출 | 시간 |
|---|---|---|
| 누름 | 5.3 눌림 | 즉시 |
| 붓기 | F1 비행 | 들기 50ms + 호 140ms, 층 간격 30ms, 합 260ms 이하 |
| 넣기 | F2 낙하 | 탭 넣기 120ms, 끌기 넣기 80ms, 착지 squash 120ms |
| 다음 조각 | F2 큐 이동 | 120ms |
| 완성 | F3 터짐 | 충격 60ms + 히트스톱 30+10p ms, 입자 450~600ms, 링 250ms |
| 흔들림 | F3 | 진폭 (1+p)px, 길이 120+25p ms (최대 6px, 250ms) |
| 점수 | F5 비행·굴리기 | 비행 350ms, 굴리기 300~450ms |
| 콜아웃 | F4 | 600~900ms |
| 구역 돌파 | F8 물결 | 700ms |

### F1 붓기 비행
- 원천 병의 맨 위 층 n개가 원천 병 입구에서 대상 병 입구로 호를 그리며 날아간다.
  - 층이 여럿이면 30ms 간격으로 뒤따른다.
  - 원천 병은 들기 동안 살짝 기운다(15° 이하).
- 대상 병의 새 층은 착지 순간에 '찰랑'하는 squash로 자리 잡는다. 지금의 `pop`을 대신한다.
- 소리: 층마다 짧은 물방울 음을 낸다. 층마다 +3반음 올리고, 콤보 단계만큼 이조한다(ROADMAP pour-feel 풀버전).
- 진동: 붓기 1회에 8ms.
- 끌기 붓기는 손가락이 끌던 고스트(`.ghost.pour`)가 대상 입구로 80ms 동안 빨려 들어간다. 그다음 같은 착지를 한다.

### F2 넣기 낙하와 큐 이동
- 탭 넣기: 조각이 컵에서 대상 병 입구로 120ms 동안 떨어진다(ease-in). 착지하면 squash(세로 0.82 → 1.04 → 1)를 한다.
- 끌기 넣기: 고스트가 대상 입구로 80ms 동안 빨려 들어간 뒤 같은 착지를 한다.
- 착지 피드백: 낮은 '툭' 소리(약 140Hz, 90ms)와 12ms 진동. 완성이 나면 F3가 이어받는다.
- 큐 이동
  - 첫 미리보기가 '지금' 자리로 120ms 동안 미끄러진다. 나머지 미리보기도 한 칸씩 당겨진다.
  - 비행 중에도 실제 컵은 입력을 받는다. 컵에 `pointerdown`이 오면 비행을 즉시 끝낸다.
- 거절: 지금의 흔들림에 더해 대상에 짧은 빨간 테두리 깜박임(1회, 150ms)과 낮은 '퉁' 소리를 낸다.

### F3 완성 '터짐'
테트리스의 줄 지우기처럼 '번쩍 → 멈칫 → 펑' 순서로 터진다.
- **충격** (0ms)
  - 완성된 병이 흰빛으로 번쩍인다(병 박스 안, 60ms).
  - 병이 1.06배로 튀고, 코르크가 '뻥' 튀어 올라 돌며 사라진다. 착지 미리보기의 금색 코르크와 이어지는 그림이다.
- **히트스톱** (30+10p ms): 충격 프레임을 그대로 잡아 둔다. 입력과 다음 수는 막지 않는다(원칙 2).
- **펑**
  - 그 색의 물방울 입자 12+6p개가 방사형으로 튀고, 중력을 받아 떨어진다(450~600ms).
  - 충격파 링이 퍼진다(250ms).
  - p가 2 이상이면 병 줄과 보상 무대를 흔든다. 하단 버튼은 흔들지 않는다.
- **소리**
  - 지금의 `chime`(콤보 음계)에 임팩트를 더한다. 임팩트는 짧은 노이즈와 저음 쿵이고, 세기는 p에 비례한다.
  - 코르크 '뽁' 소리를 더한다(짧은 고음 하강).
- **진동**: p1 20ms, p2 25ms, p3 [25,30,25], p4 [30,30,40], p5 이상 [40,30,60]
- **점수 글자**: '+N'이 병 위로 튀어 오른 뒤 점수판으로 날아간다(F5). 병 테두리와 이웃 병 위에 머무르지 않는다.
- 한 수에 2병 이상 완성되면 병마다 70ms 간격으로 차례로 터진다(지금의 아르페지오와 맞춘다).

### F4 콤보 사다리
ROADMAP combo-ladder의 단계를 지키면서 키운다. 보상 무대(U1)에 큰 ×N을 둔다.

| k | 무대 | 콜아웃(기본안, D에서 확정) | 추가 |
|---|---|---|---|
| 1 | ×1이 나타남 | 없음 | 입자 기본 |
| 2 | ×2 펄스 | '좋아요' | 점수 글자 1.2배 |
| 3 | ×3 광택 | '멋져요' | 흔들림 시작 |
| 4 | ×4 크게 | '대단해요!' | 히트스톱 70ms, 펀치. 배너 '×4!'는 지금 글자 그대로 |
| 5 이상 | ×5 불꽃 테두리 | '최고예요!!' | 화음, 무대 배경 입자. 배너 '×5!!' 그대로 |

- 퓨즈(콤보 ×2 이상인데 이번 구간에 완성이 아직 없음): 무대의 ×N에 심지가 타들어 가는 표시를 한다. 메타 줄의 `#combo.fuse`는 그대로 둔다(기존 검사).
- 콤보 끊김(×3 이상): 무대의 ×N이 유리처럼 금 가며 떨어진다. 지금의 `glass` 소리와 배너 글자는 그대로다.

### F5 점수 굴리기
- 점수 글자가 점수판에 닿는 순간 점수가 굴러 오르고(300~450ms) 살짝 튄다.
- 표시만 따라가고 `S.score`는 즉시 바뀐다. 다음 경우에는 표시를 즉시 실제 값으로 맞춘다.
  - 되돌리기, 새 판, 모드 전환
  - 클라우드 render
  - 결과 시트를 열 때
  - `reduceFx`
- **수용 기준**: '손맛 강화'에서 완성 뒤 500ms가 지나면 `#score`의 글자가 `fmt(S.score)`와 같다. 위 경우에는 즉시 같다.

### F6 열기 (속도감, 연출만)
'빨리빨리'를 몸으로 느끼게 하는 장치다. 점수와 규칙에는 영향이 없다.
- 계산
  - 넣기나 붓기를 직전 수에서 1.2초 안에 두면 열기가 1 오른다(0~10).
  - 2.5초 넘게 쉬면 1.5초마다 1씩 식는다.
  - 되돌리기를 하면 3 내리고, 새 판을 시작하면 0이 된다.
  - 열기는 UI 변수일 뿐이고 저장하지 않는다.
- 효과
  - 입자 수에 (1 + 열기/10)을 곱한다.
  - 붓기·넣기 소리를 열기만큼 반음 올린다(최대 +5).
  - 열기가 7 이상이면 무대 테두리에 불꽃이 인다. 화면 가장자리에는 두지 않는다(원칙 8).
- 표시: 보상 무대의 얇은 막대 하나다. 열기가 0이면 숨긴다.
- 위험: 생각하는 퍼즐에서 서두르게 만들어 실수를 늘릴 수 있다. 8장의 기록으로 확인하고 D에서 유지 여부를 받는다.

### F7 위기 (ROADMAP danger-states, 연출만)
- 막힘(`S.stuck`)이 시작되면 다음을 한다.
  - 화면 가장자리에 붉은 비네트를 띄운다(300ms 페이드). 병 영역 안에는 들이지 않는다.
  - 심장 박동 소리를 8박 한 번 낸다.
  - 진동 [30,60,30]
- 남은 칸이 거의 없을 때(일반 병 빈칸 합이 조각 크기 + 2 이하)는 비네트를 아주 약하게 띄운다. 소리는 없다.
- 위기 탈출(막힘 상태에서 넣기 성공)
  - 비네트가 300ms 동안 걷히며 가장자리가 잠깐 밝은 색으로 바뀐다. 화면 전체를 번쩍이지 않는다(원칙 5).
  - 올라가는 2음을 낸다.
- 상태 줄의 막힘 문구는 그대로 둔다(기존 검사와 접근성).

### F8 구역 돌파
- 새 색이 들어오는 턴에는 보상 무대를 가로질러 새 색의 물결이 지나간다(700ms).
  - 배너 글자('2구역 · 새 색 보라 (5종)')는 그대로다.
  - 빈 병마다 보너스 숫자가 튀어 올라 점수판으로 날아간다(F5).
- 쌍둥이 조각(`NEW`)은 컵에 들어올 때 새 색 테두리로 한 번 빛난다.

### F9 소리 믹스
- 모든 소리를 마스터 게인과 `DynamicsCompressorNode` 하나로 모은다. 여러 소리가 겹쳐도 깨지지 않게 하기 위해서다. Web Audio 내장 노드라 원칙 7에 맞는다.
- 소리 표를 `AUDIT.md`에 적는다. 장면, 주파수·길이, 볼륨, 콤보·열기에 따른 변화를 적는다.
- '소리' 설정이 꺼져 있으면 AudioContext를 만들지 않는다. 지금 동작과 같다.

## 7. 화면 개선

### U1 보상 무대 ('손맛 강화'에서만)
- '조각 칸 아래' 배치의 빈 공간(점수판 아래 ~ 구역 정보 위)을 보상 무대로 쓴다.
  - 큰 ×N(F4), 퓨즈, 열기 막대(F6), 콜아웃을 둔다. 점수 비행의 목적지는 점수판이다.
  - 큰 ×N은 메타 줄의 콤보를 키워 옮긴 것으로 본다. 콤보가 없으면 숨긴다. 메타 줄의 `#combo`는 그대로 둔다.
  - 무대는 '손맛 강화'에서만 보이므로 D에서 유지 여부를 받는다(원칙 8).
- **배너를 무대 안으로 옮긴다.**
  - 병 줄과 상태 줄을 가리지 않게 한다.
  - `#banner`의 id, 글자, 큐 순서는 그대로다.
- 무대는 흐름(flow) 배치를 바꾸지 않는다. 무대 내용이 바뀌어도 병 줄이 움직이지 않는다(원칙 9).
  - 막혀서 '포기하고 결과 보기' 줄이 나타나면 그 줄이 우선이다. 무대는 남은 공간 안으로 줄어든다.
- '조각 칸 위' 배치에는 빈 공간이 없다. 큰 ×N 대신 점수판 안의 콤보를 키우고, 콜아웃과 배너는 점수판 위에 겹쳐 띄운다.
- 360x740(빈 공간 91px)에서도 ×N과 콜아웃이 잘리지 않는다.
- **수용 기준** (geom에 `juicy` 변형 추가, 기본 규칙 4개 크기 + 최대 설정 2개)
  - 배너와 콜아웃의 박스가 `#rack`·`#status`·하단 버튼과 겹치지 않는다.
  - 무대 내용이 바뀌거나 포기 줄이 나타나도 `#rack`의 top 변화가 1px 이하다.
  - 스크롤이 생기지 않는다(원칙 9).

### U2 상태 줄 나눔 ('손맛 강화'에서만)
- 상태 줄은 안내와 경고만 맡는다.
- 콤보 기대 문구('이번 턴에 병을 완성하면 콤보 ×3')는 무대의 ×N과 퓨즈가 보여 주므로 상태 줄에서 뺀다. 그 자리에는 평상시 문구를 보인다.
- 다음 문구는 결정에 필요한 경고라서 그대로 둔다.
  - 퓨즈 경고('다른 병에 넣으면 콤보 ×N 끝나요')
  - 막힘, 거절, 확인 대기 문구
- '기본' 연출의 문구는 바꾸지 않는다(기존 검사).

### U3 결과 시트 ('손맛 강화'에서만)
- 점수가 0에서 굴러 오른다(600ms 이하). 신기록이면 시트 안에서 한 번 더 축하한다(꽃가루는 시트 위에 띄운다).
- 버튼의 순서와 색은 바꾸지 않는다. 질문 항목이다(7.6).

### U4 설정 시트 정리 (모든 설정)
- 순서
  1. 화면: 소리, 진동, 효과 줄이기, 연출, 착지 미리보기, 페이스, 단계별 안내, 색 기호
  2. 테마
  3. 클라우드 저장
  4. '프로토타입 실험'(규칙, 광고 자리, 조작, 잠긴 테마 써보기, 플레이 테스트 기록). `<details>`로 기본 접힘이다.
- 모든 id와 동작은 그대로다. 기존 검사가 접힌 항목을 다룰 때 열어야 하면 검사 도우미만 고치고 보고한다.
- 접힌 상태와 펼친 상태의 시트 `scrollHeight`를 보고한다(지금 2144px).

### U5 처음 온 사람 (모든 설정)
- 처음 온 사람의 도움말에서 '새 규칙' 목록을 뺀다. 기존 사용자에게 한 번 보이는 v2 시트(`#ovV2`)는 그대로다.
- 첫 판 손 안내
  - 0턴에 도움말을 닫으면, 반투명 손가락이 조각을 들어 병으로 끌어 올리는 동작을 2번 보여 준다.
  - 첫 붓기가 가능해진 턴에는 '병 → 병' 탭 표시를 1번 보여 준다.
  - 아무 입력이나 들어오면 사라진다.
  - 기기당 1회만 보인다. 보인 뒤 `prefs.seenCoach`를 저장한다(원칙 6).
  - '단계별 안내'를 끄면 보이지 않는다.
- **수용 기준**
  - `case=newuser`에서 도움말을 닫은 뒤 손 안내가 보인다. 입력 하나로 사라지고, 새로고침 뒤에는 다시 보이지 않는다.
  - 손 안내는 입력을 막지 않는다. 손 안내가 떠 있을 때 조각을 끌어 넣을 수 있다.
  - 기존 사용자(`seenHelp`)에게는 보이지 않는다.

### 7.6 질문만 하는 항목 (구현하지 않음)
체크포인트 D 보고에 장단점과 함께 적는다.
- **결과 시트 버튼**: '다시 하기'를 맨 아래의 큰 주 버튼으로 올리고 부활을 그 위 보조로 둘지. 빠른 재도전과 광고 수락률이 맞바뀐다(ROADMAP 원칙 3 '광고는 플레이어가 고른다').
- **하단 버튼 구성**: 플레이 중 주 색 버튼이 모드 전환('오늘의 도전')인 것을 바꿀지. 예를 들어 모드 전환을 헤더로 옮기고, 하단을 되돌리기 중심으로 둘 수 있다. 상시 요소 변경이다.
- **러시 모드**: 3분 동안 점수를 겨루는 시간 압박 모드를 만들지. 규칙 변경이다.
  - 엔진에 시간 종료(`overReason`)를 더해야 한다.
  - 기록 키와 공유 텍스트가 새로 필요하다.
  - 봇으로 밸런스를 잴 수 없다.
- **속도 점수**: 빨리 둘수록 점수를 더 줄지. 점수 공식 변경이라 데일리 비교와 기록이 갈린다.
- **classic 막힘 힌트**: 막혔을 때 자리를 만드는 붓기를 화살표로 보여 줄지. tapPlace의 붓기 안내를 재사용한다.
- **'빈 n' 글자**: 병 아래 빈칸 숫자를 고르거나 끄는 중에만 보일지.
- **배경 박자**: 열기에 맞춰 빨라지는 배경 박자를 넣을지. 소리 설정과 배터리 영향이 있다.

## 8. 플레이 테스트 기록의 템포 지표

기존 `wsurv.playtest`(`v: 1`)에 연출별 기록을 더한다. 기존 필드와 형식은 그대로 둔다.
- 형식: `fx: { '<base|juicy>': 기록 }`. 없으면 처음 셀 때 만든다.
- 기록 항목(연출마다)
  - `runs`: 시작한 판 수. `startGame`이 새 상태를 만들 때만 센다.
  - `turns`: 넣기 수
  - `turnMs`: 넣기와 넣기 사이 시간의 합. 한 턴을 최대 20초로 자른다. 판의 첫 넣기는 그 판을 화면에 띄운 때부터 잰다(이어 하기 포함).
  - `moves`: 넣기와 붓기 수
  - `fastMoves`: 직전 수에서 1.2초 안에 둔 넣기·붓기 수
  - `undos`, `rejects`
  - `bigCombos`: ×4 이상 완성 수
- 각 수는 그 순간의 `fxMode()`로 센다. 판 시작 때의 설정을 `S`나 저장 형식에 기억하지 않는다.
- 보기: 설정의 '플레이 테스트 기록'에 연출별 한 줄을 더한다.
  - 예: `연출 juicy · 3판 112턴 · 턴당 4.2초 · 빠른 수 41% · 되돌리기 2 · 거절 5 · ×4 이상 6회`
- 초기화하면 `fx`도 비운다. 클라우드 동기화에는 넣지 않는다.
- **수용 기준**
  - 정해진 입력을 보낸 뒤 각 값이 입력 수와 같다. 입력은 넣기 n, 붓기 m, 1.2초 안의 수 f, 되돌리기, 거절이다.
  - 판 도중 연출을 바꾸면 그 뒤의 수가 새 키에 쌓인다.
  - 기존 `by` 기록의 검사가 그대로 통과한다.

## 9. 측정과 검사

  - 완성 직후 빠른 붓기를 해도 연출이 남는지

## 10. 체험 절차 (체크포인트 D에서 사용자에게 건넨다)

1. Pages 주소를 휴대폰 Chrome에서 연다. 예전 페이지가 보이면 새로고침한다.
2. 설정의 '프로토타입 실험'을 펼쳐 '플레이 테스트 기록'을 초기화한다. 소리와 진동을 켠다.
3. '연출: 기본'과 '연출: 손맛 강화'를 한 판씩 번갈아 각각 3판, 한 손 엄지로 한다. 판 도중에는 설정을 바꾸지 않는다.
4. 기록을 '복사'해서 붙여 주고, 아래 질문에 답한다.
   - 어느 쪽이 더 빠르게 느껴졌는가, 어느 쪽이 더 시원했는가
   - 연출 때문에 기다린다고 느낀 순간이 있었는가
   - 화면 흔들림이나 번쩍임이 거슬리거나 어지러웠는가
   - 콜아웃 문구('좋아요·멋져요·대단해요!·최고예요!!')의 말투가 괜찮은가
   - 열기 막대 때문에 서두르다 실수했는가
   - ×4 이상에서 화면이 끊기거나 휴대폰이 뜨거워졌는가
   - 처음 온 사람이라고 생각하고 볼 때, 손 안내가 도움이 되는가
- 판단에 참고할 기준(사용자가 정한다)
  - '손맛 강화'의 턴당 시간이 '기본'보다 늘지 않아야 한다. 연출이 플레이를 느리게 만들지 않았다는 뜻이다.
  - 거절과 되돌리기가 크게 늘지 않아야 한다.
  - 이 둘을 만족하고 사용자가 더 낫다고 느끼면 기본값으로 바꾸기를 추천한다.
  - 판 수가 적어 숫자는 참고용이다. 체감 답을 우선한다.

### 10.1 확정
- 고른 연출을 기본값으로 한다. `fxMode()`의 기본 해석값을 바꾸며, 저장된 값이 없는 기기에만 적용된다.
- 기존 UI 시나리오는 `wsurv.prefs`에 예전 기본값(`fx: 'base'`)을 넣어 돌린다. controls2 8장의 방식과 같다. 새 기본값 검사는 `feel` 시나리오에 둔다.
- D에서 빼기로 한 항목은 코드와 검사를 함께 되돌린다.
- 지는 쪽 연출을 지우기로 하면, 저장된 그 값은 새 기본값으로 읽는다.
- ROADMAP과 달라지는 결정이면 고칠 문장을 보고에서 제안한다.

## 11. 배포와 재게시

- **아티팩트**
  - 직전에 read해서 이 작업이 마지막으로 올린 내용과 같은지 확인한다.
