## 2. 현재 규칙 (v1)

**판 구성**
- 병 6개, 각 병 용량 4칸.
- 매 턴 1~2칸 조각이 오고, 미리보기는 2개다.
- 조각은 맨 위 색과 상관없이 빈칸이 충분한 병에 통째로 넣는다(`applyPlace`).

**붓기와 완성**
- 받는 병이 비었거나 맨 위 색이 같아야 붓는다. 맨 위 연속 구간이 공간만큼 옮겨진다(`canPour`/`doPour`). 붓기 횟수는 무제한이고, `pourLimit`으로 제한할 수 있다.
- 4칸 단색이 되면 자동으로 비운다. 점수는 완성 1병당 100 × `streak`이다.

**streak (콤보)**
- `applyPlace`는 settle 전에 `if (S.turn > 0) { S.turnLog.push(S.turnClears); if (S.turnClears === 0) S.streak = 0; }`를 실행한다.
- 이때 `turnClears`는 '직전 넣기의 settle + 그 뒤 붓기' 구간에서 나온 완성 수다.
- 그래서 직전 넣기나 그 뒤 붓기에서 완성이 있었으면 콤보가 이어진다(시드 cc0: 넣기 완성 100점 → 다음 넣기 완성 200점).
- ×1로 다시 시작하는 경우는 '완성 없는 구간 다음의 넣기 완성' 하나뿐이다.
- `settle`은 구간의 첫 완성에서 `streak++`를 한다.

**색과 조각**
- 색은 4종으로 시작해 20턴마다 1종씩 늘고 최대 8종이다(`colorsAt`). `pieceAt(seed, rules, i)`는 `hashStr`(FNV-1a)과 `mulberry32`를 쓴다.
- `NAMES`: 빨강, 파랑, 노랑, 초록, 보라, 주황, 청록, 분홍, 갈색. 시작 색은 0~3번이고, 20턴에 보라(5종), 40턴에 주황(6종), 60턴에 청록(7종), 80턴에 분홍(8종)이 추가된다.

**게임오버와 구조 수단**
- 게임오버: `checkStuck`에서 `canMakeRoom`(BFS, 노드 6000개)이 자리를 만들 수 없다고 판정하면 끝난다.
- 부활: 판당 1회. `applyRevive`가 가장 많이 찬 병 2개를 비운다. 부활하면 `history = []`가 된다.
- 되돌리기: 판당 3회. `snapshot()`이 S의 JSON을 `history`(최대 40개)에 쌓는다. 되돌리면 S를 복원한 뒤, `undoLeft`만 복원 전 값에서 1을 뺀 값으로 넘긴다.
- 광고: `showAd(done)`의 3초 오버레이다. `#ovAd .note` 문구는 '끝나면 가장 많이 찬 병 2개를 비워줘요'로 고정되어 있다.

**UI 구조**
- `onTube(i)`는 `S.bottles[i]`를 직접 읽고 `canPour(S.bottles, …, S.rules.cap)`를 쓴다.
- 클릭 리스너는 `#rack`에만 있다. 드롭 판정 `tubeAt`은 `'#rack .tube'`만 찾는다. `applyFx`는 `rack.children[i]`만 찾는다.

**토글, 모드, 키**
- 토글: 자동 합치기, 턴당 붓기 제한, 색 기호(`prefs.symbols`).
- 데일리: 시드 `'daily:YYYY-MM-DD'`, 규칙 `{...DEFAULT_RULES}`. 공유 텍스트는 3줄이다(점수·턴·완성·최대 콤보, `turnRhythm`).
- 기록 키(`bestKey`): 데일리는 `wsurv.daily.<seed>`, 무한은 `wsurv.best.<rulesSig>`. `rulesSig`는 규칙 필드 9개를 '-'로 이은 문자열이다.
- localStorage 키: `wsurv.rules`, `wsurv.prefs`, `wsurv.game.<mode>`, `wsurv.best.<rulesSig>`, `wsurv.daily.<seed>`, `wsurv.mode`, `wsurv.seenHelp`.
- 다크 모드: CSS가 `:root[data-theme="dark"]`를 지원한다.

## 5. 기능 명세

### F1. 넣기 완성 콤보 + 음계 사다리 + 퓨즈 (`comboPlace`, 기본 true)

**엔진**
- `comboPlace`가 false면 v1 코드 그대로다. 점수와 streak 계산이 바뀌지 않는다.
- true면 `applyPlace`를 이 순서로 실행한다. 턴 경계, `turnLog`, `turnRhythm`은 v1 정의 그대로다.
  ```
  const prev = S.turnClears, closing = S.turn > 0;
  if (closing) S.turnLog.push(prev);
  S.turnClears = 0; S.pours = 0;
  조각 넣기 → hooks.move → S.turn++ → settle(S, hooks);   // 리셋 전 streak으로 정산
  if (closing && prev === 0 && S.turnClears === 0) { 끊김 처리; S.streak = 0; }
  ```
  - 넣기가 완성을 내면 streak은 리셋 없이 +1이 되고, 점수는 100 × streak이다.
- **끊김 기록**: `S.comboPts`에 현재 연속 동안 얻은 완성 점수를 더한다. streak이 1 이상에서 0이 되는 순간 `hooks.comboBreak(이전 streak, comboPts)`를 호출하고 `comboPts`를 0으로 만든다. v1 경로에서도 리셋 지점에서 같은 훅을 호출한다. 상태 계산은 그대로 둔다.
- **상태 문구**: '이번 턴에 병을 완성하면 콤보 ×N'(N = streak+1)은 그대로 둔다.

**UI**

*소리*
- 완성 차임: 사인파에 삼각파 배음을 섞고 0.35초 동안 감쇠시킨다.
- 음높이 = 523.25Hz × 2^(s/12). s는 `[0,2,4,5,7,9,11,12,14,16,17,19]`의 (streak−1)번째 값이고, 범위를 넘으면 마지막 값을 쓴다.
- 한 동작에서 2병 이상 완성되면 70ms 간격으로 오르는 아르페지오를 낸다. 동시에 배너 큐로 '더블!'/'트리플!'을 띄운다.

*단계 연출*

| 단계 | 연출 |
|---|---|
| ×1 | 기존 burst |
| ×2 | 점수 float 글자 1.2배 + '좋아요' |
| ×3 | 콤보 배지 광택 펄스 |
| ×4 | 60ms 정지 → 랙 1.04배 펀치 0.15초 + 배너 '×4!' 0.8초(턴당 1회) |
| ×5 이상 | 배경 입자 + 3음 화음 + '×N!!' |

*퓨즈*
- `streak ≥ 2 && turnClears === 0`이면 콤보 배지(`#combo`)에 심지 불꽃을 켠다.
- 탭-탭: 컵을 선택한 즉시 상태 줄에 '완성되는 병 k곳 · 다른 병에 넣으면 콤보 ×N 끝나요'를 띄운다. k는 F6 `previewPlace`로 센다.
- 드래그: 손가락 아래 병의 결과에 따라 상태 줄을 바꾼다.
  - 완성 0이면 '넣으면 콤보 ×N 끝나요'
  - 완성 1 이상이면 '이 넣기로 완성 · 콤보 ×N+1'
- 금색 테두리(F6)가 있는 병은 '이 넣기로 완성 · 콤보 ×N+1'을 뜻한다. 도움말에도 이렇게 적는다.
- 퓨즈 문구는 F8 규칙에 따라 2번째 판부터 보인다.

*끊김*
- 끊긴 콤보가 ×3 이상이면 유리 깨지는 소리(노이즈 버스트 + 고음 감쇠)와 배지 흔들림을 낸다. 배너 큐로 '콤보 ×N · +X점'을 1초 띄운다.
- ×3 미만이면 조용히 리셋한다.

*진동과 설정*
- 진동은 `prefs.vibrate`가 켜져 있을 때만 쓴다. 완성은 기존 25ms, ×4 이상은 `[30,40,30]`이다.
- `prefs.reduceFx`가 켜져 있으면 정지, 펀치, 배경 입자를 생략한다.

**수용 기준**
- V1_RULES로 30시드×2봇을 돌리면 v1과 턴·점수가 같다.
- 엔진 테스트: `newState` 뒤 `S.bottles`와 매 넣기 직전의 `S.piece`를 직접 설정해 만든다.
  - (a) 넣기(완성 없음) → 붓기 완성 → 넣기(완성 없음) → 넣기 완성: 마지막 완성이 `comboPlace=false`에서 100점, true에서 200점이다.
  - (b) 넣기(완성 없음) → 붓기 완성 → 같은 구간에서 넣기 완성: 두 규칙 모두 합계 300점(100 + 200)이다.
  - (c) 넣기 완성 → 붓기 없이 다음 넣기 완성: 두 규칙 모두 100 → 200점이다. **이 테스트를 통과시키려고 v1 경로를 고치지 않는다.**
- 벤치 C: 시드별 턴은 A와 모두 같다. 점수가 A보다 낮은 판은 0이다. 오른 판 수를 보고한다(참고 재채점: 2수 봇 49/200, 그리디 15/200).
- 소리를 끄면 무음이다. 효과 줄이기를 켜면 정지, 펀치, 배경 입자가 없다.

### F2. 조각 뒤집기 (`flip` 기본 true, `flipLimit` 기본 3, 0이면 무제한, 범위 0~99)

**엔진** (`sim/piece-flip` 구현을 따른다)

### F5. 최고 기록 페이스 (`prefs.pace`, 기본 켬)

**기록** (UI 레이어. 엔진은 바꾸지 않는다)
- 넣기 후마다 `S.cum`에 `S.score`를 추가한다(최대 400개).
- **`S.cum.length !== S.turn`인 판은 페이스 저장과 비교에서 제외하고 라벨을 숨긴다.** 구 저장 판을 이어한 경우 등이다.
- 판 종료 시 처리:
  - `wsurv.last.<rulesSig>`에 `{score, turn, cum}`을 저장한다.
  - `wsurv.runs.<rulesSig>`를 +1 한다.
  - 최고 점수를 넘었으면 `wsurv.pace.<rulesSig>`에도 저장한다.
- 데일리는 `wsurv.pace.daily.<seed>`를 쓴다.
- 서명은 최근 10개만 유지한다(`wsurv.pace.idx` LRU).
- 모든 저장소 읽기와 쓰기를 try/catch로 감싼다. 실패하면 기능을 조용히 숨긴다.

**비교와 표시**
- 판 수가 10 미만이면 지난 판과, 10 이상이면 최고 판과 비교한다. `diff = S.score − ref.cum[min(S.turn, ref.cum.length) − 1]`.
- 점수 바로 아래 1줄에 '최고 페이스 ▲120' 또는 '지난 판 ▼80'을 표시한다(원칙 6에서 허용한 상시 요소).
  - 5턴 이후부터 보인다.
  - 완성이 나온 턴에만 갱신하고, 그때 0.4초 강조한다.
  - F8 규칙에 따라 3번째 판부터 보인다.
- **진행 바**: 최고 판의 종료 턴이 현재 구역 안이면 깃발을 그린다. 그보다 뒤면 바 오른쪽에 '최고 판: 5구역'을 쓰고, 이미 넘었으면 '✓'를 표시한다.
- **신기록 페이스**: 10턴 이후 처음 앞서면(판당 1회) 배너 큐로 토스트를 띄우고 도·미·솔 3음을 낸다.
- **최고 기록 경신**: 최고 > 0이고 실제 점수가 최고를 넘는 순간(판당 1회) 다음을 낸다.
  - 배너 큐 최우선으로 1.2초 배너 '최고 기록 경신'
  - 점수 광택
  - 진동 `[40,60,40]`
  - CSS 컨페티 30개(효과 줄이기가 켜져 있으면 배너만)
- **종료 화면**: 신기록이 아니면 '최고 기록까지 340점 (콤보 ×2로 약 2병)'을 띄운다(병 수 = ceil(gap/200)). 신기록이면 '+X점'을 띄운다.
- **부활 버튼 문구** (우선순위 순)
  1. 다음 구역까지 넣기 3번 이하: '3턴만 버티면 4구역 · 광고 보고 이어하기'
  2. 최고 > 0이고 0 < 남은 점수 ≤ (S.score / S.turn) × 12: '신기록까지 340점 · 광고 보고 이어하기'. 부활 1회의 기대 이득(약 9~14턴)에 맞춘 기준이다.
  3. 그 외: 기존 문구
- **설정**: '최고 기록 페이스'를 끄면 라벨과 페이스 토스트만 숨긴다. 경신 배너는 유지한다.

**수용 기준**
- 저장소를 쓸 수 없어도 오류가 없다.
- 배너는 판당 1회만 뜨고 입력을 막지 않는다.
- 되돌리기 후에도 diff가 스냅샷과 일치한다.
- 구 저장 판을 이어하면 라벨이 숨겨지고 `wsurv.pace.*`가 바뀌지 않는다.
- 부활 문구의 노출률과 달성률을 봇으로 보고한다(7장 R).

### F6. 착지 미리보기 (`prefs.ghost`, 기본 켬)

**엔진 순수 함수** (S를 바꾸지 않고 복사본에서 계산한다)
- `previewPlace(S, t)` → `{ok, add, clears, completes}`. t는 일반 병만 받는다.
- `previewPour(S, s, t)` → `{ok, moved, color, clears, completes}`. `slotsOf(S)`와 `capsOf(S)`를 써서 잔을 포함한다.

**UI**
- **드래그 중** (조각 넣기)
  - 손가락 아래 일반 병 하나에만, 들어갈 층을 40% 투명 고스트로 그린다. 완성이면 금색 테두리와 코르크를 띄운다.
  - **임시 잔 위에서는 고스트 대신 빨간 테두리(거절 표시)를 그린다.** 놓으면 F4의 거절이 일어난다.
  - 소리는 놓을 때만 낸다.
- **탭-탭, 컵 선택**: 넣으면 완성되는 병에만 금색 테두리와 코르크를 띄운다. 넣을 수 있는 나머지 병은 기존 `.can`을 쓴다. 상태 줄은 F1을 따른다.
- **탭-탭, 병 선택**: 부을 수 있는 대상마다(잔 포함) 옮겨질 층 수만큼 작은 고스트를 그린다.
  - 원본에서 떠날 층은 50% 투명으로 표시한다.
  - 완성되는 대상에는 금색 테두리를 두른다.
  - 잔 고스트는 이 경우에만 그린다.
- **기호**: 색 기호 모드에서는 고스트에도 기호를 표시한다.
- 덮음 경고는 만들지 않는다.

**수용 기준**
- 엔진 테스트: 무작위 보드 1000개(잔이 있는 보드 포함)에서 미리보기의 `clears`·`completes`가 실제 `applyPlace`/`applyPour` 결과와 100% 같다.
- 미리보기는 S, 저장, 되돌리기 기록을 바꾸지 않는다.
- 설정에서 끄면 고스트와 금색 테두리가 모두 사라진다.

### F7. 게임오버 니어미스와 맥락 문구

**엔진 순수 함수 `nearMiss(S)`**
- `need`, `maxFree`, `short = need − maxFree`
- `almost`: 단색이고 길이가 cap−1인 병의 색 목록
- `scattered`: 맨 위 연속 구간의 합이 cap 이상인 색 목록
- `zoneLeft`: 다음 구역 시작까지 남은 넣기 수

**UI** (`overReason === 'noroom'`일 때만)
- **연출**
  1. 대기 조각 고스트가 빈칸이 가장 많은 병 위로 0.25초 동안 갔다가 튕겨 돌아온다. 저음 '퉁' 소리를 낸다.
  2. 랙에 `saturate(0.3)`을 0.6초 적용한다.
  3. 시트를 연다.
  - 탭하면 즉시 시트로 넘어간다. 부활 뒤 사망은 0.3초 축약판을 쓴다. 효과 줄이기가 켜져 있으면 생략한다.
- **시트 문구**: 사실만 최대 2줄 보여 준다. 우선순위는 다음과 같고, 그 아래 F5 문구 1줄을 붙인다.
  1. `short === 1`: '2칸 조각, 가장 넓은 빈칸 1칸: 딱 1칸 모자랐어요'
  2. `almost`가 있으면: '빨강 3/4: 1칸만 더 있으면 완성'
  3. `scattered`가 있으면: '맨 위에 파랑이 4칸 흩어져 있었어요'
- **부활**: 부활 직전에 `S.preReviveScore = S.score`를 기록한다.
- **포기**(`gaveup`)로 끝났을 때는 연출과 니어미스를 보여 주지 않는다.

**수용 기준**
- 봇 200판의 사망 보드에서 `short === 1`, `almost` 있음, `scattered` 있음 비율을 보고한다.
- 탭으로 건너뛰기가 동작한다.

### F8. 단계 공개와 v2 안내 (UI만, 규칙은 바꾸지 않는다)

- **진행 기록** `wsurv.unlock = {runs, sawOver}`: 판이 끝나면(게임오버 또는 포기) `runs+1`, 게임오버면 `sawOver = true`로 둔다. 데일리도 포함한다.
- **공개 표**

- **새 사용자**: 기존 도움말(6장에서 갱신)을 보고 위 표를 따른다.
- **설정 '단계별 안내'** (`prefs.staged`, 기본 켬): 끄면 모든 요소를 처음부터 보이고 공개 토스트를 띄우지 않는다. 사람 테스트의 '안내 없음' 조건에 쓴다.

**수용 기준**
- localStorage를 비운 새 프로필
  - 1판에서는 ⇅가 숨겨져 있다가 20턴에 나타나며 토스트가 뜬다.

## 8. 브라우저 확인

- 브라우저 패널은 로컬 파일(file://)을 열 수 없고, 게시본은 로그인이 필요해 열리지 않을 수 있다. 그래서 로컬 헤드리스 Chrome으로 확인한다.
  - 게시 시 붙는 뼈대(`<!doctype html>`, charset, `viewport`(width=device-width, viewport-fit=cover), `[hidden]{display:none!important}`)로 감싼 미리보기 HTML을 BASE에 만든다.
  - 360px·390px 폭 iframe을 나란히 둔 프레임 페이지를 만들어 스크린샷을 찍는다. 헤드리스 Chrome은 창 폭이 약 500px 아래로 내려가지 않으므로 iframe 폭으로 휴대폰 폭을 맞춘다.
  - 실행 예: `"C:/Program Files/Google/Chrome/Application/chrome.exe" --headless=new --disable-gpu --hide-scrollbars --user-data-dir=BASE/chrome-prof --window-size=830,900 --virtual-time-budget=5000 --enable-logging=stderr --v=0 --screenshot=BASE/shot.png file:///BASE/frame.html`. 사용자의 실제 Chrome 프로필은 쓰지 않는다.
  - 다음을 확인한다.
    - 가로 스크롤이 없다.
    - stderr 로그에 `Uncaught` 등 콘솔 오류가 0건이다. `navigator.vibrate` 차단 안내는 무시한다.
- **다크 모드**: 미리보기 HTML의 `<html>`에 `data-theme="dark"`와 `data-theme="light"`를 각각 넣은 두 벌로 찍어 텍스트 대비를 확인한다.
- **상호작용**: 미리보기 HTML에만 자동 조작 스크립트(컵 `click()` → 병 `click()` 반복 등)를 넣어 원하는 상태를 만든 뒤 찍는다. 이 스크립트는 게시본에 넣지 않는다.
- **수동 시나리오**
