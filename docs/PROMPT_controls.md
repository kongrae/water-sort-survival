# 물정렬 생존 조작성 검증·개선 지시

너는 이 HTML 프로토타입의 조작(입력)을 검증하고 개선하는 개발자다. 할 일은 네 가지다.
1. 실제 포인터 입력(탭·드래그·멀티터치·키보드)으로 조작을 검사하는 테스트 도구를 만든다.
2. 현재 조작을 감사해 결함 표와 측정 기준선을 만들고, 6장의 결함을 고친다.
3. 7장의 조작 후보를 설정에서 고를 수 있는 시제품으로 만들고, 8장대로 측정한다.
4. 체크포인트 B에서 사용자가 휴대폰으로 써 보고 고른 안을 기본값으로 확정한다.

배경: 지금은 매 턴 화면 위쪽의 '지금' 잔을 먼저 누르거나 거기서 끌어야 조각을 넣을 수 있다. 사용자가 이 점을 불편하다고 지적했고, 조작 전체의 검증을 원한다.

진행 규칙:
- 보고는 한국어로 하고 원인을 먼저 쓴다.
- 추측해서 구현하지 않는다. 먼저 코드를 읽는다. 이 문서의 줄 번호와 수치는 커밋 305aca9 기준이라 밀릴 수 있다. 코드는 앵커 문자열(예: `// ---------- input ----------`)로 찾는다.
- 명세가 코드와 충돌하거나 판단이 서지 않으면 진행하기 전에 짧게 질문한다.
- 엔진(`<script id="engine">` 안)은 고치지 않는다. 조작 변경은 UI IIFE 안에서만 한다.
- 4장의 멈춤 조건과 체크포인트 B에서는 반드시 멈춘다.
- 커밋
  - 단계마다 해도 된다. 메시지는 한국어로, 기존 커밋 형식을 따른다.
  - 이번 작업에서 만들거나 고친 파일만 경로를 지정해 `git add`한다. `git add -A`는 쓰지 않는다.
  - 작업 전부터 있던 미커밋 파일은 사용자 것이다. 건드리지도 커밋하지도 않는다.
- `deploy-pages.ps1`은 공개 저장소에 푸시한다. 사용자 승인을 받은 뒤에만 실행한다(11장).
- 아티팩트는 비공개라 재게시해도 된다(11장).

## 2. 현재 조작 (305aca9 기준 사실)

### 2.1 선택 상태와 리스너
- `sel`은 `null`(선택 없음), `'cup'`(지금 조각 선택), 슬롯 번호(붓기 원천 병, 임시 잔은 `S.bottles.length`) 중 하나다.
- `#rack`(병 선반)과 `#spareSlot`(임시 잔)에는 `click` 리스너만 있다. 병에서 시작하는 드래그는 없다.
- 조작용 포인터 리스너(`pointerdown/move/up/cancel`)는 `#cup`에만 있다.
- `document`에는 capture 단계의 `pointerdown` 리스너가 두 개 있다. 하나는 소리를 켜기 위한 것으로 항상 동작하고, 다른 하나는 게임오버 연출 건너뛰기로 연출 중에만 동작한다. 새 포인터 처리가 이 둘을 막으면 안 된다.
- `touch-action:none`은 `.tube.mini`(컵)에만 있다.
- `render()`는 매번 `#rack`의 병 버튼과 `#spareSlot`의 버튼(임시 잔 또는 제안)을 지우고 다시 만든다.

## 3. 반드시 지킬 원칙

1. 규칙, `rulesSig`, 저장 키, 공유 텍스트, 데일리 결정성은 바꾸지 않는다. 엔진 블록의 diff는 0이어야 한다.
2. 기존 기능을 유지한다. 입력 방법은 조작 방식마다 7장 표를 따르고, `classic`에서는 지금의 입력이 모두 그대로 동작해야 한다. 유지할 기능은 다음과 같다.
   - 넣기(드래그·탭-탭), 붓기, 미리보기, 착지 고스트, 퓨즈 문구
   - 되돌리기 3회, 부활 1회
   - 데일리·공유, 판 보기, 포기
   - 설정, 색 기호
   - 저장·이어하기, `window.claude.hot` 스냅샷, 클라우드 저장
3. 기본 조작은 체크포인트 B에서 사용자가 고를 때까지 `classic`(현행 조작 + 6장 결함 수정)이다. 후보(7.2 `tapPlace`, 7.3 `tray: 'bottom'`)는 설정에서만 켠다.
   - 예외: 7.4 공통 보정(피드백, 누르는 영역)은 4단계에서 모든 조합에 적용해 휴대폰에서 체험하게 한다. B에서 항목별로 유지 여부를 받고, 빠진 항목은 6단계에서 되돌린다.
4. 드래그로만 되는 기능을 만들지 않는다(WCAG 2.5.7).
   - 모든 드래그 동작은 드래그 없이 포인터 하나(탭, 또는 7.2의 길게 누르기)로도 할 수 있어야 한다.
   - 넣기와 붓기는 손을 뗄 때 확정한다. 대상 밖에서 놓으면 취소한다(WCAG 2.5.2).
   - 길게 누르기로 원천을 고르는 것은 판 상태(`S`)를 바꾸지 않으므로, 누르고 있는 동안 선택해도 된다.
   - 키보드만으로 넣기·붓기·뒤집기·되돌리기를 할 수 있어야 한다(9장 기준은 10턴). 결과 시트 같은 오버레이의 포커스 관리는 이번 범위가 아니다.
5. 연출은 입력을 막지 않는다(`pointer-events:none`). 배너가 떠 있어도 입력이 되어야 한다.
6. 화면 제약
   - 360px에서 가로 스크롤이 없어야 한다.
   - 병 6개의 폭을 줄이지 않는다.
   - 상시 버튼이나 패널을 추가하려면 사용자 확인을 받는다. 설정 항목 추가는 괜찮다.
7. 외부 라이브러리, 새 파일, 에셋을 페이지에 추가하지 않는다. 단일 HTML을 유지한다. 테스트용 전역 훅도 페이지에 넣지 않는다.
8. `prefs`의 `sound`, `vibrate`, `reduceFx`, `ghost`, `symbols`를 존중한다.
   - 새 설정 키 `controls`·`tray`는 `prefs`에 넣는다. 다만 `prefs` 기본값 객체(`Object.assign({ symbols: false, … }, LS.get('wsurv.prefs', {}))`)에는 넣지 않는다.
   - 이유: `savePrefs()`가 `prefs` 전체를 저장한다. 기본값 객체에 넣으면 다른 설정을 한 번만 바꿔도 `'classic'`·`'top'`이 저장되고, 6단계에서 바꾼 기본값이 그 기기에 적용되지 않는다.
   - 읽을 때는 `prefs.controls || 'classic'`, `prefs.tray || 'top'`으로 해석한다. 사용자가 설정에서 직접 고를 때만 저장한다.
9. 클라우드 동기화(`mergeCloud` → `render()`)가 선택 중이나 드래그 중이나 길게 누르는 중에 와도 입력 상태가 깨지면 안 된다.

## 5. 검증 도구

### 5.1 `controls` 시나리오 (uitest)
`make.js`에 시나리오를 추가하고, `driver.js`에 실제 입력을 흉내 내는 도우미를 만든다.

**합성 PointerEvent 기본값을 바꿔서 보낸다.** 기본값은 `bubbles` false, `pointerId` 0, `isPrimary` false, `buttons` 0이다. 도우미는 다음 값을 넣는다.
- `bubbles: true`
- 포인터마다 다른 `pointerId`
- 첫 포인터만 `isPrimary: true`
- 누르고 있는 동안 `buttons: 1`
- `pointerType`은 `'touch'`와 `'mouse'` 두 가지로 돌린다

**`tap(el)`, `tapAt(x, y)`**: 그 좌표의 요소(`elementFromPoint`)에 `pointerdown`과 `pointerup`을 보낸다.

**click 합성.** 합성 PointerEvent는 click을 만들지 않는다. 그래서 도우미가 브라우저 규칙대로 직접 보낸다. 이걸 빼면 `#rack`의 click 경로와, 드래그 뒤에 오는 click이 탭으로 잘못 처리되는 경우를 검사하지 못한다.
- 터치: 이동이 슬롭 이하일 때만 탭 지점에 `click`(`detail: 1`)이 생긴다. 길게 눌러 메뉴가 뜬 터치에는 click이 없다.
- 마우스: 이동 거리와 상관없이, 누른 요소와 뗀 요소의 가장 가까운 공통 조상에 `click`이 생긴다. 예를 들어 병 A에서 병 B로 끌면 `#rack`에 click이 간다.
- `drag`도 마우스 모드면 끝에 click을 보낸다.

**그 밖의 도우미**
- `drag(from, to, steps)`, `jitterTap(el, px)`, `twoPointers(...)`
- `key(el, k)`: 합성 `keydown`은 버튼을 실행하지 않는다. 그래서 `el.focus()` 뒤에 `keydown`을 보내고, `defaultPrevented`가 아니면 브라우저 동작을 흉내 낸다. Enter는 `keydown` 때, Space는 `keyup` 뒤에 `el.click()`(`detail 0`)을 부른다. Escape는 `document`의 `keydown`만 보낸다.

**포인터 캡처.** 합성 이벤트에서는 `setPointerCapture`가 실패한다(현재 코드는 try/catch로 무시한다).
- 현행 감사 단계: 리스너가 컵에만 있으므로 `pointermove`/`pointerup`을 `#cup`에 보낸다.
- 구조를 바꿀 때
  - 드래그 중의 `pointermove`/`pointerup`/`pointercancel`은 `window`에서 받는다.
  - 병에서 시작하는 동작(7.2의 붓기 드래그와 길게 누르기)에서는 이 방식이 필수다. `render()`가 병 버튼을 매번 다시 만들어서(드래그를 시작할 때 부르는 `render()`도 포함) 버튼에 단 리스너와 터치의 암묵적 캡처가 사라지기 때문이다.
  - `pointerdown`은 `#rack`·`#spareSlot`에 위임해서 받는다. 진행 중인 동작은 요소가 아니라 슬롯 번호로 기억한다.
  - 테스트는 좌표에 있는 요소에 보내기만 하면 된다.

**클라우드 병합 재현.** `cloud` 시나리오처럼 `window.claude.use` 가짜 db를 넣는다. 드래그 중이나 길게 누르는 중에 `window.__cloud.push(id, body)`로 다른 기기의 저장을 밀어 넣으면 `mergeCloud` → `render()`가 일어난다.

**검사 항목**: 2.2 표의 모든 행, 7장 각 후보의 동작 표의 모든 행, 6장 수용 기준.

- 세로: `#rack` 위 끝(병 위 `padding-top` 18px 포함)부터 병 버튼 아래 끝('빈 n' 라벨 포함)까지
- 임시 잔은 병 줄 영역 밖이지만 병과 같이 취급한다(놓기·탭 대상).

| # | 고칠 것 | 수용 기준 |

## 7. 조작 후보 (시제품)

설정 시트에 '조작 방식'과 '조각 칸 위치'를 추가한다.
- `prefs.controls`: `'classic'`(기본) | `'tapPlace'`
- `prefs.tray`: `'top'`(기본) | `'bottom'`
- 저장 방법은 원칙 8을 따른다.

두 설정은 독립이라 2x2 조합이 모두 동작해야 한다. 설정은 판 도중에도 바로 적용되고, 진행 중인 판의 상태(`S`)는 바꾸지 않는다. 조작 방식을 바꾸면 `sel = null`로 하고, 진행 중인 길게 누르기와 드래그를 취소한다.

### 7.1 `classic`
현행 조작에 6장 수정과 7.4 공통 보정을 더한 것이다.

### 7.2 `tapPlace`: 병 탭 = 넣기, 병 끌기 = 붓기
매 턴 반드시 하는 넣기를 탭 한 번으로 줄이는 안이다. 이 방식에는 `sel = 'cup'` 상태가 없다.

| 입력 | 결과 |
|---|---|
| 평상시 표시(`sel = null`) | `classic`에서 컵을 선택했을 때의 표시를 항상 보여 준다: 넣을 수 있는 병 `.can`, 완성되는 병 금색·코르크(`prefs.ghost`), 퓨즈 상태 문구. 탭 한 번에 바로 들어가므로, 이 표시가 없으면 넣기 전에 착지 미리보기와 퓨즈 경고를 볼 수 없다 |
| 병 탭(`sel = null`) | 지금 조각을 그 병에 넣는다(`tryPlace`). 실패하면 흔들림과 이유 문구를 보여 주고 상태는 유지한다 |
| 병에서 다른 병으로 끌기 | 붓기다. 내용이 있는 병에서 8px를 넘게 움직이면 붓기 드래그가 시작된다(빈 병에서는 시작하지 않는다). 원천에는 `.sel`과 `.leaving`, 대상 위에는 붓기 고스트나 `.reject`를 표시한다.<br>- 부을 수 있는 병에 놓으면: 탭-탭 붓기와 같은 경로(`onTube`의 붓기 분기)로 처리한다.<br>- 못 붓는 병에 놓으면: 흔들림과 이유 문구를 보여 주고 `sel = null`(그 병을 새 원천으로 삼지 않는다).<br>- 원천 위나 병 줄 영역 밖에 놓으면: 취소(`sel = null`) |
| 병 길게 누르기 | 붓기 원천을 고른다. 드래그 없이 붓는 방법이다(WCAG 2.5.7).<br>- 내용이 있는 병에서 450ms 동안 8px 슬롭 안에 머물면, 그 순간 원천으로 선택한다(`sel = i`).<br>- 누르는 동안 원천이 될 병이 차오르는 표시를 한다.<br>- 450ms 전에 슬롭을 넘으면 길게 누르기를 취소하고 붓기 드래그로 처리한다. 450ms 뒤에 슬롭을 넘으면 그 원천에서 붓기 드래그로 이어진다.<br>- 길게 누르기가 발동한 포인터의 pointerup과 그 뒤의 click은 넣기나 해제로 처리하지 않는다(마우스는 오래 눌러도 click이 온다).<br>- 타이머가 도는 동안 `render()`가 와도 타이머와 표시를 유지한다. 오버레이가 열리거나, `S.turn`이 바뀌거나, pointercancel이 오면 취소한다.<br>- 길게 누를 때 브라우저 메뉴나 텍스트 선택이 뜨지 않게 한다. 병과 임시 잔에만 `user-select:none`, `-webkit-touch-callout:none`을 주고 `contextmenu`를 막는다 |
| 원천이 선택된 동안 | 병 탭은 넣기가 아니라 붓기 대상이다(`classic`의 `sel = 병` 규칙과 같다). 같은 병 탭, Escape, 병 줄 영역 밖의 빈 곳 탭은 해제한다. 상태 줄은 '부을 병을 고르세요'다 |
| 임시 잔 | 조각을 받을 수 없으므로 탭은 `classic`과 같다. `sel = null`이면 원천을 고르고, 원천이 선택돼 있으면 붓기 대상이 된다. 붓기 드래그의 원천과 대상도 될 수 있다. 병 줄 영역 밖으로 보지 않는다 |
| 컵 끌기 | 지금처럼 넣기다 |
| 컵 탭 | 선택하지 않는다. 상태 줄에 '병을 누르면 바로 들어가요'를 보여 준다 |
| 그 밖의 버튼 | ⇅는 `sel`을 유지한다. 되돌리기, 새 게임 등은 지금처럼 동작한다. '병 줄 영역 밖 탭으로 해제'는 버튼이 아닌 곳을 눌렀을 때만 적용한다 |
| 키보드 | - 병에서 Enter·Space: 넣기(button의 click, `detail === 0` 경로)<br>- Shift+Enter: 붓기 원천 선택. keydown에서 `preventDefault()`를 해서, 브라우저가 이어서 만드는 click이 넣기로 처리되지 않게 한다<br>- 원천이 선택된 동안 Enter·Space: 붓기 대상<br>- Escape: 해제<br>- 임시 잔의 Enter·Space: `classic`과 같다 |

- 처음 이 설정을 켰을 때 한 번만 3줄 안내를 띄운다.
  - '병을 누르면 조각이 바로 들어가요'
  - '병에서 병으로 끌면 부어요'
  - '길게 누르면 부을 병을 고를 수 있어요'
- 위험: 물정렬 장르의 탭-탭 붓기 습관 때문에, 부으려다 넣는 실수가 생길 수 있다. '마지막 넣기는 2초 안에 무료로 되돌리기' 같은 완화책이 있지만 되돌리기 규칙을 바꾸는 일이다. 구현하지 말고 B에서 질문만 한다.

### 7.3 `tray: 'bottom'`: 조각 칸을 병 줄 아래로
- 컵, ⇅, 미리보기, 임시 잔이 있는 `.incoming` 블록을 병 줄 아래, 상태 줄 위로 옮긴다.
- ROADMAP의 '대기칸을 병 선반 바로 위'와는 반대 방향이다. 엄지 영역을 우선한 대안이고, 결정은 사용자가 한다.
- 위로 끌어 넣을 때 고스트는 손가락 위에 그린다. 판정 지점은 손가락 좌표가 아니라 고스트의 중심이다(이 배치에서는 손가락이 병을 가리기 때문). 병 줄 영역은 6장 정의대로 흡수한다.
- 조각 칸과 하단 버튼 사이는 8px 이상 띄운다. 조각 칸과 하단 버튼 줄의 모든 버튼(컵, ⇅, 임시 잔, 되돌리기·새 게임·모드)은 누르는 영역이 44 이상이어야 한다. 헤더 버튼은 9장 기준을 따른다.
- 360x740에서 넘침이 없어야 한다.
- 화면이 클 때는 병 줄과 조각 칸이 엄지 영역 쪽으로 내려오게 세로 배치를 조정해도 된다.

### 7.4 공통 보정
모든 조합에 적용하고, 체크포인트 B에서 항목별로 확인받는다.
- **피드백**: 넣기 성공, 붓기 성공, 거절에 짧은 소리와 진동을 단다.
  - 진동 예: 성공 10ms, 거절 `[20, 40, 20]`
  - `prefs.sound`와 `prefs.vibrate`를 따른다. 선택에는 시각 효과만 준다.
  - iOS Safari는 `navigator.vibrate`를 지원하지 않는 것으로 알려져 있다. 기능 감지만 하고 오류는 내지 않는다.
- **누르는 영역**: ⇅와 임시 잔의 누르는 영역을 44x44 이상으로 한다. 겉모습 크기는 그대로 두고 영역만 넓혀도 된다.
- **위쪽 칸의 컵 드래그 판정**(`tray: 'top'`, 두 조작 방식 공통): 지금은 손가락 좌표로 판정한다. 고스트 중심 판정(손가락보다 약 13px 위)으로 바꿀지 B에서 묻는다. 시제품에서는 바꾸지 않는다.

### 7.5 만들지 않는 후보 (보고에 이유만 적는다)
- **미리보기 영역 탭 = 넣기, 병 몸통 탭 = 붓기**: 한 병의 누르는 영역이 둘로 나뉘어 각각 44 미만이 된다.
- **탭 한 번 자동 붓기**: 어느 병에 부을지 고르는 것이 이 게임의 전략이다.
- **장전형**: 5.3에서 측정만 한다. 붓기가 많은 플레이어는 지금보다 탭이 늘어난다.

## 9. 공통 수용 기준

- **회귀**
  - 기존 UI 시나리오 8개(감속 모드 115개, 일반 모드 116개)와 새 `controls`·`geom` 시나리오가 두 모드 모두에서 통과한다.
  - 엔진 테스트 결과가 0단계 기준선과 같다.
- **불변**
  - 엔진 블록 diff 0.
  - `rulesSig(DEFAULT_RULES)`가 0단계와 같다.
  - 기존 저장(`existing`, `v1saves`, `v1daily` 시나리오)을 그대로 이어서 할 수 있다.
- **화면** (기본 규칙, 조각 칸 위·아래, 4개 크기)
  - 가로·세로 스크롤이 없다.
  - 360에서 게임 조작 요소(컵, 병, ⇅, 임시 잔, 되돌리기)의 누르는 영역(5.2 방식)이 44x44 이상이다. ⇅와 임시 잔은 7.4가 들어간 4단계부터 적용한다.
  - 헤더 버튼은 24 이상이어야 하고, 44 미만이면 보고한다.
  - 설정 최대값에서는 병이 44 미만이어도 되지만 수치를 보고한다.
- **입력**
  - 6장의 병 줄 영역 안에 탭이나 드롭이 안 되는 빈틈이 없다.
  - 모든 입력은 이벤트 처리 직후 DOM에 시각 피드백(클래스, 고스트, 상태 문구 중 하나)을 남긴다. 테스트는 이벤트를 보낸 직후 동기로 확인한다.
  - 멀티터치에서 고스트가 남거나 동작이 두 번 일어나지 않는다.
  - 드래그·선택·길게 누르기 중에 `render()`가 와도 표시가 유지된다.
- **접근성**
  - 각 조작 방식에서 키보드만으로 10턴을 진행할 수 있다(테스트로 확인).
  - 포커스가 보이고 유지된다.
  - 선택 상태가 `aria-pressed`로 나온다.
  - 모든 드래그 동작에 드래그 없는 대체 수단이 있다.
- **콘솔**: 오류 0건.

## 10. 실기기 확인 (체크포인트 B에서 사용자에게 건넬 목록)

헤드리스로는 확인할 수 없는 항목이다. 사용자가 Android Chrome에서 Pages URL로 각 조합을 한 손 엄지로 2판 이상 해 보고 답하게 한다.

1. 넣기가 편한 조합 순위
2. 부으려다 넣은 횟수와 넣으려다 부은 횟수(특히 `tapPlace`)
3. 위나 아래로 끌 때 손가락이 병이나 조각을 가리는지
4. 병 위에서 끌 때 페이지가 스크롤되는지, 길게 누를 때 메뉴나 텍스트 선택이 뜨는지
5. 안내 없이도 길게 눌러 원천을 고르는 방법을 알아챌 수 있는지
6. 진동과 소리가 도움이 되는지, 거슬리는지
7. 빠르게 두 번 탭하면 화면이 확대되는지
8. (가능하면) iOS Safari와 TalkBack에서 넣기와 붓기가 되는지

## 11. 배포와 재게시

- **아티팩트**
  - 게시 직전에 read한다. 이 작업에서 마지막으로 게시한 내용(처음이면 0단계에서 읽은 내용)과 달라졌으면 덮어쓰지 말고 차이를 보고한다.
  - 같으면 같은 URL에 `file_path` = `BASE/water-sort-survival.html`로 게시한다.
  - icon과 capabilities는 생략한다. 생략하면 기존 db와 user가 유지된다.
- **Pages**
  - 사용자 승인을 받은 뒤 `BASE`에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-pages.ps1`을 실행한다.
  - 실행 전에 변경이 `main`에 커밋돼 있고 작업 트리가 깨끗한지 확인한다. 스크립트는 작업 트리의 html로 빌드하고, `main`을 푸시한 뒤, `version.json`에 `HEAD`를 적는다. 그래서 미커밋 변경이 있으면 배포 내용과 `sourceCommit`이 어긋난다.
  - `https://kongrae.github.io/water-sort-survival/version.json`의 `sourceCommit`이 새 커밋인지 확인한다. 반영까지 몇 분 걸릴 수 있다.
- Claude 앱의 브라우저 패널은 사용자가 직접 클릭하지 않은 입력으로 열리는 팝업을 막는다. 사람 손이 필요한 확인은 사용자에게 부탁한다.
